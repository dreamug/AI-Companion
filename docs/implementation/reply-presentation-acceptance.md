# 分条回复与发送间隔

日期：2026-10-23（Asia/Shanghai）。本次只实现聊天回复的呈现与发送节奏；角色日常、故事生成与主动分享尚未实施。

## 使用方式

聊天上方增加两个开关，均按 bot 独立持久保存：

| 开关 | 默认 | 行为 |
|---|---|---|
| 分条回复 | 关闭 | 一次生成后，按自然语义发布 1–4 个聊天气泡 |
| 发送间隔 | 关闭 | 需要分条回复；首条生成完成后尽快发布，后续按长度等待约 1.2–3 秒 |

旧数据库缺少这两个字段时读取为关闭；新建角色也默认关闭。禁用分条后间隔选项不可操作，之前选择保留，再次启用分条时继续使用。两项设置从下一轮输入生效，不打断当前运行。

全部关闭时保持原单气泡流式路径和原提示词。开启分条时先生成完整答复，再切分发布；因此第一条需要等待本次生成完成。短句不强行拆分，代码、链接、列表、表格与较长解释保持完整。分段器只选择切分边界，不调用额外模型或重写正文。它提供可控的初始节奏，实际表达自然度仍需真实使用反馈。

## 插话、停止、刷新

- 开启分条的运行，无论还在生成还是已发出一部分，收到新的非重复用户输入后都会取消旧运行，剩余内容不继续发送；新输入进入现有执行队列。未开启分条的运行保持原排队规则。
- 「停止」取消本轮余下内容；重复点击／请求不会重复提交取消事件。已发布气泡仍为完成状态，可以保留展示和朗读。
- 发送前检查运行状态、代数、来源 epoch 与边界版本；遗忘或取消后的迟到内容不能提交。
- 刷新／重连只读取数据库内的已发消息。稳定消息 ID、组内序号与事务提交保证不会从头重播，发送间隙刷新后后台仍可继续发送后续内容。
- 后台进程重启时，运行变为 interrupted；保留已提交气泡，未发布草稿作废，不重生成、不补发。这是明确的中断策略，不承诺恢复未发草稿。
- 待发正文仅留在本次后台运行内存中，不出现在公开快照、已发消息或后续对话历史中。没有展示回执的已发消息继续沿用原保守上下文投影。
- 自动朗读按气泡串行播放；停止朗读清空本组队列，并阻止本组后到气泡重新触发自动朗读。下一轮仍可自动朗读，历史气泡可手动重听。刷新不重播旧语音。
- 现有主动关心 Delivery 保持原来的单条投递，本次未改变其通知与发送策略。

## 实现边界

`Settings.splitReplies` 与 `Settings.messagePacing` 通过现有版本化设置接口保存；每轮记录本轮采用的选项。普通模式不注入分条指令。启用时复用现有模型调用，只追加一段有界的呈现说明。

每个已发布气泡是独立 Message，使用稳定 ID、`replyIndex` 和 `replyCount`；消息列表按运行入队次序及组内序号排序，不依赖 UUID 或毫秒时钟区分顺序。发布消息、更新发送进度、追加公开事件在同一 SQLite 事务提交。Run 在最后一条发布后完成；模型生成期限与有限发送间隔分开，等待期间始终可取消。

Kimi 参考仍是固定快照 `9e1248416faa22d9f0b777b91ad092bbf1e19182`。适配其“恢复记录不自动重做副作用”的原则，继续使用项目现有 SQLite 与运行代数；未引入其 wire 格式、DI 或第二套 Agent 循环。分条正文未被用作模型推理记录。

真实 Chromium 新增用例覆盖普通模式、角色切换、发送间隙刷新、插话、停止、分条语音串行、停止后的组内静音及历史手动朗读。模型使用确定性测试替身，音频使用本地 MP3 样本，没有调用付费模型、ASR 或语音合成服务。
