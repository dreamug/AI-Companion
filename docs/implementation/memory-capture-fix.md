## 问题与处理

原链路存在两个候选写入者：聊天 `propose_memory` 工具与后台提取。它们使用不同措辞表示同一事实，完全相同文字去重无法拦截。新版自动记忆现在只有后台提取一个写入方，正常聊天不再声明提议工具。旧客户端或模型虚构该工具调用也只能收到路由回执，不能创建第二条候选。关闭自动整理时，明确保存请求也登记到同一后台链路；普通聊天不能借工具绕过开关。

没有用题目关键词、特定菜名、模糊字符串相似度或“一条来源只能存一个事实”来合并记录。同一发言可以提取多个不同属性、主体和否定。完全相同候选的兼容去重还会核对类别、主体、现实范围、有效期和来源资格。

新版提取结果增加 `retention`，区分 `durable`、`transient` 和 `uncertain`。程序只接纳明确长期资料，或用户明确请求保存的临时事实；缺失判断则拒绝整批，不能默认升级长期记忆。模型负责语义判断，程序负责执行资格。临时聊天意愿、即时动作、忙闲与情绪不应进入长期候选；近期形成的明确偏好和当前职业仍有资格。不会通过“最近／现在”之类时间词一刀切。

新输入自己产生的有效候选用 `new` 类型展示聊天内确认入口。只有重提旧候选的 `related` 提醒受每日一次限制。每轮最多展示一张新卡片；确认或暂缓后，不在同一轮连续弹下一张。来源卡片保留展示回执，确认仍执行原有版本检查与幂等命令。新的输入编号记录在遗忘时一并清理。

正常聊天不播报待确认流程；确认由独立界面卡片提供。用户主动问保存状态时，仍可按实际状态说明。提示词约束不等于语言模型绝不出错，因此自然回复也单独留有联调证据。

## 验证与边界

新增 `tests/memory-capture.test.ts` 覆盖单写入方、不同工具 ID／措辞、长期判断缺失回滚、临时与稳定资料、明确保存、拒绝保存、多事实／多主体／否定不误合并、新旧确认配额、稍后与刷新、关闭自动整理及迟到结果拒绝。原有记忆读取、修订、遗忘、来源、摘要、25,000 条规模和发布边界测试仍运行。

网页测试新增同一天连续两条普通偏好都能确认、每条候选只出现一次的场景。测试替身模拟后台提取，验证实际生产流程；不会把替身输出当真实模型质量证据。

真实模型另外用冻结的 14 组新自然输入联调，标签与预期不交付模型，每组使用独立一次性数据库。第一轮 14/14 通过候选数量、关键词、来源、确认入口和有限正文流程检查。这不是独立人工 benchmark，也不证明复合语句的完整语义准确率。完整原始输出保留在 `test-results/memory-capture-natural-v1/results.json`，包括与此次记忆修复无关的回答质量问题，未修饰或重抽直到通过。

最终类型检查、构建和全量 539 项测试通过（36 个测试文件，含 19 项新增候选捕获回归）；网页回归 7/7 通过。日志为 `test-results/memory-capture-final-verify.log` 和 `test-results/memory-capture-web.log`。

旧试用库只重新整理未处理、未更正、未暂缓的自动候选。操作前生成私有备份，旧候选保留为历史失效记录，按原来源重跑新版提取。已有聊天与用户确认的记忆不自动修改。已确认但质量不佳的旧资料继续由用户决定是否移除。

实际更新：4 条旧自动候选退为历史记录，3 份原始来源重跑后保留 1 条有效候选；16 条消息与 1 条已确认记忆的内容哈希前后相同，聊天内确认卡片可见。6 个正式数据库 schema 仍为 v1，`env.local` 哈希不变，正式进程未重启。更新证据在 `test-results/memory-capture-release/`，操作前备份位置记录在试用目录的 `capture-reconcile.json`。旧聊天正文保持原样，新回复规则从下一轮生效。
