> 最新增量见[两道漏召回与 25000 条读取延迟修复](memory-recall-latency-fix.md)；本文原始验收数字保留当时快照。

## 1 交付结论与实际运行状态

MEM-G0、MEM-0、MEM-1、MEM-C 的基础上，已补齐 v2 存储、分段、原文块摘要、历史读取、受限来源展开、本地 E5、混合排序、索引失效、恢复和等待状态。按本轮“一次性完成相关实现和评测”的要求，在隔离数据目录实施和验证后续能力。

**工程实现完成不等于自然使用门槛通过。** MEM-G1 的七天自然观察尚未完成；真实确认率、长期连续性满意度不能由合成题集推出。新功能默认不开启正式 v2／向量，未修改 `env.local`、未重启正式服务、未对正式聊天编码或向远程模型发送真实记忆。本轮只读核对 6 个正式数据库，`user_version` 均仍为 1。迁移、遗忘恢复与真实模型试验使用独立临时库；远程评测只发送合成内容。

有限测试无法穷尽所有自然语言。以下分别报告工程合同、来源检索、模型回答、提取、摘要和性能，不用其中一种成绩替代另一种。

## 2 已落地的生命周期

| 环节       | 当前行为与代码                                                                                                                                                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 统计与确认 | 生产／机会／展示／决定／退出分开统计；natural、synthetic、unknown 分离。聊天卡片和维护页共用幂等命令；未确认、解释、争议内容不自动升级。`src/memory/candidates.ts`、`metrics.ts`、`harness.ts`                                                                                                                                      |
| 输入与分段 | 输入时在同一事务登记提取任务和段归属；空闲超过 30 分钟才换段，有排队时延续。旧 Run 只回填元数据，不重跑生成；新助手消息也带段 ID。`conversations.ts`                                                                                                                                                                                |
| 提取       | 用户来源是事实根；上一条已展示助手只作省略语境，绑定切片证据。主体、否定、引用、假设、计划须保留。输入已登记，因此回答失败不会漏掉资格。`harness.ts`                                                                                                                                                                                |
| 近期与摘要 | 原文保留；按完整 Run 组裁剪。摘要从原文生成，保护最近 6 个交流组，软触发仅计算未覆盖／未预留的原文；单 Job 原文约 4000 token，摘要正文目标 700、最多验 1000，关键引用最多 8 个。完整依赖由程序保存，不让模型枚举上百个来源 ID；临时提供方错误最多重试两次，5/30 秒退避并尊重 Retry-After，Schema 错误不自动重试。`conversations.ts` |
| 摘要投影   | 只投影正文和紧凑覆盖说明：序号范围、消息数、partial；完整 EvidenceRef 留在库中。最新至多 2 块、合计 1500 token，预算测量与渲染复用同一投影，避免来源 ID 挤走摘要正文。`context.ts`                                                                                                                                                  |
| 历史读取   | facts、conversation、episodes 明确分流。摘要使用作用域 FTS trigram 候选加短词／二字词法评分及日期资格；旧事件使用现有词法后端与日期过滤。摘要／事件不使用事实 E5 分数，不暗示拥有事件语义索引。                                                                                                                                     |
| 全量与混合 | 独立事实投影 2000 token；超过 2000 进入 hybrid，回到 1700 以下才回 all。少量事实无需加载模型。大集合为 E5 semantic-12、keyword-5、delta-8，RRF k=60、权重 1/0.35；置顶优先，完整连续字面命中有明确排序，最终最多 5 条。`reading.ts`、`retrieval.ts`                                                                                 |
| 分页与展开 | “全部”使用带 scope／事实版本／epoch 的游标，不把 top-5 当全量。长记录节选标记 incomplete、UTF-16 范围与 expandId；来源仅限本 Run 已提供的 ID／版本，分片读取，助手不能超越已展示前缀。摘要检索优先提供与查询相关的根来源，至多 4 个。                                                                                               |
| 索引       | SQLite BLOB 为持久索引，后台每次只编码一个片段，片段间前台优先；编码不在 SQL 事务中。worker_threads 常驻矩阵，装载时转移 buffer，查询只传向量与资格位图。冷矩阵加载超时后继续后台完成，避免每次查询重新加载。                                                                                                                       |
| 一致性     | memoryVersion、contextVersion、indexVersion 分离；pending 和 index ready 不触发无谓事实重建。缓存复用绑定事实版本、域与时间边界；展示变化重查证据，切片变化、来源修订、到期与排队截点不能绕过资格。                                                                                                                                 |
| 更正与遗忘 | 新事实立即经全量／关键词／delta 可读；旧向量不得水合。遗忘取消读取并清缓存、向量、依赖与派生内容。只删摘要保留原始聊天，但阻止自动重建；重建是带 revision 的显式命令。                                                                                                                                                              |
| 恢复       | 迁移前一致性备份、事务建表；恢复应用最新删除台账后发布，向量重新生成。v1 备份接收 v2 的摘要阻止元数据，后续启用新表也不能复活摘要；合并台账保留全部阻止范围。不调低 user_version。                                                                                                                                                  |
| 界面       | 800 ms 后显示正在输入，8 s 后显示较慢；已出文字、取消、失败、刷新及切角色会更新状态。分条发送显示进度。状态不是 Message，不进入记忆、语音或通知。                                                                                                                                                                                   |

`EvidenceRef` 统一 UTF-16 半开区间；`sliceHash` 是精确原始切片的 SHA-256，Source／业务修订严格匹配。助手展示增长可保留旧切片，真实切片变化或撤销则失效。依赖只支持固定两层，异常保守拒绝。

## 4 检索与真实回答的评分口径

- 三个冻结题集共 212 个查询；154 个有已知答案。命中指最终提供的至多 5 条中包含预期来源，报告逐题命中和完整预期来源覆盖。无答案题不进入此分母，也不因检索返回相似内容就认定模型回答错误。
- 原题集是调试回归集，不能当新样本泛化成绩。另有挑战集与新主题 holdout；本轮未针对漏题加入问题专用映射、改预期答案或更换模型权重。
- 真实问答使用 DeepSeek、真实 Harness 和工具链；只额外要求 JSON 便于评分，不在问题里放答案。题目依次进行，保留其对话历史；这不是每题独立会话的统计实验。
- 严格评分同时检查弃答、实际支持答案的记忆 ID 和答案字面内容。它会拒绝部分合理省略和同义表达，因此保留原始答案、引用、Run 状态和上下文；不把人工解释后的通过数替代严格得分。
- 提取测试使用真实提取模型、受控助手问句；检查所需概念、禁止误断言及当前用户来源／pending 状态。有限的字面检查不能证明所有语义错误都不存在。

原题集保留两道漏召回：`work-natural`（“我的职业是做什么的？”）、`address-natural`（“你该怎么叫我才合我心意？”）。这两题的泛化问法仍可能丢掉预期来源，不能宣称 100% 换说法召回。

真实问答严格未通过的两项也保留：`birthday-exact` 的预期为“十月七日”，模型答“这一天是你的生日”；`climb-temporal` 的预期包含“尚未”，模型答“只记录了打算去，没有已完成的记录”。两者引用均指向预期记录，但严格答案没有命中字面条件，记作待复核，未改写成 60/60。三组检索共 **152/154** 个有答案问题命中，汇总 98.70%，仍不代表自然分布。

长聊首轮实测曾暴露摘要过密、输出引用膨胀及评估脚本读取辅助表错误；修复后单独复测。最新有效摘要数为 2，三项续接均通过。中间 1/3 及工具脚本错误样本保留；没有把它们删掉或把未生成摘要当成功。

## 5 实测暴露并修复的问题

1. 2.5 万条时重复 SQL 水合与逐条比较造成大量超时；改为版本化资格缓存、来源序号缓存、索引集合判定和资格位图。缓存同时保留时间边界、contextVersion 证据复查和作用域限制。
2. 大矩阵冷加载受前台截止打断，造成下一次再次加载；改为有界后台装载，分片校验并让出事件循环，前台等待超时后继续词法读取。
3. 长记录此前可能作为“all／完整”返回；现在节选一律 incomplete，保留正文原文并支持授权展开。
4. 摘要触发错误地看历史总消息数，长聊后会每轮生成小摘要；改为仅计算未覆盖原文，并增加频率回归。长摘要的完整覆盖 ID 曾挤占正文预算，现统一紧凑投影。
5. 摘要输出若枚举大量来源会耗尽输出预算；提示与 Schema 限制关键引用至多 8 个，完整依赖仍由程序记录。使用既有严格 JSON 提取器处理合法代码围栏，不放宽引用资格。
6. v1 备份恢复后可能丢失摘要阻止范围；兼容元数据保存在旧 Settings，升级时导入墓碑；相同删除记录的多个副本合并消息范围。

中间失败与最终结果分别保存在 `test-results/`，不能将中间结果覆盖后宣称一次就通过。

## 6 性能、容量与限制

设备：macOS arm64、Apple M1 Max；E5 使用 CPU。后台索引场景有 100 次实际查询，空闲另 100 次。容量实验的 50／500／5000／25000 行各做 100 次带 IPC 的扫描，完整运行时各做 30 次查询。容量矩阵使用合成归一化向量，只测工程开销；真实 E5 的语义质量由上述题集评估。

本机模型冷加载 3.97 秒，不把模型加载时间塞进每轮检索等待。

| 场景                                    | P50 ms | P95 ms | P99 ms |   截止降级 |
| --------------------------------------- | -----: | -----: | -----: | ---------: |
| 实际 E5 查询＋后台索引                  |   39.9 |   48.2 |   62.0 |      1/100 |
| 实际 E5 空闲查询                        |   23.8 |   27.4 |   31.8 | 未单独计数 |
| 完整运行时 50 条，后续查询含预热过渡    |   20.4 |   23.0 |   23.1 |       0/30 |
| 完整运行时 500 条，后续查询含预热过渡   |   36.5 |   41.7 |   42.5 |       0/30 |
| 完整运行时 5000 条，后续查询含预热过渡  |   67.8 |   76.9 |   77.0 |       0/30 |
| 完整运行时 25000 条，后续查询含预热过渡 |  222.7 |  243.1 |  452.9 |       2/30 |

常驻扫描含 IPC 的 P95（50／500／5000／25000 行）为 0.18／1.22／12.16／60.28 ms。25000 条首次查询 387.8 ms，返回 keyword 降级；后续样本的尾延迟同样未剔除。优化前完整运行时 25000 条曾 30/30 超时，原始对照见 `memory-performance/before-cache.json`。

**250 ms 是前台语义阶段的截止与降级目标，当前不是整次同步 SQL／冷缓存工作的硬实时保证。** 最大容量的冷加载和部分尾延迟仍超过该值，不能宣称 25000 条全场景达标；该规模正式启用前还需改造同步大库读取或降低经实测支持的上限。MPS、低配设备、并行多角色的持续资源与故障压测未完成。较小规模和本机 CPU 结果不能外推全部设备。

## 7 启用、迁移与回退

现有默认路径继续工作。三个开关含义：

| 配置                         | 默认与作用                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `HARNESS_MEMORY_V2=1`        | 默认关闭。构造 Harness 时会启用 v2；若库仍为 v1，会先备份再建表，**因此设置该开关本身就可能执行迁移**。不要把它当成纯只读开关。      |
| `HARNESS_MEMORY_SUMMARIES=0` | v2 开启后摘要默认可用；设 0 关闭后台滚动摘要。旧 v1 下不会创建摘要表。                                                               |
| `HARNESS_MEMORY_VECTORS=1`   | 默认关闭；依赖 v2。模型未就绪立即词法降级，事实达到预热规模才加载。                                                                  |
| `MEMORY_PYTHON`              | 本地 Python 绝对路径；当前默认复用既有 `.venv-memory-lab/bin/python`，不依赖实验脚本。专用环境依赖固定于 `requirements-memory.txt`。 |
| `MEMORY_MODEL_PATH`          | 已在本机准备好的 E5 snapshot 路径，末级目录必须是固定 revision。运行时离线、local_files_only、禁止远程代码，不自动下载。             |

E5：`intfloat/multilingual-e5-small`，revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`，384 维、query/passage 前缀、masked mean、L2、Float32。120 Unicode scalar 的保守片段、24 UTF-16 重叠，编码器最终检查 512 token，超长拒绝，不能静默截断。构建会复制 Python 与扫描 worker 到 `dist/memory/`。

隔离迁移验证示例（默认只操作副本）：

```sh
npm run memory:migrate -- --data-dir /absolute/path/to/data --bot xiaoye
```

显式 `--apply` 才迁移指定 bot 原库，需先停止实例；每个 bot 分别验证，原始数据、人格和删除台账保留。当前正式库未运行此操作。部署回退用新程序关闭增量开关，保留 v2；需要旧二进制时恢复迁移前备份并应用／核对最新删除台账，不改小 user_version，不写旧格式兼容删除转换器。

## 9 参数与本轮实现的差别

| 参数                     | 当前值与落点                                                 | 改动后重测                                        |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------------- |

| 请求／历史／摘要／工具   | 24000／4000／1500／2000；context                             | 每 Step、完整工具组、中文与 Unicode、长覆盖元数据 |
| 段间隔／摘要触发／保护组 | 30 分钟／未覆盖 18 条或 3000 token／最近 6 组；conversations | 分段、长聊、摘要频率与缺口                        |
| 摘要输入／正文／关键引用 | 4000／目标700、验收1000／最多8；conversations                | 真实摘要、引用、截断和 200 条续接                 |
| E5 检索／RRF             | 12／5／8、60、1/0.35，最终5；retrieval                       | 原题、挑战、holdout、字面优先和置顶               |
| 前台／队列／后台粒度     | 250 ms／16／单片；embedding、retrieval                       | 后台回填延迟、取消、队列饱和                      |
| 失败保护                 | 内核5秒、冷启动30秒、3次/10分钟暂停60秒；embedding           | 假进程协议、退出、无响应与恢复                    |
| 等待提示                 | 800 ms／8秒；web                                             | 浏览器等待、取消、刷新、切角色、语音              |

后台不是“8 个长片段一批”：每次仅一片，避免整批阻挡前台；尚无自适应 50 ms 推理切片保证。历史摘要先用 FTS／词法，事件没有向量；大型全文语义问答、通用依赖图、语义冲突自动裁决和跨角色合并都不在当前实现中。

## 10 结论边界

当前可确认：已实现的权限、来源、版本、更正、遗忘、恢复、预算与索引合同通过本轮自动验证；真实模型在明确样本集上有可复核的表现，仍存在换说法漏召回和评分待复核题。不能推导所有问法都准确、所有长聊细节都保留、所有设备延迟都满足 250 ms，或真实用户愿意持续确认记忆。正式启用和产品判断继续依据 MEM-G1 与真实使用证据。
