# 独立记忆试聊：E5 与回答边界修复

2026-10-25。仅更新 `http://127.0.0.1:4321/` 的独立试用实例。原聊天、已确认记忆与来源保留；正式实例、六个正式数据库及 `env.local` 不变。原 4324 对照实验保留原结果，不能把新结果覆盖到旧报告中。

## 运行行为

试用实例启用真实、离线、本地的 `multilingual-e5-small`，固定 revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`。仍使用正常 Harness、提取、界面确认、工具和聊天界面，不装入题库、合成事实、读写替身或上下文消融控制。

保留原有自适应策略：合格事实装得下 2000 token 时全量读取，超过预算后才用关键词与 E5 的混合召回。试用现有 3 条合格长期事实仍在全量分支；“向量启用”不等于强迫每个小问题都检索向量。大于预算的混合分支另外在隔离的 32 条事实副本上验证，不能把小库浏览器截图当作向量贡献的证明。

## 编码与检索

修复前的 30 次“后台编码与前台查询并行”抽测未重现旧现场超时，结果见 `embedding-before.json`。因此不能声称精确复现了上次 221 毫秒事件的根因。

本次消除三个已确认的机制风险：

1. Python worker 在发出 ready 前，先实际执行短输入和最大 512 token 长度的推理预热。权重加载完不再冒充内核就绪。
2. 前台查询与后台片段各用一个常驻编码进程，避免不可中断的后台片段占住查询队列。进程内相同模型配置通过引用计数共享这两个进程，各 scope 的索引和读取资格仍分别校验。每进程限制两条 CPU 推理线程，防止不受控争用。
3. 查询编码与索引快照/资格池加载并行，共用原始 220 毫秒内部截止与 250 毫秒整次检查。快照失败或请求结束会取消尚未完成的编码等待；没有延长截止、静默重试或假装 hybrid 成功。

保留冷模型未就绪、快照加载中、超时、取消、错误向量和 scope/generation 不匹配的真实降级/拒绝路径。矩阵仍常驻扫描 worker，只在索引版本变化时传入，不随每条查询复制矩阵。

代价：两个模型增加常驻内存。本机观察两个新 worker 的 RSS 各约 0.9 GiB，数值受缓存及系统压缩影响，不当作通用上限。比单 worker 更可靠地隔离队列等待，但不能承诺 CPU 饱和时永不超时。未来如需降低内存，应另外测共享权重方案，不以取消截止换取“成功”。

## 已知偏好与时间条件

生成提示统一要求保留偏好的条件、上下界、例外、排除项与严格程度。正确复述前半句后，不能在推荐选项中重新引入不符合条件的内容。用户当前明确更新优先于旧记录；假设和提问不当作偏好更新。

发布检查新增 `memory_constraint_conflict`，使用本轮实际交付的证据与当前输入核对，完整读取分支也会执行。判断预算、容量、时间、排除项、主体和条件，不包含咖啡、兔子、工作室等题目专属分支。相关约束未被提及且与回答无关时不要求主动复述。

当前时间改为直接交付用户时区的带偏移 ISO 时间，另外保留当地可读时间和 `localHour`；不再把 UTC 放在最显眼的 `currentTime` 字段中。评审也收到同一份程序生成的当地时间。测试覆盖上海跨午夜和纽约夏令时回拨，避免用提问中的时段推断当前时段。

## 评审误拦截与迟到结果

原评审只返回违规代码，难以定位是把“我知道多少”误读成“全库有多少”，还是把话题相关清单误读成全部清单。本次改为严格的 `checks` 结构：原文连续引句、作用域、短理由、违规代码或 null；程序汇总违规，Trace 保留逐项判断。

仍区分知识不足、当前交付范围、存储/全部历史、现实断言。`我这边`、`目前` 单独不能把“没有记录”变成“本轮没查到”；同样，描述自己目前知道什么、对未知属性说依据不足，不自动等于全库缺失。数量词按主体和所问属性解析，交付中存在其他主题或其他人的资料，不代表某主题的限定陈述在枚举所有记忆。

评审规则由程序按 Run 固定的保存意愿选择。非保存回合不附加保存流程规则；若模型仍返回不适用的保存违规，拒绝该无效评审，不当作新的业务违规去重写。没有把违规静默清空。

引句必须能在原草稿中找到。仅允许 Markdown 强调、代码样式的显示差异，数字、否定和措辞仍须连续一致。推理评审最大输出 4096 token，非推理 1500，费用、六次调用上限、Run 截止及输入预算仍统一计量。草稿缓冲，最多一次全文重写；重写收到具体检查理由并核对原证据，执行过工具的回合仍不自动重放。

## 回归方法与范围

代码测试覆盖前后台挂起隔离、取消/关闭、冷快照和编码并行、来源失效、25000 行规模、完整读取下的约束检查、当前更新、引句校验、不适用规则、午夜与夏令时。

真实评审题集在每版运行前冻结，最终版本延续之前所有标签，并加入实际失败草稿及跨主题对照。预期标签只在运行后对比，不进入生成、检索或评审请求。真实回答另外使用冻结的 14 个场景，包含预算、容量、气味、夜间音频、活动时间、排除项、当前更新、假设和其他主体；两条故意注入冲突草稿，验证拒绝与一次重写，不能算正常初次生成成功。

混合召回回归复用之前冻结的 30 个问题，使用新建隔离副本，保留 16 个干扰事实和 5 个不合格控制项。自动选择仍是原生 top-5/2000 token。模型实际请求去除旧聊天、摘要和工具，测量自动召回加阅读；这不是完整工具 Agent 的总体成功率。90 次检索另外并发准备全量与关键词上下文，模拟原对照的前台形态。

所有同作者合成测试都只支持这里列出的工程回归，不能外推为用户问题百分之百正确。宽泛的风格、无保存意愿回合的未来记忆承诺，以及未覆盖的问题仍是单独风险，不能因为任务回答正确就宣称全部产品质量合格。
