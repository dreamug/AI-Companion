# 新版记忆试聊用例

入口：<http://127.0.0.1:4321/>。先刷新页面，以使用最新连接。

这些句子是示例，不会预先写入 bot。选你愿意临时保存的资料发进去，也可以换成自己的真实偏好。测试后可在记忆面板移除对应记录。现有聊天会保留。

## 先试这六项

| 顺序 | 发什么／怎么操作 | 应该看到什么 |
| --- | --- | --- |
| 1 | 「今天先陪我随便聊两句。」接着说「我还在整理文件，这两天比较忙。」 | 自然聊天。这些临时状态不会单独变成长期记忆候选，也不应要求你点确认。 |
| 2 | 「我最近开始喜欢听蓝调音乐了。」 | 出现一条待确认偏好和聊天内确认卡片。同一句不会因聊天工具和后台提取重复生成。点击「记住」。 |
| 3 | 「我放松的时候偏爱哪种音乐？」 | 能回答蓝调；不反复解释“待确认、确认后保存”的流程。 |
| 4 | 同一天继续说「我每周日一般会去游泳。」 | 仍然有聊天内确认入口。新候选不会被旧候选每日提醒额度挡住。 |
| 5 | 对这条游泳候选点「稍后」，然后刷新页面。 | 卡片不再重复弹出；记忆面板里仍是待确认，未成为已确认事实。 |
| 6 | 「我在测试场馆的储物柜编号是多少？」 | 如果你此前没有提供这个编号，应明确不知道，不能猜一个。 |

第 2 项与第 4 项允许更换其他音乐、爱好或习惯。若完全相同的资料此前已经保存，重述时可能不会再出现新候选。

## 再试边界

| 场景 | 发什么／怎么操作 | 预期与观察重点 |
| --- | --- | --- |
| 多主体 | 「我喜欢看历史书，我妹妹喜欢看侦探小说。」 | 两条事实可以分别进入候选，不合成一条，也不把妹妹的偏好记到你身上。同一轮最多展示一张聊天内卡片，其余可去记忆面板处理。 |
| 否定 | 「我不喜欢太甜的饮料。」确认后问「给我挑饮料有什么要注意的？」 | 保留否定含义，不能推荐甜饮料并说这是你的喜好。 |
| 当前但持续 | 「我现在的职业是展陈设计师。」 | 可以进入候选。不能仅因为出现“现在”就把职业当临时动作丢掉。 |
| 显式保存短期事项 | 「请记住这件事：我这周在准备作品集。」 | 明确的保存请求可以产生候选；“这周”的限定应保留，不能改成长期职业。仍需你确认。 |
| 不保存 | 对一条新候选点「不保存」，刷新并等几秒。 | 不再重复产生同一候选，原聊天仍在。 |
| 来源里拒绝保存 | 「我喜欢下国际象棋，但这条不要保存。」 | 不应产生自动候选。 |
| 假设／愿望 | 「要是我会拉大提琴就好了。」 | 不能记成“用户会拉大提琴”。 |
| 更正 | 对已经确认的音乐偏好点「更正」，改成「用户现在更偏爱轻音乐」。再询问音乐偏好。 | 按当前有效更正回答；旧版本可以追踪，不能当作现行偏好继续使用。 |
| 自动整理关闭 | 关闭「整理记忆建议」，说一个普通偏好；再明确说「请记住，我喜欢篆刻」。 | 普通偏好不自动收集；明确保存请求仍可以产生待确认候选。测试后可恢复开关。 |
| 重启保留 | 刷新或关闭页面后再次打开。 | 已确认记录保留；已暂缓的卡片不会因刷新重弹。服务重启同样使用原试用库。 |

## 怎样判断结果

- **待确认不等于长期记忆**：只有点「记住／确认」后，才应以已确认事实参与长期记忆读取。候选本身仍会保存在本机，以便你处理。
- **最近对话也能提供答案**：刚说完立即追问，bot 即使没有长期记忆也可能答对。可继续聊 15–20 轮后再问，并在「Trace / 维护 → 查看 Trace 和上下文」检查是否选中了对应记忆。
- **不保存不等于遗忘原话**：拒绝候选后，bot 仍可能从最近聊天知道这件事。要撤销原始来源，应使用「遗忘这条原始发言」；这会影响依赖它的记忆。
- **确认记录有用户决定权**：这次更新没有自动删除你已确认的记录。若之前确认了“想闲聊”之类的临时状态，可自行在记忆面板移除。
- 遇到异常，保留原话、实际回复、候选状态及是否点过确认。最好同时记下该轮 Trace，避免只凭一条答复判断是提取、确认、召回还是回答出了问题。
