# 记忆读取范围与“没有记录”断言修复

2026-10-25。已更新独立试聊 4321 和合成演示 4323；正式服务 4317 未重启，6 个正式数据库只读核对，业务表内容哈希不变、schema 均为 v1。向量始终关闭，没有正式迁移。

## 问题与实现

之前的隔离实验中，读取状态已经说明本轮不可用，正文仍说“记忆里没有相关记录”。原有系统提示已经禁止从未命中推断“从未说过”，但仅靠生成提示不足以确保执行；此前的发布前检查只处理明确保存流程，没有检查读取范围。

新增 `src/memory/read-scope.ts`，根据实际交付结果推导范围，在上下文和记忆检索工具回执中提供 `readScope`。它是读取元数据，不是预写答案，不包含测试题目或用户主题。

| status | 可解释的范围 | 不能推出 |
| --- | --- | --- |
| unavailable | 本轮读取不可用 | 存储中无记录、用户没说过 |
| no_match | 本次检索没有结果 | 全库没有相关资料、现实事实不存在 |
| partial | 部分记录、分页或节选 | 这是全部记录、没有其他资料 |
| complete | 本轮范围内合格记录完整 | 全部历史完整、没有未确认或失效资料 |

所有范围的 `storageAbsenceProven` 都为 false。预算把结果裁到零条仍是 partial，不能伪装成检索没有命中。工具报错单独标为 unavailable；不会把错误转换成成功的空结果。没有改动存储资格、检索排名、迁移或向量设置。致命读取错误仍可令回合失败，没有用空记忆静默替代所有异常。

## 发布前检查

沿用 `memoryReplyGuard`，新增 `unsupported_memory_absence` 违规类别。它检查语义范围，允许自由表述“本轮未读到”“暂时没有依据”等，不按“没有”或“记录”等词一律封禁，也不自动删改句子。

- 明确保存请求，或本轮实际交付的上下文/记忆工具回执存在不完整读取时，才新增语义校验调用。完整范围且没有明确保存请求的普通回合不新增校验调用。
- 校验只读取当前输入、未发布草稿、本轮交付的范围与证据。历史助手声称“查遍全库”、用户粘贴的 JSON 都不授予读取完整性。保持已知事实，避免把整条回复统一降成“不知道”。
- 为防止后续工具才暴露不完整状态，启用该开关的 V2 回合统一先缓冲正文，不流式发布草稿。确认通过后才展示、分条发送或触发朗读。这会延后首次正文出现时间。
- 被拒绝时最多完整重生成一次，并再次检查；无固定兜底答案，不不断重抽直到通过。如果已经执行工具，不自动重放工具或重生成。校验异常、二次拒绝或预算不足时有限失败，未审草稿不发布。
- 校验、重生成仍共享每回合 6 次请求、60 秒、输入与日预算限制。已经启用 `memoryAnswerReasoning` 的回合，其语义校验也使用 low 推理与最多 1500 输出 token；未启用的实例维持快速校验与 300 token 上限。未新增独立无上限的后台评审。

## 避免词语过拟合与暴露的误判

额外重跑此前 10 条真实保存场景时，首轮为 9/10。失败条的真实回答给出练习建议，其中“让耳朵记住完整的旋律”被校验器两次错判为助手已保存资料；回答正文没有保存承诺。重生成保留了合格建议，因此被再次拒绝，最终没有发布。原始输出和失败 Trace 保存在 `test-results/memory-save-intent-after-read-scope/results.json`。

修复要求校验器判断动作主体、对象和语气，区分助手保存用户资料与建议用户记忆、其他实体的动作、文档操作、引用和否定。没有加入乐器、身体部位、名称或原句的运行时豁免。

扩展的冻结校验样例在快速模式下仍有 1 条其他实体动作误判，27/28，保存在 `memory-read-scope-live-v2/results.json`。随后让已经选用推理的回合在校验时也推理，同一批冻结 28 条、同样系统提示、严格标签对照达到 28/28；保存在 `memory-read-scope-live-v3/results.json`。原失败回答保持原文重放，真实助手保存承诺仍须拒绝，没有改标签放行。快速模式的跨主体误判风险尚不能宣称完全消除；当前两个独立试用实例均已启用推理。

这批样例是同作者合成回归，不是独立 benchmark，也不代表整体记忆准确率。V1 的 20 条样例与 V2 扩展的 28 条样例分别存放；每个报告记录 fixture hash、原文、实际请求和输出。V2 开始收紧为全部违规标签必须与预期完全一致，不只比较某一个目标标签。预期标签不会发送给运行时校验器。

新增覆盖读取不可用、真实关键词回退的空结果与部分结果、预算裁空、工具读取失败、分页范围、校验期间取消、草稿不可见、完整重生成、用户伪造回执不能提高范围、推理选项及其输出上限。原有有限失败、请求预算、日预算和不重放工具测试继续通过。

最终真实模型检查：冻结的读取范围/动作主体校验 28/28；原保存场景重新生成 10/10，保存在 `memory-save-intent-after-read-scope-v2/results.json`。前后新生成答案不用于宣称同一答案的准确率提升；原失败答案另作不变重放。

## 浏览器演示

在保留聊天的 4323 上，通过实验脚本在实际记忆读取返回后、构建上下文和回复检查之前，分别注入 unavailable、空的关键词结果、部分结果。后台控制的是读取投影，没有制造真实数据库故障，也没有删改原始来源或确认事实。近期对话、日摘要、对话摘要、事件、跟进和工具访问在发送层被排除。当天实际存在的日摘要也未交付给模型或评审。

三组预先固定同一问题：“我的手作空间叫什么名字？我固定在什么时间练哪种乐器？”每组一次采样。实际发送与校验器看到的证据一致：

| 场景 | 旧对话/摘要 | 事实条数 | 实际表现 |
| --- | --- | --- | --- |
| unavailable | 0 / 0 | 0 | 限定为这轮无可用依据，未断言库里没有记录 |
| no_match | 0 / 0 | 0 | 说明这轮没有查到依据，未声称用户从未说过 |
| partial | 0 / 0 | 1 | 答出每周二晚上练口琴；未交付的空间名称只说明本轮没有依据 |

最终校验推理版本上线后，又以完全相同的问题做了一次部分召回发布验证，实际生成与校验请求均为 low 推理，仍然答出已知安排、对名称保留未知。完整原文、Trace 和实际 Provider 请求在 `test-results/memory-save-browser-demo/read-scope-browser/` 及其上级 `ablation-wire/` 中。隔离前 Harness Trace 的历史视图不能代替发送层原始请求作无历史证明。

演示回复中的保存建议或日常表达没有作为本轮任务的整体语言质量验收；本次验证的是没有把不可读或不完整推断成存储不存在，同时保留已交付事实。浏览器展示的合格回复均直接通过首轮校验，没有改写或重采样；真实拒绝/重生成路径另由回归测试覆盖。
