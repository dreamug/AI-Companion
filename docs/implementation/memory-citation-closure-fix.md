2026-10-24。承接[五题复核报告](memory-answer-five-case-audit.md)。本次只修改工程和隔离评测，没有迁移正式库、启用正式向量或重启正式服务。

## 两条原始诊断

原答卷来自 `test-results/memory-answer-delivery-final/results.json`。原文件不修改；`memory-citation-incidents.json` 保存原回答、实际交付资料、来源文件 hash，以及人工逐项核对的证明。证明注释与原答卷分别保存。

1. **辅助引用遗漏确实存在。** 回答说“蓝老师是航天工程师”，职业资料的主体却是“用户的姐姐”。所以职业记录与称呼对应记录共同构成证据；不能只引用职业。开头使用个性呼语时，其偏好依据也纳入严格引用合同。原来漏引的答卷必须继续失败，不能因为该记录在上下文里就自动替回答补 ID。
2. **复合句回答和双引用原本正确。** “除了修复之外也会制作陶瓷”同时承诺修复与制作两项属性。前者由职业资料支持，后者由技能资料支持。不能只评主结论，再把职业引用判为多余；也不能删掉正确引用迁就评审。

离线回归要求：原漏引失败；原话仅补齐实际所需来源后通过；原复合句保留双引用通过；故意漏掉任一属性、身份连接或来源均不通过。人工证明是固定回归的测试预言，不参与新回答的自动评分。

## 实施方式

### 回答生成

`src/context.ts` 使用一份稳定的通用记忆规则：主体、时间、现实范围、属性粒度、已知与未知，以及多条记录间有依据的身份连接。交付记录中的“用户”指当前对话用户；其他主体仍分别核对。身份对应允许代换同一属性，不允许跨人或跨属性推断。

删除了上一轮具体职业、亲属职业、修复／制作的示例，以及按“是否、也会、兼任”等问法追加提示的分支。合成 JSON 输出合同独立规定：问句中的已陈述前提或背景不算所问目标；`abstain` 和引用都必须由生成方正确输出。普通聊天没有新增 JSON 格式或远程评审步骤。

合成评测严格保留原始 JSON：不删额外字段，不改布尔值，不修剪回答正文；仅将实际存储 ID 映射为题集 ID。映射前另核对原引用是否确实交付，不能让猜中的内部题集 ID 冒充真实来源。重放从 `raw` 重建输入并核对保存的 `answer`，不再信任旧版本可能丢字段的 `protocolInput.answer`。

### 评审先定位原文，再核对来源

当前入口为 `scripts/lib/memory-claim-audit.ts`：

1. **锚点提取不看标准答案、预期 ID、自报引用或事实库。** 输入只有问题、完整回答及从回答生成的句法分段。原文逐字拼回，`focus` 必须来自其原文单位。第二阶段不接收自由改写的断言文本，避免评审自己添加“专注、仅仅、正式”等限定。
2. **句法约束覆盖复合结构的两臂。** 对“除了……之外还……”“不仅……而且……”“既……又……”“虽然……但……”分别保留原文锚点。带这些词的书名、引语不机械拆开。同一未知命题内部的引入和限定不按每个逗号强行分成新事实。短肯否回应不能藏成礼貌语而跳过事实依据。
3. **每个原子分别核对证据路径。** 程序为每个锚点创建独立来源任务，不能由模型只返回主问题的一行来省略背景。普通事实只交付所属原文单元、前文限定及当前语法臂；单独肯否与未知回应才附原问句帮助消歧，避免主问题或另一臂覆盖当前属性。 `entailed`、`valid_unknown`、`valid_meta`、`unsupported` 等枚举分开表达事实有据、合理未知和纯回应，避免一个 `supported` 布尔值混装不同含义。来源引用须是实际交付资料的连续原文。直接资料支持属性；`subjectLinks` 显式登记必要的身份对应及来源，不接受只在解释文字里提到辅助依据。
4. **按完整路径检查引用集合。** 每项事实至少有一条完整路径被回答实际引用，回答的每个引用也必须真正用于路径。盲评可能先选另一条充分来源，因此对尚未用于证明的原引用，逐条独立检查它是否也支持已有事实。如果某项事实仍缺少回答实际引用的完整路径，即使某个引用已经用于其他事实，也必须检查它能否同时支持这一项；“引用已使用”不能代替逐事实完整性。空匹配是正常拒绝结果；不能借另一个直接来源让无关记录混进路径，也不能把原来无据的事实翻成有据。等价的充分来源可分别成为替代路径；未选择的替代来源不强加给回答。必需身份桥不能作为可省略的替代项，未知／纯回应不需要伪造来源。
5. **独立审查覆盖与目标映射。** 在所有原子的来源任务之后，再核对完整回答的覆盖；连接词不是第三项个人属性，普通来源引导语也不强制另造断言，额外的全库范围声称仍须核对。**所问目标映射到实际断言。** `targetClaimIds` 指向本题所问属性的事实或未知声明。背景事实不能替代主要目标。程序保留原始 `abstain`，不按测试标签替模型改正。

`memory-proof-bindings.ts` 做主体证明的必要结构检查：引用原文真实存在、映射端点有原文依据、所需连接完整、无关身份来源不得混入。普通姓名要求连续出现；用户属格在汉语话题／把字结构中可有句法插入。它不是新的实体数据库，也不是自然语言蕴含的最终真值，不能把相同称呼自动当作同一个人。

### 评审失败也保留

每个逻辑任务最多修复一次结构错误，不重试语义判错来追分。一份回答最多自动核对 24 个原子及 24 条待核原引用（包括存在未闭合事实时已经用于别项的引用），单原子任务并发最多 3 个；拆解、每项来源、每条待核引用、完整覆盖各是固定任务。含一次结构修复的理论上限为 `2×(24+24+2)=100` 次调用，单次期限 60 秒、整份评审期限 240 秒。达到总期限即停止，不保证执行到理论上限。超过数量上限保留全部原文并标记待复核，不截掉尾部来凑通过。实际无据断言、漏引、乱引和自报标记错误不触发重写回答或重试回答。原子来源核对负责最终类型，独立覆盖审查再次核对其语义；开头已经识别的个人事实不能降成礼貌语后放过。每次调用使用独立消息快照，格式修复反馈不会反向改写此前请求记录。

锚点提取与普通当前用户事实核对使用温度 0；其他主体的事实、待核引用及覆盖检查使用请求级低档推理。这是按任务角色选择配置，不按题号或答案选择。推理调用额外预留 4096 输出 token，但不改变证据要求；截断结果即使可解析也不得接受。请求配置的来源与取舍见[独立决策记录](../engineering/memory-review-request-profile.md)。

所有阶段保留原始输出、模型、请求 ID、用量和实际请求选项。已保存的评审证明可以经 `--audits` 复验，但必须绑定同一原答卷 hash；程序重新检查原始 JSON、实际交付 ID 和完整证明，不信任保存的通过标记。模型异常、字段遗漏或仍未解决的分歧保持失败／待复核；待复核不能算作已正确拒绝一个反例。

这些额外调用只属于离线评测，不增加普通聊天的读取延迟。

## 过拟合审查

| 检查项 | 本次处理 |
| --- | --- |
| 运行时出现测试实体、答案或题号 | 通用系统指令不包含测试姓名、书名、职业或题号；新增上下文回归检查稳定指令与无按问法追加字段 |
| 为某个负例专门写头衔正则 | 删除评分器的头衔拦截特例；以原文覆盖、实际证据与反例检查处理 |
| 用标准标签改正模型布尔值，或者关闭引用校验 | 删除 `scoreMemoryMeaning` 和旧的宽松评审验证入口；验收和重放一律使用原字段 |
| 将预期来源暗示给评审 | 拆解和来源盲评不发送标准答案、预期来源或自报 ID；反向引用核对只展示当前待核引用，不展示预期得分；程序最终严格比较原引用集合 |
| 只测试原来的职业和亲属问法 | 冻结不同人物、地点、交流技能、非人物别名、并列属性、否定、无依据呼语和无关引用控制；新增完整 Harness 问答题集 |
| 改原题、删除失败项或挑新答卷覆盖旧答卷 | 原始题集、旧答卷及各次失败报告保留；重放绑定来源文件 hash，不重新生成答案 |

“问句不能当证据”的对照指历史记忆召回合同：不能把问题中的假定当成已保存事实；它不禁止普通聊天使用用户当前新提供的信息。

原来的有界 fixture rubric 仍用于冻结历史基线，不冒充通用语言评分器。严格实时验收要求独立评审，`--assert-live` 缺少 `--judge` 会失败。职业／称呼的查询词表仍是人工维护的有限召回扩展，本次未改权重、向量模型或这些词表；它不能被描述为覆盖所有记忆领域的通用语义理解。

句法规则和主体出现检查也有明确边界：它们检查必要结构，不证明任意自然语言都能被正确解释。新题集在首次运行前冻结，但本轮调试后已属于回归资料，不能再称为未见留出集。

## 验证证据

工程验证、严格模型控制和真实回答批次分别记录，不能合成一个“全部准确”的分数。最新汇总见本目录报告末尾的运行结果和 `test-results/memory-citation-summary.json`。

- 固定来源读取：8 套题、262 次读取，有答案的 **188 道题**全部必需来源均齐全（**188/188 题**）；74 道无答案题不计入召回分母。来源门槛从“命中任一预期”收紧为“全部必需来源都命中”。证据：`test-results/memory-citation-release-source/results.json`。
- 原始两例及边界：单元回归覆盖原文分区、两臂漏拆、缺主体桥、未交付／伪造来源、无关或重复引用、错误主体、未知与否定、目标映射、Unicode、引语、有限评审修复及原始回答不可变。
- 模型控制：固定 17 例，6 个正例、11 个反例。结构错误或待复核不能冒充正确拒绝。
- 真实批次：每批一次采样 50 题，24 道历史问法、12 道属性边界、3 道未知额外属性、3 道明确正向证据、8 道新领域引用问题；各题独立上下文。采样与后续评审分离，重放不替换回答。

开发期出现过错误肯定、未知标记不一致、异常 JSON、以及评审漏字段和错误解释来源等失败。相关目录中的 `final` 等名称不表示通过，必须看结果里的 gate；不能把评审待复核当作真实回答错误，也不能把正确文字当作完整引用协议通过。原来“语义 42/42、引用另计”的历史报告不再是当前验收口径。

## 复现

```sh
npm run verify
npm run test:memory:web
npm run test:memory:recall
MEMORY_EVAL_OUT=test-results/citation-gold npx tsx scripts/memory-citation-audit.ts
MEMORY_EVAL_OUT=test-results/citation-controls npx tsx scripts/memory-citation-audit.ts --live
MEMORY_EVAL_OUT=test-results/citation-capture npm run eval:memory -- --live --dataset query-regression.json,answer-boundaries.json,open-world.json,positive-attributes.json,citation-generalization.json --independent --assert
MEMORY_EVAL_OUT=test-results/citation-replay npx tsx scripts/memory-answer-replay.ts --input test-results/citation-capture/results.json --rejudge
```

`--live` 与 `--rejudge` 会发送合成资料并产生模型调用。没有这些选项的工程测试不调用真实远程模型。重放最多两个独立评审并发；模型可以用 `MEMORY_JUDGE_MODEL` 显式选择，实际型号保存在逐次输出中。不同模型和不同评审合同的结果分别保存，不能挑更高的分数当作统一成绩。

复用同一批已完成的来源证明、而不再次调用模型：

```sh
MEMORY_EVAL_OUT=test-results/citation-raw-replay npx tsx scripts/memory-answer-replay.ts --input test-results/citation-capture/results.json --audits test-results/citation-replay/results.json
```

严格 gate 有失败或待复核就返回非零。采样命令中的 `--assert` 只验来源；它不是回答验收，回答必须继续走严格重放。

其中真正的生成问题包括过度弃答、相近技能越界肯定、缺失／无关引用，以及额外 JSON 字段。评审问题包括把一个未知声明继续拆成多条“否定事实”、把 subject 指向属性所属人误读成该人的认知行为、身份预设重复拆项，以及来源证明和输出格式失败。它们不能混称漏召回，也不能把评审错误人工改成自动通过来凑成绩。

因此，本次交付是原始两类诊断的工程修复、严格回归和可追溯评测；**不是“整体记忆回答已经全部通过”**。通用生成与通用评审仍有上述边界。没有据此迁移正式库或开启正式向量。
