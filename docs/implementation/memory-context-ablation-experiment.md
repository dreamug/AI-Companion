# 浏览器与后端联合：排除聊天上下文后的记忆实验

2026-10-24，真实 DeepSeek，本机独立实验服务 `http://127.0.0.1:4322/`。正式服务 4317 和用户试聊服务 4321 均未重启或修改。向量始终关闭。

## 问题与结果

确认一条资料后，排除原始对话和所有摘要，再重启进程，模型能否从长期记忆读回答案？关闭记忆读取时，能否承认未知？

通过正常网页聊天输入随机生成的摄影项目名「苔原灯塔-696774」，由真实后台提取候选，再在网页点击「记住」。预先冻结追问为「我给自己的摄影计划起的名字是什么？」。随机后缀降低凭常识猜中完整答案的可能。

| 阶段 | 后端 PID | 请求内历史消息 | 摘要 | 选入记忆 | 原始回复 |
| --- | --- | --- | --- | --- | --- |
| 排除历史，保留记忆 | 30434 | 0 | 0 | 1 | 你的摄影计划叫「苔原灯塔-696774」。 |
| 排除历史，屏蔽记忆读取 | 31029 | 0 | 0 | 0 | 目前没有与你摄影计划名称相关的记忆，我这边也没查到依据，所以不确定你起过什么名字。你愿意的话，可以直接告诉我。 |
| 再次重启，恢复记忆读取 | 31633 | 0 | 0 | 1 | 你给摄影计划起的名字是「苔原灯塔-696774」。 |

三次使用完全相同的追问与系统提示，模型均为 `deepseek-flash`。为控制变量，实验三阶段都关闭额外回答推理选项。每次实际上下文只有两条消息：当前结构化状态与所选记忆，以及当前问题。没有工具续步，没有把上次回答或预期答案加进追问。

## 如何排除上下文

`scripts/memory-context-lab.ts` 仅在实验服务中改变读取投影：记录先前消息 ID，使正常上下文构建和网页快照读不到这些旧消息。原始消息、来源记录及其版本不变，记忆引用继续有效。没有把来源标为已删除，也没有调用遗忘功能，避免误把“记忆来源失效”当成“清掉聊天上下文”。

每个阶段都真正退出并重新启动服务，清掉进程内的 Run 上下文与缓存。摘要从实验开始就关闭，实际请求再次检查摘要、边界和跟进均为空。负向对照屏蔽事实枚举、关键词检索与上下文记忆读取；数据库中的已确认记录继续存在，所以右侧维护面板仍能看见它，模型请求里没有它。

网页上的消息输入、确认按钮和追问均由浏览器执行；后端只控制实验读取范围、重启及读取 Trace。普通产品的 Harness、上下文构建、模型适配器和记忆资格检查继续工作，没有添加正式的“清空上下文”按钮或配置开关。

## 结论的范围

这一个可观察的正向／负向／恢复对照支持：已确认的记忆可以在没有近期对话、没有摘要且经过进程重启后重新交付给模型；屏蔽该记忆后，模型没有猜出随机名称。

三次读取模式都是 `all`。这是小规模记忆全量注入的验证，不是向量、混合检索、海量筛选、长期确认率或总体回答准确率验证。实验只有一个合成事实，各阶段一次采样，不计算总体成功率。

## 同时发现的残留问题

首次输入明确说了「请记住」，助手仍回复：

> 好，记下了：你的摄影项目名是「苔原灯塔-696774」。
>
> 以后提到这个项目，我就按这个名字来。需要我把它作为长期记忆保存下来吗？你说要保存，我就提交确认。

此时后端仍是待确认，随后确实由网页确认才成为长期事实。底层确认机制有效，但正文重复询问保存意愿、播报流程的约束仍会失守。此前 14 组联调的有限文字检查没有覆盖这种表达，不能据此宣称已经消除此类语言问题。本轮保留原始输出，没有在实验中改提示词或重新采样掩盖它。
