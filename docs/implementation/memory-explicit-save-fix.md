# 明确保存意愿：去除重复询问与发布前回复检查

2026-10-24。已更新独立试聊服务 4321；保留聊天、记忆和设置，正式服务 4317 未重启，正式库不迁移，向量关闭。

## 改动

旧提示把“新记忆先提出建议”与“用户已经要求保存”混在一起；关闭自动整理时，处理明确请求还依赖一次模型工具调用。现在在输入准入时识别常见的明确保存指令并登记提取任务，意愿固定在该 Run 中。普通状态查询、否定和引用中的命令不会当成保存同意。

新版不再向模型声明 `propose_memory`。旧客户端伪造调用仍受原有执行边界约束，不会新增第二条候选。自动整理关闭时，明确请求照样进入统一提取链路。明确保存意愿不等于候选内容已确认；用户仍通过界面确认事实。

模型只在明确请求时收到 `memoryCapture` 的真实处理状态。查询“你记住了吗”不会因此被改成新的保存任务，也不会收到无关的操作说明。去掉了新版系统提示里相冲突的泛化建议要求，回复专注内容和同一消息中的问题。

真实模型实验说明，仅改提示或启用推理仍会偶发“我记住了”或流程播报。因此增加了窄范围的发布前契约检查：

1. 只对新版记忆中的明确保存请求生效，普通聊天不增加校验调用。真实提供方默认开启，试聊入口明确固定开启；模拟测试按配置选择。
2. 这类回复先在进程内生成草稿，校验之前不推送正文、语音或分条消息。
3. 校验只判断重复征求保存意愿、内部流程播报、虚称已确认保存，不使用目标答案、题目 ID、特定菜名、项目名或实体规则。
4. 不合格时最多完整重生成一次，提供原草稿和违规类别供模型改写，再校验一次。没有程序删句、局部替换、固定回复或无限重抽。
5. 两次仍不合格、校验协议无效或预算不足时，本轮有限失败，不把草稿冒充合格答复发布。已经执行过工具的回合不自动重生成，避免重放领域副作用。
6. 校验及重生成都计入原有最多 6 次模型调用、60 秒和 token 预留。保持原 Run 的模型、人格与配置，支持取消和迟到结果拒绝。修复后的实际请求及提示哈希可由 Trace 查看。

试聊已有的 `memoryAnswerReasoning` 选项扩展到首次明确保存请求，即使该轮还没有已选记忆也能使用；仍先预留额外输出预算，后台提取不继承这项回答推理设置。未开启该选项时不擅自开启推理。

## 验证

- 最终类型检查、构建与 587 项测试通过，39 个测试文件。相比上轮增加 48 项：意愿与链路 26、离线诊断 12、发布契约 10。
- 网页回归 8/8，新增关闭自动整理时仍能从明确请求产生候选、界面确认前不成为已确认事实、刷新不重复的验证。
- 原始失败和其他话题组成的 10 组冻结合成联调，最终实现下 10/10 通过。覆盖称呼、爱好、否定偏好、习惯、混合问题、不同句法、关闭自动整理、状态查询和引用对照。预期标签不提供给模型。
- 其中称呼与否定偏好的草稿各触发一次拦截，完整重生成后通过；记录保留原始模型调用与违规结果。不能把这 10 组的通过换算成总体记忆准确率。

新增回归还覆盖：草稿不可见、校验非法 JSON/未知字段不默认通过、重生成仍失败时有限终止、取消后的迟到结果、已执行工具不重放、校验调用预算检查、校验也受第 6 次请求上限约束、普通聊天不继承校验、Run 配置不受后续修改影响。

所有早期试验结果保留，包括提示词阶段的流程播报、提前声称记住、一次提取来源 ID 不合法，以及第一版发布检查重生成失败的记录；没有修改原始结果。各阶段是不同答案的采样，诊断也曾补强，不能当成同一份答案重放的分数提升。
