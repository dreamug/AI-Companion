# 多 bot、角色与相处设定交付

2026-10-23 · 私人本地版本。本轮保留原小野，新增独立的成年 AI 恋爱陪伴角色「小棠」，网页可以创建、切换、编辑、归档和恢复角色。

## 已实现

- 顶部角色选择器；切换时结束旧页面连接、停止播放并进入新角色页面。浏览器地址带角色 ID，刷新仍停留在所选角色。每个标签可以使用不同角色。
- 角色名称、身份、表达风格、对话示例、虚构背景、兴趣；日常陪伴／虚拟恋爱／自定义相处模式，以及双方称呼、互动方式和边界。发布后影响新接受的运行，旧运行固定原版本。
- 原小野继续使用原 `data/companion.sqlite` 与已发布人格，不复制、不清空、不替换其记忆。原角色不允许归档。
- 小棠与后续角色使用 `data/bots/<botId>/` 独立数据库；消息、来源、记忆、运行、任务、预算、事件、Trace、导出和备份按角色隔离。API 使用显式角色选择，非法或未知 ID 不回落到原角色。
- 归档保留数据，取消该角色活动／排队对话并停掉调度与连接；恢复重新打开原数据。关闭期间过期事项沿用原有时效规则，不批量补弹通知。角色总数暂限 24（含归档），没有永久删除入口。
- 相处模式与角色设定参与真实上下文和关心草稿；AI 身份的诚实要求不再被提示为拒绝知情虚拟恋爱的理由，现实生活与用户停止要求仍受尊重。

角色目录 `bots.json` 保存 ID 与状态，名字显示优先取该角色已发布人格。底层模型凭据和语音服务配置仍由当前本地服务统一提供；聊天模型选择、记忆、预算和免打扰状态各自保存。没有增加公网账号或多用户身份系统。

## 使用

打开 [本地测试台](http://127.0.0.1:4317/)，刷新旧页面后，顶部选择小野或小棠。「人格」面板可修改角色与相处设定；「新建角色」可从日常陪伴或成年虚拟恋爱模板开始。「已归档角色」可恢复此前角色。

新 bot 不继承另一角色的聊天和记忆；新增时仅沿用原角色已确认的模型外发许可状态。用户可以在运行设置撤回当前角色的许可。切换会重新载入页面，未发送草稿保存在当前浏览器标签会话中，切回原角色可继续，不会带到另一角色。

网页「导出当前角色数据」「备份当前角色」只作用于当前角色。原来的备份 CLI 默认仍针对原小野的数据目录；不要把原角色单库快照误认为包含全部 bot，完整迁移须保留角色清单及所有角色目录。新角色单库备份恢复需要使用其原 scope，不能用原小野的固定 scope 打开。

向量记忆本轮只调研，结论与合成检索实验见 [向量记忆决策](../research/vector-memory-decision.md)。当前没有接入 Embedding、向量扩展或新的远程记忆服务。

## 工程适配依据

参考固定 Kimi 快照 `9e1248416faa22d9f0b777b91ad092bbf1e19182` 的 `_base/di/lifecycle.ts`、`test/_base/di/scope-tree.test.ts`，采纳「资源随其拥有者释放，子作用域状态不能向其他子作用域泄漏」的不变量。Adapt 为每 bot 一个 Store／Harness、独立任务和信号；请求固定选择目标，页面切换释放连接和播放。没有移植 Kimi 的 DI 或会话框架。目标项目没有 Git 历史，本轮依据实际源码和测试记录。
