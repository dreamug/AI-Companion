## 隔离方法与证据

本次与早先 4322 实验的区别是：不屏蔽数据库或网页的消息视图。只在实验启动脚本 `scripts/memory-save-browser-demo.ts` 的模型出口应用纯读取投影 `scripts/lib/memory-ablation.ts`，原聊天继续完整显示。

正常产品先完成记忆资格检查、来源核验与选择；实验投影只保留其中已确认且非事件的事实以及当前问题，去掉全部历史消息、对话摘要、日摘要、事件、边界、跟进与工具声明。负向对照进一步去掉事实，把读取覆盖状态标为不可用且不完整。未把预期答案加进系统提示、当前问题或修复提示，未改写模型输出。

每次切换都真正停止并重启 4323 进程，清除应用内 Run 上下文和缓存。模型接口是独立请求，没有复用远程对话会话。三阶段系统提示、模型、推理选项、输出上限和工具设置相同。每次实际发送恰好两条消息：当前结构化数据和当前问题；工具声明为空，不能通过工具绕回旧原文。

实际发给 Provider 的请求及原始输出保存在 `test-results/memory-save-browser-demo/ablation-wire/`。每阶段记录的 `actualModelRequest` 是隔离后的实际请求；`originalHarnessTraceNotWire` 是隔离前的 Harness Trace，不能混用后者来证明最终请求内容。`ablation/summary.json` 汇总了验证结果。

实验开始时数据库原本没有对话摘要，因此本次直接观察到的是“请求无摘要”；投影删除已存在摘要、事件和其他文字通道的行为另外由回归测试验证。没有为了构造摘要而向现有聊天插入测试记录。

## 暴露的问题与适用范围

负向回答能承认没有依据，且未猜中任何答案；但“记忆里都还没有相关记录”把本轮不可用推成了存储中不存在，表述不正确。末句对下一次记忆的承诺也偏强。这些原始文字已保留，没有重采样或放宽评分。本轮任务是隔离演示，未顺带修改这部分产品行为。

两个正向阶段读取模式均为 `all`：少量合格事实全量交付。这证明小规模长期事实读取链路在本次实验中有效，不能用于证明向量必要性、混合检索质量、大规模召回率或所有问法的回答准确率。
