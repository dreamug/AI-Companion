## 2 实际修复

`src/context.ts` 的产品系统指令现在明确：核对主体、时间和现实范围；允许有证据的同义回答；多项问题回答已知部分并说明缺失；不能把已知职业扩成正式职位、工号、职级、地址或入职日期。修复作用于普通聊天，不只用于评测 JSON。

额外测试发现两类实际推理风险：不同的已知职业不能排除兼任；修复工作不能证明制作技能。读取到全部合格记录，也不表示用户现实属性已经完整。对“是否、还会、也做、兼任”等核实问法，当前上下文增加通用证据提示：只有该项的直接肯定或否定记录才支持确定回答，不能先回答“不是／会”又承认未知。**有明确额外技能或兼职记录时仍须直接回答**，由独立正例题集验证。

运行时没有题号分支、合成答案、评分器或远程评审调用；没有改 E5 权重、检索参数或事实内容。事实读取资格、预算与隐私边界沿用原合同。

## 3 评分与评测修复

新的流程把三件事分开：来源是否进入上下文、回答是否符合事实、输出是否满足合成测试协议。

1. 首先校验结构、Run 完成状态和本轮实际交付资料。坏 JSON、错类型、重复 ID、引用未交付资料，以及凭未交付事实作答，不能被远程评审覆盖。取证读取最终实际请求中的上下文与 `search_memory`／`read_memory_source` 结果，不只看初始 top-5；未进入请求的缓存、伪造的用户 JSON 和不完整片段不能冒充完整事实交付。
2. 保留旧字面指标。另用有来源绑定的有限断言合同接受同义表达：每个事实分句都要有本轮交付资料支持，不是“包含标准答案就通过”。事实含义不依赖测试 JSON 自报的 `abstain` 或 `memoryIds` 是否完整：比较时用冻结题目的已知／未知标签，仍独立检查文本是否真的回答或承认未知；原始文本、标记和引用数组完全保留。遗漏自报 ID、未使用的自报 ID、标记不一致另外审计，不能洗成全协议通过。单纯呼语须有合格偏好依据，未经验证的称呼在进入远程评审前就拒绝。
3. 合同识别不了的表述进入 `review`。显式加 `--judge` 才做额外的只读模型评审，逐条保留事实／未知声明／回应或推理说明、来源 ID、原始评审和用量。未知声明和“修复不等于制作”这样的推理说明无需伪造个人事实来源；正确承认未知是正确处理，不因没有具体值而判错。
4. 同一供应商的模型评审**会误判**，不是独立真值。原始自动结果、评审分歧与重新复核均保留，不用重复生成回答来替换失败样本。文本事实模式要求断言由实际交付证据支持，严格引用模式还要求自报引用逐项闭合；推理说明复用已有事实来源并不构成额外断言。`memory-answer-replay.ts` 支持原答卷重放；`--rejudge` 仅重新评审原答案，不重新生成答案。缺少旧 ID 映射时明确待复核，不猜映射。
5. 真实问答默认可选择 `--independent`：只清理本次临时库中此前的合成交流，断言每题 `historyIds=[]`，避免相似题的前一轮答案泄露给后一题。每套题使用同一份合成输出约定，修复累计追加人格指令和示例预置 `abstain=false` 的偏置。

`abstain` 的含义是“所问主要属性未知”，不是“完全没有任何相关背景”。未知工号时可以解释有来源的已知职业，但仍须 `abstain=true`；若解释了事实，应引用它。对职业与工号的联合提问，可以回答职业、说明工号未知，整体不应因局部缺失而弃答。这是测试协议，普通产品聊天不要求输出这些 JSON 字段。

## 5 保留的失败与限制

原始 19/24 不删除。中间运行 `memory-answer-fix-first`、`memory-answer-fix-repeated`、`memory-answer-fix-acceptance`、`memory-answer-boundary-acceptance`、`memory-answer-acceptance` 等均保留原结果；目录名不构成“已通过”的声明，应看其 gate。

其中 72 条中间答卷在当时的严格引用重放中仍拒绝一条：正确承认工号未知，却解释了检索到的无关角色记录而未引用。这是合成引用协议／输出相关性问题，不能算成另一道事实漏召回，也不能从分母删掉。旧边界答卷有一条补充称呼无法从旧报告重建额外 UUID 映射，明确记为 `replay_alias_unavailable`；新报告保存完整 `scoringInput`、原始 `protocolInput` 和实际交付路径解决可重放性。

扩展测试还真实抓到过先说“不是／会”再承认未知的矛盾回答；修复过程及失败答卷保留。模型评审也曾错误要求未知声明提供来源、把正确弃答判失败、把“你是修复师”误当正式职位推定。不能为了服从这类误判，把正确产品回答改成错误回答。

有限合成题、单次或少量重复采样不能证明所有自然问法都正确；模型评审也不能替代真实用户观察。MEM-G1 自然观察仍未完成。此次没有修改向量扫描或装载逻辑，不把此前的容量性能结果冒充本轮重新压测。

## 6 复现

```sh
npm run verify
npm run test:memory:web
MEMORY_EVAL_OUT=test-results/memory-answer-audit-recheck npx tsx scripts/memory-answer-audit.ts
MEMORY_EVAL_OUT=test-results/memory-answer-controls-recheck npx tsx scripts/memory-answer-audit.ts --live-controls
MEMORY_EVAL_OUT=test-results/memory-answer-live-recheck npm run eval:memory -- --live --dataset query-regression.json,answer-boundaries.json,open-world.json,positive-attributes.json --independent --judge --assert-live --assert
MEMORY_EVAL_OUT=test-results/memory-answer-plain-recheck npx tsx scripts/memory-answer-plain.ts
MEMORY_EVAL_OUT=test-results/memory-answer-replay-recheck npx tsx scripts/memory-answer-replay.ts --input test-results/memory-answer-delivery-final/results.json
```

带 `--live`、`--live-controls`、`--rejudge` 和普通聊天检查的命令会向远程模型发送合成资料并产生模型调用；普通 `npm run verify` 不调用真实远程模型。读取与迁移都在临时库；正式开关不受命令影响。语义评审异常或仍待复核时，`--assert-live` 返回非零，保留原始结果。
