## 1 冻结范围与保护结果

- 设计保持v3.4，仅修正实施状态、交付门槛和历史时态。主动触达独立验收，不阻塞记忆交付；72小时空闲问候暂缓。
- 4331从新空库建立，独立目录、关系身份和会话Cookie。没有复制4321资料，也不自动合并回原bot。页面保留本次合成演示和调试记录，其中早期失败回复未被改写。
- 新实例主动发送关闭且界面不可打开；后台tick不执行跟进，新实例向量关闭、向量表0行。受限私人事件、观察、主动接续、bot自述学习等未开放。
- 原有7个数据库的schema及messages/memories/settings行数和逻辑内容哈希，与实施前只读快照完全一致。`env.local`、旧试聊状态文件哈希一致；正式4317（PID 65891）和4321（PID 87427）仍为原进程，没有重启。
- 编译输出写到测试结果目录，没有覆盖正式服务使用的根目录dist。

保护证据：`test-results/companion-memory-cm3/protection-before.json`、`protection-after.json`。这里只声称这些已核对项目一致，不将SQLite的WAL文件字节变化当业务变更，也不声称对任意外部文件作了全盘比较。

## 2 实际实现

| 部分       | 本切片行为                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 显式准入   | 新入口显式启用schema3并先留备份；普通启动不自动升级原库，旧模式不能硬开schema3                             |
| 输入与提取 | 用户输入事务登记inbox；一次有界结构化解析，只引用当前用户的唯一连续证据；上一条已展示助手只作解释语境      |
| 自动形成   | 低风险、本人、明确稳定陈述可自动提交，保存为stated及committed admission，不伪造人工confirmed；不用确认卡片 |
| 关键档案   | 姓名、长期/当天/交流段称呼、禁用称呼和有限交流边界使用结构化槽位；关键档案独立装入上下文                   |
| 真实操作   | 保存、更正、遗忘的事实、槽位、来源、回执在事务中提交；幂等/CAS拒绝重复或过期更正，partial不说全完成        |
| 及时生效   | 先commit再组装本轮上下文，不等向量、MD或摘要；当前切片普通形成也串行等待，快速路径后续再做                 |
| 发布       | 沿用事实和操作两项检查；不发布未检查草稿，不启用风险分级流式实验；失败有固定中性回应，Run仍计失败          |
| 遗忘       | 保留界面聊天时屏蔽模型原文区间、修订链、派生记录、工具结果及旧助手投影；删除台账可阻止旧备份复活           |
| 恢复与隔离 | 重启保留事实/聊天；中断inbox不自动重放聊天，取消拒绝迟到提交/回复；同库不同关系不得串读                    |

主要新增：`src/memory/companion-types.ts`、`companion-schema.ts`、`companion-v3.ts`；适配既有Store、Harness、上下文、读取/来源、服务器和测试台。没有重写Agent内核或新增通用调度器。

实现复用了Kimi参考中的持久记录与只读投影边界、事务和生命周期约束；参考版本为本地`kimi-cli`提交`9e1248416faa22d9f0b777b91ad092bbf1e19182`，没有运行或改动参考项目。

## 4 浏览器证据与发现的问题

以下均在4331发生，内容是合成测试资料。

1. “以后聊天叫我南枝吧”当轮形成preferred_address；“请记住，我平时放松会去观鸟”提交普通事实，没有重复询问确认。
2. 重启仅新实例，聊天和事实仍在。点“只清模型近期上下文”后，以不同问法问称呼和放松方式，回答南枝与观鸟。
3. 普通分享写作音乐后自动形成；自然更正音乐为爵士乐，旧值退出有效事实，新值立即生效。
4. 不带保存命令的饮品偏好自动形成。清近期原文/摘要后问称呼、写作音乐及饮品，均按长期事实回答。Run `68ae6b30-482c-4587-aa5d-e0feec07306f`的historyIds和summaryRefs均为空。
5. 按指令遗忘放松活动、饮品，聊天保留；称呼和音乐保留。再次清上下文后问四项，回答南枝和爵士乐，对饮品与放松活动说目前依据不足，不猜、不声称用户从来没说过。
6. 最终Run `fc8a30db-96fa-4121-b704-5d07ed9bfe54`的historyIds/summaryRefs为空，selected只有称呼和音乐两条，pending候选与后台job为0、向量表为0。不是靠近期原文、pending或摘要得到答案。

本次真实发现并修复了三类通用问题，调试失败没有从历史记录里删除：

- 更正后旧事实已过滤，模型误说没有找到旧依据。现在投影带真实replace及replacesId，区分旧值退出有效集合与更正未成功，不重新注入旧正文。
- 解析器把普通分享当成save意图，触发存储办理播报。明确区分用户本轮意图与系统自动add；CM3检查普通分享的主动办理汇报，仍允许明确命令的真实简短回执。
- 遗忘指令自身被屏蔽后，模型误答上一轮问题并否认已执行。当前指令投影保留程序给出的intent/receiptId/status，不恢复遗忘内容；操作检查同时检查与真实已提交回执相反的说法。回归及另一属性的真实浏览器复测均通过。

这些修复按操作类型、来源资格和回执工作，没有按昵称、食物、爱好或冻结题ID添加生产分支。最终遗忘回复仍略机械、重复提及保留项，属于后续陪伴体验观察，不据此声称温度层达标。

## 5 如何继续试聊与运行

入口：http://127.0.0.1:4331/ 。当前保留了本次合成演示记录；称呼仍为南枝，音乐仍为爵士乐，可自然更正为你的测试值。4321原聊天与记忆留在原入口。

数据目录：`local-data/memory-cm3-2-trial`；关系身份：`cm3-2-isolated-trial`。实例已在后台运行，状态见同目录`trial-status.json`，日志见`daemon.log`。需要手动重启时，只停止该状态文件标识的新实例，随后在项目目录运行：

```sh
node_modules/.bin/tsx scripts/memory-cm3-trial.ts
```

不要重复启动占用同一端口/目录，不要把旧库复制进这个目录，也不要给正式服务加memoryV3开关。停用试聊只需停止新实例并保留目录；schema3保护不能通过降低user_version或改成旧模式绕过。

试聊可以自然进行，不必照固定句子：换个称呼并设一天的临时称呼；随口分享低风险稳定偏好；用问句、假设和他人的偏好作对照；更正一个值；忘掉其中一项并保留聊天；点清上下文后以不含答案的问法回问。管理页可检查来源，文本更正经聊天执行，避免界面手工造事实绕过准入。

先观察7个自然日，争取30个实质回合，不强迫补聊。可选记下“被记得”“像客服”“被打扰/监视”“说错了”的具体一句及当时背景；没有设置自动通知或主动跟进任务。

## 6 当前限制

- 普通回合仍串行准入、生成、事实检查、操作检查，通常4次模型调用，修复可能更多。本次11轮诊断耗时3.8至6.2秒；不是固定负载，不据此发布P95或语音实时性结论。
- 本次普通事实少，主要走有界all读取；向量关闭。不拿本次小库试聊证明多年使用下的召回准确率。
- 提取看到的existing最多32条且1800估算token；远期旧对象可能需先查找，目标不足时不能猜着覆盖/遗忘。通用主动检索与快速路径在后续阶段。
- 不支持受限私人事件的自动形成、首次征询、间接E5、观察、跨天主动接续或主动触达；没有完成144个完整规划位置、120次各路径负载或7天真实观察。
- 没有交付完整MD管理界面、人格自定义故障模板或通用实体学习；关键槽位与真实提交是本轮重点。现有摘要在新切片关闭，验证更正和遗忘不依赖摘要补救。
- 语义提取、事实与操作评审不是形式化证明。浏览器中已记录的机械感和多余复述需要真实试聊反馈；先收反馈，不继续扩设计版本。
