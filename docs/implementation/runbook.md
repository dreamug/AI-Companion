# 启动与使用手册

2026-10-23 · 当前单用户实现，配合[验收报告](acceptance-report.md)阅读。

## 启动与配置

要求 Node.js 24+。本机为 Node 25.2.1，另在隔离的 Node 24.15.0 完成独立安装与验证。请从项目根目录启动，后台显式从这里加载 `env.local`：

```sh
cd /Users/kuanyu/Projects/aic_project
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:4317>。当前机器已完成安装和构建，可直接 `npm start`。Ctrl+C 停止，再次启动保留历史。`npm run dev` 直接运行 TS，没有自动重载，改代码后需重启。

已有 DeepSeek 配置保存在 `env.local`，继续兼容。默认地址 `https://api.deepseek.com`、模型 `deepseek-flash`，普通对话显式关闭 thinking。

在「人格 → 运行设置」选择服务商：DeepSeek（DS）支持 Flash／Pro，xAI（Grok）使用 `grok-4.3`。填写所选服务商的 API Key 后点击「保存运行设置」，会先保存 Key，再保存模型与其他设置；也可以单独点击「保存 Key」。输入框留空会保留已有 Key。每个角色分别保存模型选择和两家的 Key，切换时无需重复填写，重启后继续生效。

BYOK 优先于对应服务商的后台环境配置；「移除 BYOK Key」删除该角色保存的 Key，并回退到后台配置（如有）。页面只显示配置状态，Key 不回显，也不进入 SQLite、Trace、导出或数据库备份。Key 以明文保存于当前角色数据目录的 `model-keys.json`，权限 0600；迁移机器时需单独安全迁移或重新填写。Grok Key 不会用于 DeepSeek，反之亦然。缺 Key、凭据错误、额度不足和限流都有对应提示。

Grok 通过官方 `@ai-sdk/xai` Responses 接口接入，设置 `store: false`、`reasoningEffort: none`，以当前角色的模型处理对话、工具请求和后台归纳。运行固定最初选择的模型；切换影响新运行。模型返回的工具请求仍由 Harness 校验与执行。模型标识和能力参考 [Grok 4.3 官方文档](https://docs.x.ai/developers/models/grok-4.3)、[SDK 接入文档](https://ai-sdk.dev/providers/ai-sdk-providers/xai)。模型别名不能当成可冻结的远端快照。

| 环境变量 | 默认／作用 |
|---|---|
| `PORT` | 4317，只监听 127.0.0.1 |
| `HARNESS_DATA_DIR` | 根目录 data；相对路径按工作目录解析 |
| `HARNESS_MODEL` | `deepseek`（默认）、`grok`、`mock`；`grok` 设置新角色的默认模型为 Grok 4.3，已有角色保留已保存的选择 |
| `DEEPSEEK_API_KEY` | DeepSeek 后台 Key；对应角色 BYOK 优先 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` |
| `DEEPSEEK_MODEL` | 新角色默认 DeepSeek 模型，默认 `deepseek-flash` |
| `XAI_API_KEY` | Grok 后台 Key；兼容 `GROK_API_KEY`，对应角色 BYOK 优先 |
| `XAI_BASE_URL` | `https://api.x.ai/v1` |

独立练习环境，不调用远程模型：

```sh
HARNESS_MODEL=mock HARNESS_DATA_DIR=/tmp/aic-harness-practice PORT=4318 npm run dev
```

真实与测试数据应分目录。每个目录只允许一个 daemon，`daemon.lock` 防止误开第二个；异常退出后检查旧进程是否存活，不能删除活实例锁来强开。

## 第一次聊天

1. 阅读并确认页面的外发说明。聊天投影、选中记忆及后台归纳会发送给所选的 DeepSeek 或 xAI。此 API 账号端点的完整训练／保留／远端删除条款尚未确认，不能按零留存理解。
2. 在「人格」查看默认小野，按喜好修改并发布。新版本影响后续 Run，已有运行固定原版本，安全策略不能被人格覆盖。
3. 发一句话，检查回复和运行状态。「停止」使当前运行失效，迟到输出不再提交。断网不是取消，回来会恢复已持久内容。
4. 「Trace / 维护」可选择 Run／任务／跟进，查看程序事件及上下文。上下文敏感且默认折叠，不保存隐藏推理。完整上下文只在当前进程内存保留，重启后只剩投影 ID、预算与选择理由。

专注、免打扰、主动关心和整理记忆建议均是显式开关。空闲无任务时不持续调用模型。免打扰不阻止主动聊天；边界更改可能停止旧生成，让下一次使用新状态。

聊天上方新增「分条回复」和「发送间隔」，分别按当前 bot 保存，默认关闭，旧角色也不会自动开启。发送间隔需要先开启分条回复；切换选项从下一轮生效，不打断当前回复。开启分条后，先生成完整答复，再按语义发布最多四条；短句、代码、列表和长解释可以保持一条。间隔为约 1.2–3 秒，无额外模型调用。

分条生成或发送期间再次发送消息，会停止旧回复尚未发出的部分，并开始回应新输入；「停止」立即取消余下内容。已发消息保留。刷新只恢复后台已提交的消息与进度，不重新生成；若后台进程重启，保留已发部分，未发部分作中断处理，不补发。自动朗读按气泡顺序播放，「停止朗读」会让本组余下内容保持静音，仍可手动重听。现有主动关心投递保持原有行为。详细证据见[分条回复验收](reply-presentation-acceptance.md)。

## 记忆与遗忘

记忆页可添加确认事实、偏好、共同经历，置顶、更正、查来源和旧版本。经历的发生时间与得知时间分开，未来计划不能当成已发生经历。

自动提取只产生待确认建议，最多 20 条、默认保留 7 天。通过列表确认／更正／移除；不会自行升级成权威偏好，也不通知催确认。冲突先保守待确认，明确确认后替换当前版本。

日摘要在启动或跨日首次输入时检查，最多补最近一个有消息的已结束日，不补全部漏天。上下文取最近三个已结束自然日有效摘要，缺日不向前凑数。超长日只取预算内来源范围，Trace 记录覆盖 ID，不保证摘要覆盖全天。人工摘要不自动覆盖；删后不重建，需手动选择「明确重算所选日期」。

- 「移除记忆，保留来源」清派生记忆，原聊天保留。
- 「遗忘这条原始发言」撤销来源及依赖归纳，为避免引用残留，保守清理当前助手正文；相关任务、投递、事件、Trace、导出及在线页面旧视图同步失效。

删除清单先落盘，旧计算不可写回；备份恢复前合并最新清单。页面尽力关闭自己持有的旧通知。已经看到的内容、已下载导出、离线旧页面、WAL／空闲页、旧备份、操作系统快照和提供方副本不保证物理撤回，副本需自行保管和销毁。

## 主动关心

「关心与投递」建立一次性跟进，填写最早与最晚有效时间，需要时明确允许打断。每日／每周习惯只能显式建立，独立停止，使用 IANA 时区。错过窗口跳过过期实例，不批量追赶。

点击「启用浏览器通知」授权，保持标签常驻。后台标签可以工作，电脑休眠、页面冻结、系统专注模式可能影响触达。离线或权限被拒时未尝试，回来仅站内历史；尝试结果不明保留 unknown，不盲目重发。

构造／show／click 都不等于阅读。用「喜欢／打扰／没看到」明确反馈；没看到不进入喜欢分母。首周只评价在电脑前的场景，离机触达留到后续 App／Push。

默认静默为当地 23:00–08:00。自发关心有每日限额和间隔；专注、免打扰、关闭关心、源失效、过期会阻止投递。沉默不会触发追问或关系扣分。

## 模型、预算和安全

Run 保存模型配置、SDK／Prompt／人格版本与配置 hash，记录提供方返回的身份。可观测身份变化会暂停新的自发关心并提示复核，普通对话和明确约定仍可用。先运行 canary 并人工复核，再点恢复。同别名内部更新可能不可观测，此机制不能完整检测静默漂移。

每天 Token 预算可调。准入保守预留，结束用真实 usage 校正，失败且未知时保留预留。费用缺账单口径，显示未知。每 Run 最多 6 次模型调用、8 次工具、60 秒；只有未输出且无工具副作用的暂时错误可重试一次，遵守 Retry-After，超出截止时间不抢跑。

安全策略高于人格，明确即时危机走认真支持路线、保留熟悉语气、禁用普通工具，不自动联系第三方或编造地区号码。当前危机识别含有限中文规则，仍可能漏判；语气和真实风险识别需要人工评价。

## 备份、导出和恢复

页面「创建一致性备份」，或：

```sh
npm run backup
```

当前数据目录 `backups/` 内有 SQLite 快照、manifest 和当时存在的删除清单。导出另存私有 JSON，只通过受保护 API 下载；遗忘后本地旧导出撤销，已下载副本自行处理。

先停止原实例，把下方「备份ID」换成返回的 UUID，目标必须新建或为空：

```sh
npm run backup -- --restore 备份ID --to /Users/kuanyu/Projects/aic_project-restored
HARNESS_DATA_DIR=/Users/kuanyu/Projects/aic_project-restored npm start
```

命令从当前数据目录找备份，合并备份清单和当前最新 `deletions.json` 后才打开恢复库。保留最新清单；只有旧备份的另一台电脑无法知道后来删除了什么。不要拷贝活跃 SQLite 主文件，不覆盖原目录恢复。确认历史、检索、人格和 unknown 状态后再考虑切换，保留原件。

另一台机器首次跑网页测试需 `npx playwright install chromium`。合成测试使用独立数据，不写个人关系；报告在 `data/reports/`、`test-results/`。Playwright 的临时目录可在测试停止后清理。

盲比先看 `blind-*.json`，隔天评价自然度、人格连续性、记忆接续、危机语气，再看对应 mapping 揭盲。自动筛查只查非空、协议和少量显式操控措辞。CLI 评估用量在独立报告，不计入 daemon 日预算，运行前自行控制次数。

新增失败案例写入 `tests/`，通过 ScriptedModel、虚拟时钟和故障端口重放同一生产 Harness。没有一键把私人聊天无损转换为 Fixture 的录制器，复制案例前先脱敏。

## 排障和边界

- 无回复：查看状态；凭据、余额、限流和预算有独立错误码，不打印原始请求头。
- 实例或端口占用：打开现有页面，或停止属于本项目的旧实例；并行实例分目录、分端口。
- 换 Node 后 SQLite 原生模块错误：在选定 Node 下重新 `npm ci` 并构建。
- 通知没弹：查权限、连接、静默／专注和系统设置；不可观测的压制保留 unknown。
- daemon 重启后页面自动重取会话和快照，不重生成输入；遗忘后旧 cursor 强制同步并清旧视图。

不要把本服务通过端口转发开放给他人。公网账号、隔离、条款、年龄／地区策略按[W1 路线](../engineering/web-and-scaling-roadmap.md)另行验收。

## Fish Audio 语音朗读（2026-10-23 增量）

当前使用「甜妹」，音色 ID `5b50d7ae59f24c0cb447599df8ae34ab`，官方接口核对作者为 `shi9444woyi334390`，状态 trained。用户试听后选择 C 组：合成模型显式使用 `s2.1-pro`，原始语气、不自动添加温柔指令。采样参数固定 temperature 0.7、top_p 0.7；音色与模型仍是独立配置项。

后台 `env.local` 使用 `FISH_AUDIO_API_KEY`、`FISH_AUDIO_BASE_URL`、`FISH_AUDIO_MODEL`、`FISH_AUDIO_VOICE_ID`，临时凭据已保存且不发送到浏览器。修改后需重新构建／启动进程加载。官方协议见 [TTS API](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech)，音色见 [甜妹](https://fish.audio/app/m/5b50d7ae59f24c0cb447599df8ae34ab/)。

- 顶部「试听音色」播放固定的合成示例。
- 完整回复旁「朗读」、站内关心消息的「朗读关心消息」按需生成语音。
- 「自动朗读新回复」默认开启，可手动关闭；刷新后恢复默认开启，不补播历史，只处理本页初始化后、最近两分钟内最新一轮的回复。
- 「停止朗读」、发送新一轮消息、遗忘、关闭页面会停止播放并释放音频；在本地停止网络请求不能保证提供方完全停止计费。
- 浏览器可能禁止无手势自动播放，遇到时播放器会保留音频并提示手动播放，自动开关保持开启；这次合成不重复请求。

这是 TTS：完整文字回复生成后，一次 HTTP POST 请求 Fish Audio；后台逐块转发 MP3，支持 MP3 MediaSource 的浏览器通过 SourceBuffer 边接收边播放，不等待整段下载。请求使用 `latency: balanced`、`chunk_length: 100`。不支持该格式的浏览器自动降级为同一次请求的完整 MP3 播放，界面会提示兼容模式，不额外收费重试。没有启用麦克风录音、语音识别或文字 Token 分句合成。每次最多 4000 字、45 秒合成截止和 10 MiB 音频，后台单并发，不自动重试收费请求。失败不会影响原聊天。语音费用单独由 Fish Audio 计费，当前记录字符数、字节数、分块数、首块和整体耗时，金额未知，不计入 DeepSeek Token 预算。

只有被选择朗读的正文会发送给 Fish Audio，不把整份上下文、记忆和密钥一起发送。该提供方的远端数据保留／删除政策没有在本轮取得额外保证；本地遗忘不能撤回已经外发的文本。运行时音频只在内存和临时 Blob 中存在，不纳入数据库、导出或备份；可见在线页面会同步清理旧声音。浏览器和操作系统的内部副本仍不保证物理擦除。

`npm run smoke:speech` 会收费调用一次固定合成试听，并特意将测试音频保存到 `data/reports/voice-preview.mp3`、结果到 `speech-smoke.json`，方便核对。这是诊断样本保留的例外，不包含个人对话。普通朗读不写音频文件。

## 代码审查后的行为补充

- 关闭「整理记忆建议」会停止在途及未完成的提取；日摘要是独立任务。撤回远程模型许可会停止活动与排队的远程运行，并暂停后续外发，重新确认后再准入。
- 已取消／已解决／已过期跟进不能原地确认复活，需显式建立新事项。多个跟进存在时，模糊的「做完了」不会授权模型结束另一个不明确的目标。
- 明确约定与自发关心预算分开；普通取消发生在投递开始后，迟到的真实点击仍可被记录，重复回执不会反复修改状态。遗忘仍会使旧正文与尝试失效。
- 运行时仅保留最近 20 份完整调试上下文，较早 Run 保留持久元数据；客户端过期身份会回收。
- `npm run backup` 在线时通过 daemon 创建一致性快照，离线时持有实例锁。恢复要求停止原实例，并在临时目录验证／应用删除清单后才交付目标目录，失败不发布半成品。
- Canary 读取网页当前选择的模型及发布人格，评估读取配置不再对活库运行启动修复。
