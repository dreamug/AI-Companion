## 行为及边界

普通聊天先读取已有合格记忆，开始生成，同时后台解析当前输入。普通分享只有 `intent=none` 且动作全为 `add` 才允许后台提交；更正、删除、称呼及交互控制不得由后台直接提交。明确关键指令等待事务完成，再生成并检查答复。

每个来源修订只启动一次准入解析。轻量路由只作提示，独立操作检查还必须根据用户原话返回 `requiredAction` 和连续证据。发现漏分流时，丢弃未发布草稿，加入同一次解析，提交后重新组装上下文、生成并重跑两项检查；最多升级一次。助手自己在草稿中说“以后记住”不会成为保存授权。真实回执为 partial/quarantined/noop 时不能反复办理，也不能说全部成功。

同一关系按来源顺序解析，后来的更正会看到前序已提交记录。普通新增不会因全局 memoryVersion 改变而重复生成；已选记录及关键槽位仍验证资格。取消、遗忘、人格更换、关闭自动形成和交流上下文消融会阻止相应迟到写入；关闭 Harness 会先中止并等待准入任务退出，再关闭存储。正常回复完成不取消普通后台保存，晚到用量会补回原 Run，model_usage 台账仍是费用依据。

沿用 inbox/mutation，没有新增 Agent 或存储系统。账户内并发最多 4 个请求，其中后台最多 1 个，前台优先；账户身份只在内存中使用不可逆指纹。关系内待处理任务、账户等待队列各最多 16。来源截止仍为 30 秒，提供方解析最长 25 秒，不重试后台解析。

未处理来源最多覆盖 8 条，单条最多 512 UTF-16 单位、标识是否节选；总共最多 1000 估算 token，与近期原文共享 4000 配额。它们是近期用户原话，不能作为已保存事实或成功回执。消融后的历史、摘要及这些旁路均排除旧内容。未引入新的全库原文扫描或无限等待。
