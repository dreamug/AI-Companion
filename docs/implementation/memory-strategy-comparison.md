# 全量、关键词与 E5 混合：隔离副本实测

2026-10-25，真实 `deepseek-flash`，同一份事实库，30 个冻结问题 × 3 种策略，共 90 次批量回答；另外在浏览器执行预先固定的 3 个问题 × 3 策略，共 9 次现场回答。所有结果保留，包括失败、超时降级和评审拒绝。没有修改产品 `src/`、正式数据库或正式向量开关。

实验页：<http://127.0.0.1:4324/>。原有 4317、4321、4323 服务均未重启或修改；只在 E5 实验副本启用本地向量。

## 结论

本次数据支持“预算内全量读取，超预算后使用 E5＋关键词混合”的既定方向。关键词确实会漏掉自然改述和多项问题中的部分依据；E5 在批量测试中补齐了这些依据，但没有解决模型读对资料后仍答错的问题，也出现了一次现场超时降级。

不能把这轮说成“E5 已经百分之百可靠”：样本有限、同作者合成、全量组使用更多上下文，还有回答错误、评审误拦截风险和待复核措辞。正式启用前仍有明确的问题需要处理。

## 数据与冻结规则

从原 4323 演示库只读备份出 master，再复制成三个独立 SQLite。原有 20 条聊天、3 条记忆（含 2 条确认事实）、来源和摘要在各副本继续保留。新增 30 条有效的合成确认事实，形成 32 条合格事实：其中 16 条是问题目标，16 条为相似活动、姓名、家庭成员或同事的干扰项。

另加入 5 条资格控制：待确认年龄、失效来源地址、过期租金、角色扮演能力和另一 owner/relationship 的近似事实。这些记录不会作为现实查询的有效答案。测试用的新增记录通过正常 `Harness.addMemory` 和来源校验进入副本，未写入原库。

事实、30 个问题、所需依据 ID、已知/未知属性要求和浏览器演示题号在首次检索前冻结，见 `tests/fixtures/memory-strategy-comparison-v1.json`、`test-results/memory-strategy-comparison-v1/frozen-plan.json` 和 `freeze.json`。两条既有事实及其近似问法属于历史回归，其余是本次新增的合成主题；整组不称为独立盲测集。

30 题包括自然改述、复合问题、主体干扰、时间、否定和真正无答案属性。24 题需要至少一条已知依据，其中 2 题还要求回答未知部分；6 题完全没有有效答案。一次提交就是一次样本，不人为重抽；产品原有的有限发布校验/重写仍正常运行，其全部调用计入记录与延迟。

问题 q07 在冻结时标成 literal，但“通勤”相对“骑车上班”实际也是改述。因此不依据这个标签发布“精确关键词命中率”；未事后改题或改标签改善分类成绩。

## 三组真正执行了什么

| 组别 | 实际执行 | 记忆预算 |
| --- | --- | --- |
| 全量参考 | 现有 `readFacts` 的 forceAll，沿用资格过滤，交付全部 32 条 | 上限 12000，实际约 4071 token |
| 纯关键词 | 现有 `readFacts` / Store 关键词检索及已有查询词规则，无向量、无远程改写 | 2000 token，最多 5 条 |
| E5 混合 | 正常 `MemoryRetrieval.facts`，真实本地编码、SQLite 索引、扫描和现有融合逻辑 | 2000 token，最多 5 条 |

E5 使用已固定的 `multilingual-e5-small@614241f622f53c4eeff9890bdc4f31cfecc418b3`，384 维。实际离线权重编码并完成 32 条索引，没有替身向量或根据预期答案选候选。权重、查询扩展、融合权重、候选数量、超时和系统提示均未按本轮结果调参。

全量组是较大上下文的参考上限，**不是等成本基线**。同样 2000 token 放不下这些事实，所以不能拿它的结果宣称正常预算下无需检索。三组总请求预算均为 24000；实际发送证明全量组始终交付全部 32 条，没有静默裁成部分全量。

三组人格与初次生成的系统提示 hash 完全相同，真实请求均固定为同一模型、low 推理和 1500 输出 token。没有附加贴题提示、JSON 答题模板、答案标签或预期结果。

旧聊天与摘要保留在数据库中，但不交付模型；还排除日摘要、跟进、边界文字和工具补查。因此测的是“自动取回的一批长期事实＋同一阅读器”，不代表允许多轮工具补查时的全部 Agent 能力。实际 Provider 请求只有状态/事实及当前问题；只有产品既有重写发生时，多一条未发布草稿数据。校验器也只看到本轮已交付事实。

## 批量结果：取回依据与回答分别统计

“完整召回”要求一题所需的**全部依据**都进入实际请求，复合题只命中一项不算成功。6 道无答案问题不进入召回率分母。“回答任务正确”要求答全所问已知部分、对所问未知部分保留未知，并核对主体、时间和否定；未发布空回答不算正确弃答。

回答原文由本助手逐条按冻结要求复核，记录每个答案 hash、判断依据及风险，见 `answer-audit.json`。这不是独立人工或双盲评分，不用字符串包含答案替代语义检查。

| 指标 | 全量 | 关键词 | E5 混合 |
| --- | ---: | ---: | ---: |
| 有依据题完整召回 | 24/24 | 17/24 | 24/24 |
| 回答任务正确 | 29/30 | 21/30 | 29/30 |
| 纯未知题正确弃答 | 6/6 | 5/6 | 6/6 |
| 范围措辞待复核 | 2 | 0 | 0 |
| 严格通过／待复核／失败 | 27／2／1 | 21／0／9 | 29／0／1 |
| 回合正常完成 | 30/30 | 28/30 | 30/30 |
| 不合格或跨 scope 事实交付 | 0 | 0 | 0 |

以上“回答任务正确”不等于整段产品语言全部合格。全量组另外两条范围表述待复核，已从严格通过中排除；保存建议、未来记忆承诺和整体陪伴风格未做完整专项验收，不能借此宣称都已解决。

## 保留的真实错误与边界

1. **三组共有的 q18 回答错误。** 三组均读到“下午两点之后只选不含咖啡因”，却建议“低因或无因”，放宽了已知限制。全量与关键词还误把实际凌晨时间当成下午。当前状态同时给出 UTC 时间和 `Asia/Shanghai`，模型没有正确处理。三条均记为回答失败，不能靠命中偏好原句就放行，也不能归因于漏召回。
2. **关键词 q12 发布失败。** 花卉记录没有取回，草稿又说“只记着一条”之类未充分限定范围的表述，校验两次拒绝，最终没有回复。漏召回明确，生成措辞与评审边界仍应分开复核。
3. **关键词 q24 发布失败，疑似评审误拦截。** 年龄本来未知，首次草稿的“没记到”有范围风险；重写稿已说“这一轮的依据不足，我没法确定”，仍被拒绝。这是评审可靠性问题的证据，不能把空回答记成安全弃答。初稿、重写、两次裁决完整保留，没有改校验器或重新生成来替换失败。
4. **全量组 q05、q26 范围措辞待复核。** 所问安排/未知姓名处理正确，但又说“暂时没有别的记录”“记忆里只记着……没有关于教练名字的记录”，没有明确限定本轮合格记录范围。没有以全量读取为理由自动放行，也没有冒充已经确认的错误结论；两条保留 review，不计严格通过。

## 性能：局部检索与整轮回复分开

| 指标 | 全量 | 关键词 | E5 混合 |
| --- | ---: | ---: | ---: |
| 独立顺序检索 P95 | 6.12 ms | 5.11 ms | 32.18 ms |
| 并行三组时前台读取 P95 | 91.79 ms | 55.41 ms | 117.37 ms |
| 平均交付记忆估算 token | 4071 | 181 | 673 |
| 每题平均模型调用，含校验/重写 | 1 | 2.47 | 2.13 |
| 整轮回复 P95 | 1.58 s | 8.31 s | 6.07 s |

全量组完整读取通常不触发范围语义校验；另外两组为部分结果，会运行原有发布校验，部分还会重写。因此整轮时间差不能全算在检索或向量编码上。前台数据包含同进程三组并行的调度/上下文构建影响，不等于单独编码速度。30 次是小样本，不是性能 SLA。

本次冷模型启动约 9.63 秒，之后才开始正式采样；实验没有把它藏在首条普通问题里。批量 30 个 E5 请求全部走 hybrid，现场演示另发生一次约 221 ms 的 `embedding_timeout`，真实退回关键词。

## 浏览器演示：没有替换失败

演示题号 q02、q15、q23 在首次检索前固定，三个问题均通过浏览器提交，同一请求交给三组。

- **自然改述 q02：** 全量答对、关键词无命中；E5 现场超时降级，也没有答出名称。保留 `01-paraphrase-live-timeout.png`，没有重试到成功。批量同题 E5 是成功的，二者分别记录，不合并成单个最好结果。
- **复合问题 q15：** 全量和 E5 都答出自己的名称与姐姐店名；关键词只答出自己的名称。见 `02-compound-live.png`。
- **未知地址 q23：** 三组都说明没有有效地址依据，没有使用被标为来源失效的地址。见 `03-unknown-live.png`。

现场 E5 模型和索引均已就绪，不能把这次超时解释成尚未装模型或没有建索引。具体尾延迟原因尚未定位；同进程并行构建上下文是待验证因素。实验中没有延长截止或改策略把它掩盖。

## 实施与保护

新增实验脚本 `scripts/memory-strategy-lab.ts`、纯策略/交付证明辅助模块及实验网页，没有改产品代码。新增 5 项测试覆盖完整召回定义、未知题分母、真正全量与关键词上限、E5 原生路径委托、发送层隔离与输入不变；类型检查、构建与这 5 项测试通过。本轮没有重复宣称整套既有 614 项全部重跑。

6 个正式数据库、原 4321 与原 4323 共 8 个库的业务表哈希在实验前后完全相同，`env.local` 哈希不变。正式库 schema 均为 v1，正式 PID 65891、试聊 PID 98052、原演示 PID 99742 均未重启。原试聊与演示的向量开关仍关闭。各克隆中原有聊天、来源、记忆和摘要逐行核对保留，见 `protection-after.json`。

事实与查询标签只用于运行后的评估，不进入编码器查询、候选排序或阅读请求。批量与浏览器共 99 次初次生成系统提示 hash 一致；实际交付记录中未出现待确认、过期、失效来源、角色扮演或跨 owner 控制项。全部 Provider 请求、草稿、校验和最终输出保存在 `wire/` 与 `answers.json`。
