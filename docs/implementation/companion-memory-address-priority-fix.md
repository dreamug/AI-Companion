# 4331 临时称呼优先级与评审一致性修复

日期：2026-10-26。有效临时称呼优先级误拦截已修复并更新到 4331。两项独立检查及发布屏障保留，未放宽判定和结构化输出校验。

## 原因与修改

原先主生成能读到关键档案槽位，评审投影却把它们混入普通 `existingFacts`，丢失清楚的称呼层级与适用范围。评审因此可能按跨槽位时间排序，把长期称呼置于仍有效的临时称呼之前。

新增纯函数 `resolveAddress`：在已有关系、现实范围、来源、时间和交流段资格过滤之后，按禁止叫法过滤，再依次选 `address_override`、`preferred_address`、`self_reported_name`。同一槽位仍由已有指针决定当前修订，跨槽位不按数组顺序或时间重新排序。禁止值做 NFKC 和首尾空白归一化后精确比较，不用子串判断。

主生成和事实评审都读取程序生成的 `addressResolution`；`criticalProfile` 单独保留来源、作用域和有效期，不再当成普通事实列表。普通检索不可用不抹掉仍合格的关键档案。历史引用旧称呼与实际用旧称呼叫用户分别判断，不要求每句加昵称。

称呼和姓名更正必须走槽位命令；普通 `replace` 不能绕过槽位指针更新。更正长期值不撤销仍有效的临时覆盖，更正临时值保留原先的今天或交流段范围。补上未来 `validFrom` 的资格排除。

事实检查负责称呼选择、优先级和禁用冲突；操作检查负责真实操作回执与保存承诺。当前合格档案证明已有状态，但不能证明本轮刚保存。`noop` 也不能否定已有状态。错误称呼由事实检查照常拦截；检查输出非法代码仍失败，不映射、不吞掉。

涉及源码：`src/memory/address.ts`、`src/memory/companion-v3.ts`、`src/context.ts`、`src/memory/read-scope.ts`、`src/memory/reply-contract.ts`。没有昵称字面分支、题号条件或为测试改动的提取正则。
