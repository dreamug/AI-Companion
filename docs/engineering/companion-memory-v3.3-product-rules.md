# 陪伴机器人记忆产品规则

版本：3.3 设计稿。项目：companion-harness。

本文件决定用户应感受到的行为、信息如何接纳与使用、温度层的边界和陪伴评价。执行、事务、预算和测试见[工程合同](companion-memory-v3-engineering-contract.md)；第一次可试聊的范围见[CM3 2 最小试聊清单](companion-memory-v3-cm3-2-checklist.md)。设计待实施，本轮仅文档。

## 1 用户体验与目标

用户正常分享生活，bot自然回应并逐渐了解用户，不让用户逐条维护候选。目标同时包括事实可靠、交流连续、被理解以及不被打扰；温柔措辞不能抵消错误记忆，数据库正确也不能代替陪伴体验。

以下是行为示意，不是生产提示词里的主题特例或固定答案：

1. 用户介绍希望被叫的名字，当轮采用，实际提交后清掉模型近期上下文仍可正确称呼。明确保存失败就如实说明；不先说保存成功再补写。
2. 用户昨晚说与朋友争执后难过，第二天问候时，已接纳的事件仍可支持克制接续，不认定今天仍难过。若涉及受限私人内容，则先满足第4节授权与用途，不承诺所有私人事件默认次日主动提起。
3. 用户在不同日子讲过睡得晚，相关聊天里可以有依据地询问近况，不凭凌晨上线推断失眠，不写成“夜猫子”。证据不足时不观察。
4. bot记得实际说过的约定、双方采用的晚安方式，不把未展示草稿当共同经历，不把口头承诺当已执行。
5. 用户不想再提就停止主动使用；要求忘记则完成实际遗忘。问“怎么知道的”能解释来源；检查故障有简短、符合角色语气的真实回应，不要求用户重复已经收到的输入。

不追求提旧事的次数、聊天时长或亲密度分数。跨bot默认不共享档案，现实与角色扮演分开；新的隐私用途不能由角色口吻授予。

## 2 记忆分层与称呼

| 层次          | 内容                                                    | 使用方式                                                     |
| ------------- | ------------------------------------------------------- | ------------------------------------------------------------ |
| 核心          | 当前称呼、禁用称呼、明确交互边界，少量普通稳定背景      | 正常模型请求固定带关键槽位，软概览有界；受限私人事件不入核心 |
| 近期          | 近期原文、摘要、pending来源、持续事项、有时效的交流背景 | 当前问题优先，七天摘要候选不是删除线                         |
| 归档          | 普通事实、历史事件、过往决定及已接纳私人事件            | 结构化、关键词与合格的本地E5召回，不全量塞上下文             |
| bot与共同经历 | 已展示自述、口头约定、共同仪式                          | 独立来源类别，不进入用户画像，不覆盖已发布人格               |

称呼按当前明确要求和禁用约束、有效临时覆盖、长期偏好、自报姓名、人格默认称呼依次解析。昵称不等于法定姓名；“他叫某某”不更新用户槽位；角色世界的称呼不污染现实。今天的临时叫法到用户当地下一午夜恢复，“这段聊天”的叫法按第6节结束，页面刷新不结束交流段。

单值偏好变化、纠错与多值追加分开；当前用户纠正优先于旧资料和后台任务完成顺序。bot猜测、赞美、摘要和向量不能成为用户事实的权威来源。关键字段保护不表示模型永不犯错或保证每次旧事都召回。

## 3 自动形成与真实表达

### 3.1 用户设置

沿用每关系的`memoryFormationMode`：automatic自动接纳合格普通信息；explicit_only只按明确要求形成一般记忆；off暂停新增一般记忆。旧autoExtract=false映射为explicit_only，不因升级重新开启。关闭形成不等于删除或关闭读取；称呼、停止类交互控制和遗忘仍可显式办理。

受限私人事件另用现有拟定`sensitiveMemoryMode`：默认explicit_only，可明确设置related_events。一般automatic不暗含私人自动许可。只有用户明确选择后，related_events才允许automatic下的合格最小事件后台形成；不扩大到病历、药量、金额等细节。off下不以征询绕过暂停；用户若要更改设置，必须明确办理并真实提交。

### 3.2 准入规则

| 原子内容                     | 处理                                                   | 对话行为                         |
| ---------------------------- | ------------------------------------------------------ | -------------------------------- |
| 明确普通稳定偏好、习惯       | 后台自动提交用户陈述                                   | 自然回应，不播报内部流程         |
| 称呼、禁用称呼、明确交流要求 | 受保护槽位与实际事务                                   | 同轮遵守，实际成功后才确认       |
| 今天的状态或经历             | 有依据的临时状态；有价值的历史证据可为短期reported事件 | 不固化成长久特征，见第7节        |
| 明确保存、更正、遗忘         | 关键路径实际提交或如实失败                             | 不再次征求同一意愿               |
| 提问、假设、引用、办理意愿   | 不生成对应现实事实                                     | 理解语境，不保存“用户想保存”     |
| 助手推测                     | 不进确定用户事实                                       | 第7节允许有限临时观察            |
| 主体或目标有歧义             | 暂缓有歧义的变更                                       | 为理解内容澄清，不机械问是否保存 |
| 明确不长期保存               | 屏蔽相应形成及长期派生                                 | 不能从摘要或原话重提取绕回       |
| 受限私人事件及细节           | 第4节按内容和用途处理                                  | 不一刀切忘掉，也不自行扩权       |
| 秘密和凭证                   | 禁止记忆、概览、MD与向量                               | 不回显秘密，不说已经记住         |

混合消息按证据区间拆开；不得因为一处拒绝就全丢，或因为一处允许就全收。原聊天保留、模型读取、长期形成是不同操作，“没有长期保存”不意味着原文没有保留。

### 3.3 保存措辞

只有实际提交回执支持已保存、已替换或已删除。queued、原话落盘、提取完成、索引ready均不代表事务成功。临时、partial、失败、noop按实际范围表达；不承诺永远记住或跨窗口必然召回。普通分享无需主动宣布存储流程。

## 4 受限私人事件的授权与使用

### 4.1 分类边界

“受限私人事件”指需要额外控制的私人内容，不专指恋爱关系。用版本化的有限类别表按原子内容分类；普通生活事件仍是私人资料，也受作用域和遗忘保护。情绪强烈不独自构成受限理由，清单外的未知内容也不自动放行。

| 分类                 | 本版范围与边界                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 普通最小生活事件     | 本人明确讲述分手、失业、争执、考试等基本变化与当时感受；不因事件名自动变成受限档案                                     |
| 受限私人事件         | 健康诊断/治疗与照护背景、财务困境、法律纠纷、性与亲密细节、非公开身份/联系方式/精确位置、第三人的非公开私人细节        |
| 不自动接纳的精细资料 | 具体药名剂量、详细病历、精确债务/账户金额、案件材料、精确住址/联系方式等；显式请求只按允许字段，不因事件获许可全部接纳 |
| 禁存                 | 密码、访问Token、私钥、身份证件号码和支付认证凭证等可用于认证/冒用的秘密；明确要求也不能入记忆                         |
| 无法判断的原子部分   | 单独暂缓，不扩大为整条普通事件都受限，也不默认ordinary；按必要性自然澄清                                               |

用于标注的边界对照：

- “我分手了，昨晚有点难过”：普通最小事件与有时间的感受；对方性经历、可暴露非公开身份的细节另拆为受限，不从一句话推断性取向或依赖程度。
- “我被裁员了”：普通就业变化；“我欠款多少、账户剩多少”是受限内容；不能从失业推断财务困境。
- “我和朋友吵架了”：普通本人经历；第三人的诊断、住址或私密经历仍受限；与第三人有关不等于所有提及都受限。
- “妈妈正在接受治疗，我担心”：受限照护事件；抽象成“家人治疗”仍是受限资料，不用概括规避准入。

这些是成对语义测试，不是生产代码中的关键词分支。用户、第三人、虚构人物分别识别；诊断/法律描述仅表示用户陈述，不表示现实已核实。

### 4.2 当前事件授权与一次自然征询

默认explicit_only并不要求用户只去设置页操作。用户主动说“记住这件事”可按现有明确保存路径提交该事件，不必再问。

没有明确保存请求时，可在合适对话时机自然征询一次：先回应用户正在表达的需要，不把征询作为安慰的条件，也不强迫当轮问。问题只指当前可描述的最小事件，例如说明“以后你提到时能接上”；此句本身不是已经保存的声明。

| 用户回应或情形                   | 实际含义与处理                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------ |
| 明确同意当前事件                 | 仅按明确保存路径提交该事件及已说明的用途，取得回执；不更改关系级related_events |
| 说“可以”但对应目标不清           | 只在紧邻已展示征询、目标唯一且未换题时解析为同意；否则不写，必要时澄清         |
| 拒绝                             | 复用交互偏好记录不再主动征询；当前事件不形成长期派生，不保留额外候选正文       |
| 跳过、换题或无回应               | 不当同意，不重复主动追问；未来用户自己明确保存仍可办理                         |
| 主动选择以后自动记住合格私人事件 | 单独明确更改关系级设置；不能从同意当前事件推导此意愿                           |

自然征询每关系最多实际展示一次，使用现有displayed消息元数据与交互偏好查重，不建许可状态机或新权限服务。候选未展示不消耗机会；partial展示若可能已表达征询，保守记为已问，断线重连不重复。用户明确拒绝即使未曾征询也优先。未开放该能力的早期试聊不征询；已有适用许可、一般off或明确不保存时不征询。

未同意前只使用允许的当前原话，不建立敏感长期事件、跨段事项、持久征询候选或衍生向量；已保留原聊天不是许可。拒绝标记只保存控制含义与必要来源，不复制事件正文。用户可主动更改决定，不能用一次拒绝阻止其未来显式指令。

许可范围落在现有明确命令的对象、交互偏好与实际回执，不另建授权数据库。保存最小事件可包含已明确归属该事件的后续状态，不能扩成同一人的其他私人事件；新事件仍需自身许可。必要范围不明时不自动覆盖。

### 4.3 保存 相关使用与主动关心分别决定

已合法保存的事件允许在相关交流里回忆；这不等于允许开场点名。默认`proactiveUse=never`，不入核心、核心MD或一般all注入，不因事件标题或同源事项绕过。

用户明确说“可以时不时问问这件事”，通过现有interaction_preferences绑定具体事项/事件，将该对象proactiveUse设为eligible，并保留授权来源。只授予实际描述的范围；原事件若未保存，按同一请求表达的必要范围提交，未提到的细节不纳入。该指令不是关系级related_events授权。

eligible仍遵守第5节频率与场景选择，不保证一定问，不建立提醒/通知，不扩成所有私人事件可主动提起。撤回、“别再提”或忘记时即刻停止对应用途；忘记另做完整闭包。用户当前问到该事属于响应当前意图，不是主动关心。

### 4.4 间接召回不等于因果判断

对已经接纳、许可仍有效的最小事件，允许在隔离实例复用本地E5做受限相关检索，不再一律仅FTS。限权适用于关键词、向量、delta、缓存、摘要和来源展开，不能因为Embedding本地运行就忽略隐私。

| 本轮意图与证据                        | 可用方式                                                                     |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| 明确回问、点名或能唯一定位的间接回指  | 召回最小必要内容，按时间和主体回答；不因没重复实体名而拒绝检索               |
| 泛化的压力/睡眠表达，存在若干可能背景 | 旧事只作为待判断的候选；可以中性询问近况，不能点名暴露受限旧事或直接断言原因 |
| 多个事件都合理                        | 自然澄清，不按最高相似度替用户选择真实原因                                   |
| 仅问候或不相关聊天                    | 默认不读取作开场素材；有具体主动关心许可才按第5节选择                        |
| 当前不想再提、撤销许可或遗忘          | 按对应用途阻断；检索命中不能覆盖新明确边界                                   |

“用户压力大”与“家人治疗”相似不证明因果，更不证明病情改变。候选命中、模型实际读取、恰当使用、越界披露分别统计；未明确提旧事也可能是正确行为。相关召回不能靠偷偷把受限事件常驻所有请求实现。

本地编码只处理已允许的最小事件文本，不编码整段病历或原聊天。向量与相关缓存仍是私人资料；命中后进入既有授权回复模型/评审的内容也可能传输给该提供方，不能宣称整个链路完全本地或无第三方。禁止新外部Embedding、评审或记忆服务。索引不就绪时按既有截止降级，不伪称库里没有。

关闭形成只影响后续新增，不冒充删除；关闭读取、撤回用途与删除按现有操作分别解释。未来正式启用前完成间接提及、误关联、无答案和遗忘验收；本轮不改任何开关。

## 5 主动接续与冷却

交流段开始时，从合格未结束事项、结果尚未知的计划及近期重要事件提供最多一个可选线索；当前话题优先。重要性由用户表达、明确影响和未解决结果支撑，不按主题写特例。没有合适候选就不提供；主生成可询问、只调整语气或不用，不新增关心模型。

排除删除/屏蔽、跨主体/world、未获准主动使用的私人事件、明确不再提及、取消/已解决无进展、冷却中的项。其余按当前相关、预计时间已到、用户明确重要、最近证据、稳定ID排序。开场供给不强制扫描归档。

初始上限每段1候选、每关系每用户当地日最多1次实际主动询问；刷新/重连/时区切换不重置已消耗限额。候选和实际问过分开，只在displayed后记录lastOfferedAt、来源seq与冷却。部分展示无法确认是否已问到时保守消耗；单纯调整语气不算主动问。

**实际问过即默认同事项7天冷却，不再判断“用户是否故意跳过”。** 下一轮已有intake只识别有来源的明确接续、进展或拒绝；它不为此单独调用模型。用户主动接续可正常响应、更新结果；新证据不自动清空冷却让bot立刻再追问。模糊回复、换题或未回复均保留冷却，不推断不满。明确“别提”形成持久主动使用限制。

“下周面试”日期经过只成awaiting_update，不推断完成/通过；用户没回应也不欠bot一个答复。已准入事件可跨天保留同源事项，但不续期当前情绪。重要事件的私人部分始终按第4节使用，事项不能成为绕行通道。

## 6 交流段与带时间的背景

### 6.1 交流段定义

复用当前`assignSegment`语义，见[工程合同第2.7节](companion-memory-v3-engineering-contract.md#27-交流段与准入元数据)：同一关系收到新输入时，若无open段则建立；若距lastUserAt严格超过30分钟，且除当前Run外无queued/running Run，则关闭旧段并建立新段。恰好30分钟仍属原段；有其他在途Run时不拆开。

lastUserAt以新输入受理时间更新，助手输出、后台维护、页面刷新和网络重连不延长。连续跨午夜聊天不单独换段；空闲后新输入才触发惰性切段。运行恢复保留原段ID；历史回填只补元数据，不重放回复或触发开场。用户日期用于日限额与“今天”的有效期，不能混成段边界。

30分钟的段空闲阈值与30分钟的缺省情绪窗口是两个规则，不能互相续期。下一次新段第一轮可做一次候选供给；不因恢复页面就新增开场。

### 6.2 背景有效期

| 背景                     | 适用期                                  | 到期含义                                 |
| ------------------------ | --------------------------------------- | ---------------------------------------- |
| 这轮/这段先听我说        | 对应Run/segment                         | 身份结束即失效                           |
| 今天先别给建议           | 表达时用户当地日期，至下一午夜，处理DST | 不按now加24小时，不因后台迟到延长        |
| 无明确期限的当前情绪表达 | 当前段结束与收到表达后30分钟中的较早者  | 不再当当前心情，合格历史事件可继续存在   |
| 相关事件背景             | 来源时间、事件与许可范围                | 事件仍在不表示情绪仍在；新表达覆盖旧状态 |
| 以后先听完再建议         | 用户明确长期交互偏好                    | 明确更改或撤回才更新                     |

区分收到表达的observedAt、实际发生的occurredAt与适用期。“上周难过”不能从现在重开当前情绪；实际时间不明不补造。“现在好多了”本轮先采用，对对应事件更新，不等夜间维护。人格稳定，语气随当前输入、明确边界、有效背景调整；不新增必经情绪模型，不猜未提供的音色情绪、摄像头或位置。

## 7 观察所需的历史证据

复用现有`Memory.kind=episode`、`episodeType=reported`，不新建观察库或原始聊天扫描器。ordinary自动提取可把明确、可复述且对近况连续性有价值的当天经历写成轻量事件，带用户原始证据、主体、发生日期/时区与发生时间；同源去重。不把所有“今天喝了水”逐句存档，也不靠特定主题词决定价值。

例如“今天睡得很晚”可同时支持当轮状态和有日期的历史事件。状态到期不删除仍在保留期内的事件；历史查询不把“那天晚睡”当“现在晚睡”。默认这类轻量记录保留14个当地日期，锚定发生日期，不因重述或维护续期；明确要求长期保留则按正常保存命令另行改变实际保留范围。超期不再作为观察依据，原聊天是否保留独立说明。

仅在当前话题相关时，对最近14个当地日期的合格事件做有界读取，至少2个不同发生日期、不同实际经历的独立用户陈述，才可考虑本轮观察。摘要、助手复述、同一事件隔天重讲不增支持数；日期不明不能充当“另一天”的证据。来源不足、抽取失败、只剩过期原话时不观察，不能伪装已有依据或强行补扫原聊天。

观察仅为本轮派生内容，可用不确定语气询问，不能写回确定事实、MD或向量。不凭上线时间、标点或回复速度推断作息/健康；不推导诊断、性格或亲密度。受限资料即便有两个日期也不能绕过第4节。用户否认后按原更正/交互边界停止该推断；忘记支撑来源后不得继续使用。

14天是证据窗口与默认轻量保留，不是所有记忆的统一删除线。事件到期只影响本类临时证据；明确长期保存、未结束事项与其他历史记忆按自己的生命周期处理。

## 8 bot与共同经历连续性

已发布人格是上限；实际自述用assistant_said/bot_continuity标来源，不能成为用户事实或现实履历。与既定人格矛盾时可解释纠正，不因曾说过就永久维持错误。只记录实际displayed的必要内容，不记未展示草稿或每个修辞。

口头约定进入既有持续事项，待接续、已交付、取消分别记录。“下次一起挑书”不证明已推荐，更不授权提醒或外发。文本交付以实际展示为证，现实执行以工具真实结果为证。后台登记失败须计连续性失败，不能重发承诺补票；“已保存约定”仍需发布前真实回执。

共同仪式需双方明确采用或用户后续实际使用；单方建议不算。里程碑只按实际首次交流与时区计算，不建立亲密度分数。共同经历、私人来源、角色扮演与遗忘规则同样受控，不能绕过第4节。

## 9 陪伴评价口径

每个位置在运行前标注should_use、may_use或should_not_use。应该使用可通过恰当调整建议/语气实现，不要求逐字提旧事；可以使用时不提也可成功；不应该使用时禁止越界或绕回。生产模型不读取评分标签。

| 指标           | 判定                                                               |
| -------------- | ------------------------------------------------------------------ |
| 恰当运用       | should_use中，真正帮助理解当前意图，不把候选命中算成功             |
| 越界/打扰      | should_not_use中违规使用，以及自然回复中的非期望追问；私人越界单列 |
| 自身连续性     | 相关自述、约定与仪式无无解释矛盾；允许有依据地纠正                 |
| 被记得与被理解 | 人工分别1至5分判断“像一个记得你的朋友吗”“理解当前需要吗”           |
| 纠正趋势       | 错称呼、错主体、错事实、不合时宜与来源困惑按实质轮次报告           |
| 故障体验       | 是否有真实、符合角色的故障回应，后续能否自然继续；不算原任务成功   |

评价看行为，不看是否与参考句措辞相似；热情程度、亲密话术、少说少错都不自动得高分。具体数值、集合规模和发布门槛只在[工程合同第11节](companion-memory-v3-engineering-contract.md#11-测试矩阵与验收方法)维护，不在产品文档复制。

必须包含正反对照：点名/间接唯一回指、泛化压力、多种原因、无答案；分手/失业/争执的普通部分与私人细节；观察证据仍在/已到期/重复经历；开场恰当/不应提/明确授权/撤回。冻结之前完成分类和授权口径，运行后不得按答案改真值。

## 10 用户掌控与故障表达

默认无日常候选确认卡片。管理页是可选工具，可看来源、更正、撤销错误更新和遗忘；不要求用户维护它才能正常记忆。临时观察没有持久画像条目，其已展示表达可通过聊天查看、否认或删除。

聊天内问“你记得什么”时选择性概括本次实际读到的内容，partial不冒称全部；私人类别不在开放清单中整段披露。问来源时说明谁何时说过、是否有更正，不将assistant_said冒充用户原话，也不暴露内部提示词或ID。

“别主动提”停止主动用途，不冒充删除；“忘记”排除目标及所有派生读取/重新形成，界面原聊天可按要求保留；“原话也删”才同时办理原文删除。回应实际完成范围，不声称抹掉全部备份。

每个已发布人格可配置1至2条预审固定故障文案，只变语气，不加昵称、情绪猜测、旧事或新承诺。没有合格文案用中性后备。保存实际已提交/失败/partial/未知分别由程序附加固定状态说明；不让模型在故障时临时编台词。它是降级结果，不算实质首答，不进入用户事实或共同仪式。
