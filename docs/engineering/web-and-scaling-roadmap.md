# 网页产品与十万级用户的演进路线

v0.3 · 2026-10-23 · 开工前勘误后冻结。认知状态：未来设计与容量验证计划，未部署；算例与数字不是实测结果。M0期间只登记[实现偏差](implementation-notes.md)，冲突按[权威规则](../../README.md#文档冻结与权威规则)处理。

## 1. 规模结论与限制

TypeScript＋Node.js可以作为十万级用户产品的Harness技术基础。容量按活跃量、到达率、模型耗时、连接、数据量与故障条件压测，总用户数不能直接决定单机容量。

Node.js 适合事件驱动的网络 I/O；每个请求的同步计算必须受控，长时间计算会阻塞同进程其他请求。[事件循环说明](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop) 多进程能分摊负载，但各进程的内存不天然共享；跨实例身份与运行状态必须由应用管理。[多进程说明](https://nodejs.org/api/cluster.html)

因此保留 TS，不原样放大个人版的单进程 SQLite。Python 也需要数据库、队列、流连接与模型配额的容量治理；更换语言不能替代这些工作。

## 2. 不同规模必须分别定义

| 说法 | 还需要的输入 | 验证重点 |
|---|---|---|
| 十万注册用户 | 活跃比例、保留周期、每人消息与记忆量 | 存储、索引、删除／导出、账号隔离 |
| 十万日活 | 每人回合数、日内峰值、平均模型调用数 | 高峰请求、后台整理、额度与费用 |
| 十万在线连接 | SSE／WebSocket数量、心跳、慢客户端比例 | 连接内存、文件描述符、代理超时、重连风暴 |
| 十万同时生成 | 单次请求耗时、Token率、每回合调用次数 | 模型侧并发与Token容量、排队、预算、降级 |

在线不等于正在生成；一个对话回合也不等于一次模型请求。记忆提取、关心判断、草稿和工具续步都要纳入模型负载。

## 3. 容量模型与示例

首先记录实测参数：DAU、每人日均回合数 t、高峰系数 p、每回合平均模型请求数 k、模型请求平均占用时间 s、后台模型请求率 b。

- 平均回合到达率：`DAU × t / 86400`。
- 高峰模型请求率：`平均回合到达率 × p × k + b`。
- 稳态平均在途模型请求数：`模型请求率 × 平均占用时间`；这是规划估算，不是尾延迟或突发负载的上界。
- Token 吞吐：分别估算每秒输入和输出 Token；缓存命中只有实际 usage 证明后才进入成本计算。
- 连接内存：实测单连接常驻与缓冲成本乘在线连接数，再加运行快照、进程基础开销及余量。

算例：十万DAU，每人每天10回合，平均约11.6回合／秒；高峰系数10、每回合两次模型调用、每次8秒，则前台约232次模型请求／秒、1856个在途请求，后台与故障余量另计。

每人 1000 条记忆乘十万人就是一亿条记录。检索必须先限定 owner／关系，再查询索引；单用户“1万条可精确扫描”的实验不能推出全站可扫描。原始消息、事件保留、附件、备份和副本另算。

## 4. 分阶段部署

| 阶段 | 部署与技术 | 触发及退出条件 |
|---|---|---|
| M0–M5 个人自用 | 本地daemon、SQLite、单消费者、Trace常驻页浏览器Notification | 真实相处与已启用硬合同通过；离线不弹，返回只看站内历史 |
| W1 网页产品小范围验证 | 同一 Harness 的托管部署；正式网页；服务端鉴权；PostgreSQL；私有附件存储；后台任务和首个网页投递适配 | M5门槛之后启动。对第二个真实账号开放前必须完成隔离、删除／导出和云端备份恢复 |
| W2 多实例与独立 Worker | 多 API／流实例，前台与后台计算解耦；持久队列；跨实例运行认领、租约、fencing与取消 | 部署第二个可执行实例前通过跨实例合同；队列重复投递不造成重复副作用 |
| W3 按真实负载扩容 | 独立扩容连接、模型调用与后台Worker；索引、缓存、读扩展或分区按测量增加 | 按目标工作负载压测、故障演练、模型额度和成本验证后放量 |

W1 不必先上 Kubernetes、微服务集群或多地域。W2 的队列可先由 PostgreSQL 持久任务实现；若实测证明吞吐、延迟或运维需要，再选专用队列／Redis。不能同时让两个系统各自决定同一 Job 的权威状态。

W1 的领域、API 与任务执行可暂在同一托管进程中，但必须是可持续工作的后台服务；不能把浏览器定时器或随请求消亡的临时函数当持久调度器。W2 再拆部署角色，不重写领域规则。

产品入口可先本地Web或Electron，再到App；托管多用户网页按W1启用。首周只评电脑前、常驻页可用时的通知；离机触达留到App／移动阶段。若标签常被关闭，可加极薄Electron托盘适配，不包含产品聊天UI。Web Push／Service Worker另验浏览器、设备与权限；用户拒绝通知后仍可读站内历史。[通知权限与持久通知说明](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)

## 5. 从第一版保留的迁移边界

### 5.1 数据与身份

所有私有记录携带 ownerUserId 和必要的 relationshipId；派生数据、缓存、Trace、向量、附件与导出都保留相同归属。共享角色模板不包含个人状态。

个人版可以固定一个 owner，但核心用例不可通过全局变量隐式寻找“当前用户”。关系内串行、不同关系并行；预算包括关系／账号层，并预留提供方共享配额。

### 5.2 存储与任务

领域通过明确 Repository 和事务用例访问存储，SQLite SQL 留在适配器。迁移到 PostgreSQL 时实现新适配器，不追求一套 SQL 自动兼容两库，也不预建通用 ORM 平台。

Job 持久身份、幂等与提交检查不依赖某个进程的定时器。M0 的轻量唤醒只负责提示检查数据库；W2 队列同样只负责调度，领域提交仍核查当前版本。

### 5.3 事件与连接

公开事件与诊断 Trace 分开，版本化、按授权 stream 续传。多实例之间可以用通知通道唤醒连接节点，最终从持久记录补齐；不能把易丢 Pub/Sub 当唯一消息历史。

网页 UI 不直接依赖 AI SDK 流协议。API、SSE、Run 和消息格式由我们的合同定义；前后端共享类型也不替代运行时校验。

## 6. W1 前必须补齐的多用户能力

1. 服务端身份验证、对象级授权与跨用户读／写拒绝；本地 token 不直接当公网登录系统。
2. 数据库、附件、检索、缓存、导出、诊断和任务携带一致 owner；索引候选使用前重新授权和水合。
3. 显式用户时区、通知授权、静默时段和设备能力；一个用户的偏好不改变其他用户。
4. 云端模型密钥由服务端密钥管理提供；开发用 env.local 不打包部署。后续替换临时凭据，不记录其值。
5. 私有内容访问、保留期限、删除、备份与恢复流程；托管后的数据位置和远端模型外发范围必须重新说明。
6. 每用户频率／费用限制与全站提供方预算；一个账号超额不能饿死其他账号。
7. 管理诊断权限独立，默认只收集必要指标；不把个人版可展开的完整上下文暴露给普通网页。
8. **目标地区合规审查：**启动前确定服务地区、主体、数据／模型地域和公开范围，核对适用的备案／登记、安全评估、内容标识、数据处理、外发及应急流程；不是“一律某种备案”的概括。中国大陆除[生成式AI服务规则](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)，还应审查2026年已发布的[拟人化互动服务规则](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)，其适用范围包括持续情感陪伴，可能直接影响联系人、干预和数据设计。海外按实际地区另查，由合规审查形成上线结论。
9. **年龄与未成年人策略：**先确定首发人群、年龄识别／申诉、未成年人可用服务、人格与亲密边界、时长／付费、监护和紧急支持要求；不能只加注册勾选框。上述拟人化互动规则对未成年人的虚拟亲密关系与模式有专门要求，不能将成人自用人格原样开放。两项本轮只登记，W1启动前明确方案、上线前验证。

PostgreSQL RLS 可作为纵深防护，不能替代应用授权。连接池中的租户上下文必须按事务设置与清理；表 owner、superuser 和 BYPASSRLS 的绕过行为必须验证。[官方行级安全说明](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 7. W2 前必须补齐的协调语义

单实例的启动 running → interrupted 规则不能照搬到共享数据库：新实例不能把仍由其他实例正常执行的 Run 标成中断。需验证 owner instance、租约与接管资格后，只恢复已失去有效所有者的任务。

跨实例认领按关系／任务使用原子条件更新、唯一约束与单调 fencing token；旧 Worker 即使网络恢复也不能提交。版本栅栏防旧执行者，源修订／遗忘代数防事实已变化，两者均不可省。

取消先持久提交，再通过通知通道尽力唤醒执行 Worker。通知丢失时仍有有界检查；每个 Step、领域提交和发送前都重查版本。不能依赖向某个进程发 abort 就宣称跨实例取消完成。

队列按至少一次到达设计，Outbox 与领域变更在同一数据库事务提交。消费重复、Worker失联、提交后确认丢失均有确定状态；外部投递依旧不承诺通用 exactly-once。

持续流连接可留在接入实例，执行 Run 不要求依赖该连接或粘性会话。连接节点退出后，用户从另一节点读快照／事件；重新连接不重新生成，也不重复执行工具。

## 8. SQLite 到 PostgreSQL 的迁移办法

初次个人数据迁移使用受控停写窗口，不引入双写：

1. 验证一致性备份与删除清单；停止输入、取消或结束活动 Run，暂停调度和投递。
2. 导出带稳定ID、修订、来源依赖、时区、幂等身份和投递状态的数据；不把活跃 Run 直接搬过去续跑。
3. 在新库导入、检查外键／唯一性／行数／内容摘要和来源归属，重建索引。
4. 验证 pending、interrupted 和 unknown：旧外部尝试不因迁移重新发送；应用删除清单后再开放数据。
5. 用相同合同集验证更正、遗忘、任务、事件与备份恢复，再切换写入。

切换后产生新写入时，禁止简单改回旧 SQLite；回滚需受控停写和数据对账／反向迁移，或修复前进。旧备份受同样删除与保留策略约束，不能作为未经核对的活动副本。

## 9. 容量保护和故障降级

前台交流与后台记忆／自发关心分配独立并发额度，保留前台容量；按用户公平排队，避免大户独占。全站模型预算不足时先暂停可选任务，明确告知排队／不可用，不假装已关心或已记住。

为请求、队列、SSE缓冲、模型在途调用、工具结果和日志大小设置有界限制。慢客户端可断开续传；超时任务进入明确终态；失败不得通过无限重试放大模型流量。

重型向量计算、语音或本地推理放独立 Worker／服务，不占 API 事件循环。better-sqlite3 的同步调用在自用版也需短小；未来数据库查询变异步不等于没有慢查询，仍需索引、连接池上限与查询预算。

## 10. 放量前的测量与 Gate

工作负载包括普通聊天、长上下文、多工具续步、冷／热缓存、后台提取、通知峰值、慢客户端、重连与删除；分别标明输入／输出Token、每用户数据量与实例资源。

至少报告：accepted和排队P50／P95／P99、首Token、完成与取消延迟、事件循环延迟、CPU／堆内存／GC、连接与缓冲、数据库等待／慢查询、队列年龄、模型限流／超时、每用户与全站费用、重复副作用和越权次数。

先用模拟模型隔离测 Harness，再用受预算约束的真实 DeepSeek 验证协议、延迟与配额。模拟吞吐不等于真实服务容量；Provider 配额和Token吞吐须根据实际账号确认，不猜测默认限制。

每次放量前形成工作负载、SLO、测试报告与资源预算。零越权、无重复领域提交、无遗忘复活是硬门槛；可用性、尾延迟、恢复时间和数据恢复点目标要在对应托管环境确定并演练。不复用个人机P95目标作为公网SLA。

十万同时生成不是既定验收范围。若业务需要，另外建立对应并发和模型吞吐目标；不能拿十万注册或十万日活测试替代。

## 11. 本阶段明确后置的工作

个人版在M0／M1后按实测重估，不再沿用旧总人日或6–10周锚点。W1–W3的账号、合规／年龄设计、正式网页、PostgreSQL、云运维、多实例、Web Push和压测在启动时单独估算。

当前只保留必要作用域、端口、版本和可验证合同。完整上线测试见[验收矩阵未来 Gate](acceptance-matrix.md#9-网页与多实例后置验收)；不会为未来可能的十万用户，提前部署整套分布式设施。
