# 陪伴机器人记忆工程合同

版本：3.4 设计稿。项目：companion-harness。

本文件是运行时、数据、测试和发布的实施合同。[产品规则](companion-memory-v3-product-rules.md)维护体验、准入及温度层语义；[CM3 2 最小试聊清单](companion-memory-v3-cm3-2-checklist.md)唯一维护早期范围和放行条件。主入口见[版本导航](companion-memory-v3-plan.md)。

v3.4冻结，仅CM3 0至2实施。接口、字段、测试位置和延迟是计划合同，不是已实现能力或实测成绩。本轮仅实施CM3 0至2，在新的隔离目录显式建立schema3并验证；现有4321和正式库、进程、向量开关不变。实际实现、测试成绩及限制见[切片交付记录](../implementation/companion-memory-cm3-2-release.md)，本文其他阶段继续为计划。主动发起交流的产品语义见产品第11节，执行复用第3.12节既有链路。SQLite权威存储、本地E5和既有模型提供方继续复用，不引入观察库、许可数据库、情绪状态机或关心Agent。风险分级发布仅是第4.6节的默认关闭实验。

## 1 范围与历史基线

### 1.1 记忆与Agent改造的边界

本方案已经跨越单纯记忆模块：检索由生成过程触发，写入由Run内的真实事务完成，发布取决于证据/回执/取消状态，后台形成又与前台共享资源。它是“记忆、有限主动交流及其必需的Agent执行适配”，不是重写通用Agent内核。

| 层次       | 本次必须涉及                                   | 明确不扩张                                 |
| ---------- | ---------------------------------------------- | ------------------------------------------ |
| 记忆领域   | 准入、槽位、事件、持续事项、召回、来源与遗忘   | 新图数据库、无限画像、跨bot自动共享        |
| 对话编排   | 每轮上下文、按需检索、写入先后、关键意图升级   | 新任务规划框架或自主多Agent                |
| 执行边界   | 幂等回执、取消、有限恢复、发布与实际展示记录   | 通用工作流引擎、任意重放或全部工具权限重构 |
| 资源与体验 | 小型并发限制、完整延迟统计、故障回应、提前试聊 | 全项目调度平台、实时语音协议重做           |

业务选择留在memory模块；harness只负责编排、预算、取消与发布；主动交流复用FollowUp/Series/Outbox，不按“分手/面试”等题目主题加分支。现有模型适配、工具系统和会话身份能复用就复用。新增独立表或通用框架之前，须证明现有对象无法表达，并给出可观察收益；实现顺序以工程第10节为准。

### 1.3 主动交流的现有代码边界

设计阶段只读核对`src/domain.ts`、`src/harness.ts`、`src/schedule.ts`、`web/app.js`和`tests/concern.test.ts`、`tests/schedule.test.ts`。本次CM3 0至2的运行验证只在新隔离实例进行，主动发送关闭。现有FollowUp有kind/confirmed/dueAt/latestAt，Series有daily/weekly及时区，Delivery已有ready/attempt/构造/错误/未知与客户端认领；tick和后台模型调用可复用。

现有concernRule对非commitment使用每日2次/4小时间隔，且allowInterrupt可绕过专注/静默；默认proactiveEnabled=true。deliveryEvent当前要求新鲜在线客户端及浏览器granted，离线ready不补弹，constructed/show/click保持曝光unknown。v3.4的新增授权、严格陪伴限额、只在应用内展示与双检/最小来源不是现状，必须改动并验证，不能因已有FollowUp便称新主动陪伴已接入。

本轮源码哈希另记私有文档检查产物，历史v3源码基线不改写。v3.4只扩展既有对象、资格函数与客户端显示；不引入云推送、Service Worker、第二队列、关系评分或常驻关心Agent。

## 2 数据与资格

### 2.1 作用域

所有新表、缓存键、回执与后台任务包含 `ownerUserId`、`relationshipId`。首版用户档案仍在当前 bot 的关系作用域内保存，不读取其他 bot 的私有资料。

再包含 `subjectId`、`realityScope` 和必要的 `worldId`。现实与虚构数据不能只靠提示词隔离；同名人物不因相似度而自动合并。用户实体使用当前 owner 的稳定标识；朋友、家人和角色使用独立实体 ID。无法确定两个名称是否同一个人时，保留分离。

### 2.2 扩展现有 Memory

继续使用 `memories` 主记录。新增 v3 `admission` 元数据，不把自动写入伪装成手动 confirmed。

```ts
type AdmissionV3 = {
  policyVersion: "companion-memory-v3.4";
  state: "committed" | "quarantined";
  origin:
    | "explicit_user"
    | "automatic_user_statement"
    | "legacy_user_confirmed"
    | "assistant_said"
    | "joint_exchange";
  verification: "user_reported" | "externally_verified" | "not_applicable";
  mutationId: string;
  learnedAt: number;
  observedThroughSeq: number;
  subjectId: string;
  scopeKind: "relationship" | "segment" | "until";
  scopeId?: string;
  validUntil?: number;
  riskClass: "ordinary" | "sensitive_event" | "sensitive_explicit"; // sensitive_event对应产品“受限私人事件”，沿用字段名
  audience: "user_facts" | "bot_continuity" | "shared_history";
  proactiveUse: "eligible" | "never"; // eligible仍须产品第5节选择，不是必须提起
};
```

新自动事实可以是 `active/stated + admission.committed`。长期已提交记录没有默认7天到期；`validFrom/validTo`表达事实的有效时间，临时作用域的`validUntil`限制使用范围，内部计划正文清理期限不参与事实真值。`certainty` 继续表达原陈述的性质，`admission` 表达是否被程序接纳；两者不能混用。首版不自动生成 externally_verified。audience是同一memories表的使用分类，不新增事实主库；assistant_said/joint_exchange的校验以已展示消息和双方来源为准，不强求用户原话作主要证据。用户事实接口排除bot_continuity，bot自述也不能伪装成automatic_user_statement。

通用 `predicate` 不能完全依赖自由文本。维护小型谓词注册表，明确单值或多值、比较规则、允许对象、时间与风险。首批结构化键覆盖称呼、禁用称呼和明确交互偏好；音乐等一般偏好可用多值事实，暂不为每种生活主题造独立表。

v3 统一资格函数同时检查作用域、准入、来源、有效期、排除区间、删除台账和读取截止。SQL 预筛、内存缓存、全量模式、FTS、向量 delta、来源展开和评审投影必须使用相同资格语义，不能只修改 `eligibleFact` 而遗漏 `qualifiedFacts` 的 SQL。

### 2.3 新增表

物理schema版本为3，不凭设计文档版本号将数据库升到4。本轮只在新隔离目录显式创建schema3并验证，不迁移原有库；其余计划字段不等于已实现用途。

| 表                       | 权威内容与约束                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `memory_entities`        | 作用域内实体 ID、别名和证据；别名不直接证明同一身份                                                            |
| `memory_inbox`           | 输入修订、处理状态、单次解析租约、计划指纹与提交回执引用；助手展示登记可用无模型结构化计划；不复制一份事实主库 |
| `communication_contexts` | 用户明确表达的近期交流背景、证据、事件关联、生效与结束条件；与稳定人格分开                                     |
| `profile_slots`          | 结构化键到当前 Memory 修订的指针，按主体 范围 场景唯一；与事实同事务更新                                       |
| `profile_views`          | 核心概览的派生快照，含支撑 ID、版本、最早失效时间和预算统计                                                    |
| `ongoing_threads`        | 计划 状态 结果和时间条件，记录来源及可见版本；不创建 Delivery                                                  |
| `memory_mutations`       | 幂等命令、申请与实际结果、受影响 ID 和版本；不无限复制正文                                                     |
| `memory_suppressions`    | 不保存与遗忘所需的对象指纹、来源区间、适用范围和重新学习条件                                                   |

沿用 `memory_dependencies`、`memory_state`、`memory_embeddings`、`memory_index_state` 与会话摘要表。不得创建另一个无同步合同的事实主库。

温度层不新增独立物理表：敏感事件与bot/共同经历复用memories元数据，接续复用ongoing_threads，临时观察只存在本轮派生投影。ongoing_threads只补`proactiveUse`、`lastOfferedAt`、`lastOfferSourceSeq`、`unansweredUntil`等最小字段；实际展示位置和来源复用消息回执。

事务外生成自然语言概览、向量和 MD。SQLite 事务只包含检查与记录更新，不能跨网络或模型等待。

### 2.4 称呼槽位

| 键                        | 值的含义                           | 基本更新规则                                   |
| ------------------------- | ---------------------------------- | ---------------------------------------------- |
| `self_reported_name`      | 用户自我介绍的姓名，仅表示用户说过 | 不当作法定身份核实，不覆盖已有偏好称呼         |
| `preferred_address`       | 当前关系中长期希望被叫的名字       | 新的明确长期称呼替换指针，历史事实保留         |
| `address_override`        | 当前交流段或到指定时间的临时称呼   | 到期后恢复长期值，不写回长期槽位               |
| `forbidden_addresses`     | 明确拒绝的叫法集合                 | 添加与撤销分开，有独立证据；不被新昵称顺手清空 |
| `interaction_preferences` | 用户明确要求的交流方式             | 使用有限、可解释的字段，不变成系统人格任意改写 |

解析顺序为：当前用户明确要求和禁用约束 → 有效临时覆盖 → 长期偏好称呼 → 用户自我介绍姓名 → 已发布人格默认称呼。用户当轮明确撤销某个禁用值时，先按本轮新的明确指令更新，避免旧禁用永久压过用户的新选择。

“叫我小岚”作为明确称呼指令，默认作用于当前关系；“今天叫我小桥”只设临时值；“他叫小岚”不改用户槽位；“戏里叫我阿棠”只进对应 world。昵称不能被当作法定姓名。“我叫林然，不过叫我小林就好”可分别记录用户报告姓名和偏好称呼，两者不会互相替换。

“今天”到期点按用户时区的下一个当地午夜计算，处理DST，不能用now加24小时；保存表达时的时区与源消息时间，后台延迟或之后切时区不自动延长原范围。“这段聊天”绑定内部交流段，不因页面刷新结束；“这轮”绑定当前 Run。范围不明时不自作永久更新。

每轮生成前和发布前检查 `validUntil`；跨午夜或换段造成的失效即使没有后台版本递增，也不能继续使用缓存临时称呼。

### 2.5 更新与冲突

单值谓词按明确更新顺序、来源语义和生效时间更替，不以后台任务完成时间或向量相似度决定最新值。旧任务的 `observedThroughSeq` 低于现行槽位时不能覆盖。

“我现在改喜欢银色”是偏好变化，旧值的历史有效期结束；“之前记错了，我一直喜欢银色”是纠错，不能伪造一段真实偏好变化史。“两个我都喜欢”不应按单值替换。问“我以前喜欢什么”使用历史查询，不把旧值当现在有效值。

普通冲突保留来源并暂缓有歧义的覆盖。当前输入仍可用于本次回答，暂缓不能变成继续坚持旧值。

### 2.6 核心选择与概览更新

关键字段由槽位白名单决定，不能由模型给一条普通记录打高分就获得系统指令优先级。软性概览只从已接纳、有效、当前作用域匹配的普通用户原子资料选择，排除敏感事件和bot_continuity。共同仪式按用途进入近期/相关召回，不把bot设定并进用户背景。

选择按固定优先级排序：用户明确表达的重要性（须有证据）→ 当前持续事项相关的重要背景 → 多个独立用户来源支持的稳定资料 → 近期相关资料 → 稳定ID。重复提取同一来源和助手自己重复的话不增加支持次数；重要性只影响选择，不证明内容更真实。具体主题不写入排序特例。

超过500 token的软性部分按此顺序收缩，未选内容仍保留归档。用户要求“这很重要”提高选择优先级，但不能把无限信息都变成硬常驻；回应保存成功也不能暗含每轮全部载入的保证。明确的行为边界进入受限交互槽位，而非混在自由文本背景里。

提交新事实只标记概览dirty并记录wantedVersion，不每轮生成长概览。初始维护合并等待60秒，最早dirty后最多5分钟安排一次；同一关系最多一个维护任务。生成期间又发生变化，只允许匹配版本提交或重排一次，不并发写多个相互覆盖的概览。

当前概览过期、依赖无效或尚未形成时，按同一选择规则直接投影有效原子事实作为后备，不等待后台模型，也不用陈旧MD代替。自然语言概览的每条陈述必须能回到来源集合；模型新推断不因写入概览而获得事实资格。

### 2.7 交流段与准入元数据

交流段沿用`src/memory/conversations.ts:assignSegment`：输入受理时按当前关系open段判断；距lastUserAt严格大于30分钟且除本Run外无queued/running Run才切段。无open段创建；等于30分钟不切，其他Run忙时不切。输入、Run、消息的segment引用在同一现有受理事务中落盘。模型生成、页面刷新、重连、后台维护不更新lastUserAt；跨午夜不单独切段，恢复/回填不触发新开场。时钟倒退时本次差值不算正向空闲，记录异常，不提前到期或建新段；不引入额外定时器。

`backfillSegments`只补历史关联，不重新解释同一交流的已展示结果。已持久化的段身份优先，缺失元数据按既有来源重建并记录；恢复前清理中断Run状态，不能用陈旧running无限阻挡切段。bot隔离由Store作用域继续保证，schema3需显式能力检查，不把旧memoryEnabled对schema2的判断当新库不支持。

产品规则只定义行为，字段复用既有Memory/事项/交互偏好：

| 内容             | 现有对象的最小落点                                                                   | 校验                                                         |
| ---------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 当前私人事件许可 | 该事件admission和明确mutation证据，引用已展示征询及用户同意；回执记录实际对象/用途   | 同意不升级关系级related_events，不由生成草稿授权             |
| 一次征询与拒绝   | displayed消息标记用途/源区间，interaction_preferences记录不再征询                    | 不存未许可事件的额外候选正文；未展示不算问过                 |
| 具体主动关心许可 | interaction_preferences的具体事件/事项引用及来源，事务内同步proactiveUse             | 仅该对象eligible，撤回同事务失效，不获得通知权限             |
| 轻量历史证据     | Memory.kind=episode、episodeType=reported，occurredAt/day、时区、evidence与expiresAt | 过去发生不等于当前有效状态；长期事实资格不能直接套用历史事件 |
| bot/共同经历     | audience与origin、displayed区间、人格版本                                            | 不进入用户事实集合，不登记未展示草稿                         |

不新增授权表、观察表、向量服务或关心Agent；存储字段的合法用途由程序白名单控制，用户/模型粘贴许可JSON无效。

### 2.8 轻量事件的保留与资格

后台单次intake可在现有每输入8个变更以内提出短期reported事件，不能无限多提取以给观察凑来源。普通automatic与明确不保存/风险规则先适用；本轮临时状态不必等待事件落盘。采用现有expiresAt限制这类轻量证据，不新增保留服务。已关闭自动形成就不主动挖历史原话补齐。

发生日期明确时，以发生时捕获的用户时区，计算该当地日期起第14天的零点为缺省expiresAt：例如D日经历在D+14日零点退出本类可读证据，D日至D+13日可读，处理DST。回述同一经历不刷新expiresAt；晚到事件按实际发生日算，不从后台完成日重开14天。未知发生日保留observedAt而不造occurredAt，不计不同发生日的观察支持。用户明确长期保存时走原变更/回执流程调整保留，不能自动续命。

历史event读取以事件发生范围和retention/来源资格判断，不要求过去事件的状态validTo覆盖现在；expiresAt、遗忘或来源失效仍阻断。当前状态读取则要求当前适用性。每日维护可物理清理到期派生记录，但读取时到期即不可用，不依赖定时作业赶上。界面原聊天保留不能替代事件证据；纯观察不新增14天原文扫描路径。

## 3 执行路径与及时生效

### 3.1 输入收件箱与三条执行路径

输入接收事务保存原消息、来源修订和enqueueSeq。automatic模式创建普通`memory_inbox`条目；explicit_only/off不启动普通提取，也不制造等待30秒超时的空任务。需要办理的关键指令按需登记inbox；off下的一般保存返回disabled结果，允许的交互控制和遗忘仍可执行。收件箱状态为 `queued | running | requires_sync | committed | partial | noop | quarantined | failed | cancelled`；到达queued只证明原话和处理任务已登记。每项操作另有状态与pendingOperationCount；仍有未决操作时父项保持running/requires_sync，结束后记录settledAt和committed/partial等实际结果，partial不能隐藏尚未处理的请求。

普通分享不再先等一次模型准入。输入走三条路径：

| 路径         | 进入条件                                             | 必须等待                                         | 可并行或后台执行                   |
| ------------ | ---------------------------------------------------- | ------------------------------------------------ | ---------------------------------- |
| 普通聊天快路 | 无需即时改变核心或执行记忆命令                       | 本轮上下文、必要生成、两个发布检查               | 普通事实提取、概览、索引、MD和维护 |
| 关键事务路径 | 明确保存/更正/遗忘、称呼或交互控制，或其语义尚不确定 | 受限解析、资格校验、实际事务结果，随后生成及检查 | 向量与自然语言概览不阻塞提交       |
| 按需召回路径 | 指代未解、相关背景不足或用户回问历史                 | 有界检索及必要的一次生成续接                     | 无关维护不参与等待                 |

路径可以组合，但受同一个Run预算约束。程序路由提示只做快速分流，不能授予写权限，也不能被当成自然语言指令识别完整性的证明。规则只识别通用命令结构与明确UI命令，不加入题目实体或主题特例。

### 3.2 普通聊天快路

1. 持久化输入与收件箱，读取当前核心槽位、近期情况及有限的尚未处理来源覆盖；交流段开始时按产品第5节选择最多一个可选接续线索，按工程第6节决定是否基础检索。
2. 后台单次提取可与读取、生成并行，不让当前回复等待普通资料持久化。当前用户明确说的内容直接约束本轮回答，不必先假装它已入库。已实际问过事项后的默认冷却由程序写入，下一轮已有intake只识别明确接续/更新/拒绝并引用用户证据，不另调用“转题分类器”；未知时保留冷却。
3. 用本轮快照生成答复；交流背景与应用信号作为有范围的数据参与生成，不额外串行调用一个语气模型。
4. facts与operations使用同一份草稿和冻结证据并行检查，两个结果都要返回才进入发布屏障。普通回合默认不主动播报保存状态。
5. 发布前复核来源、关键槽位、到期时间和收件箱是否已标记requires_sync。只增加不相关事实的后台提交不使整轮重答；具体依赖规则见工程第5.3节。

普通无工具回合是一次生成加两次并行检查，共3次前台调用；这是相对3.0取消阻塞准入的快路，不声称已经比当前v2实测更快。后台提取仍要单独计费，不能把总成本减少一次当作事实。

### 3.3 漏判关键指令时的升级屏障

operations检查在校验保存陈述之外，必须依据**用户输入**给出 `requiredAction: none | sync_write | clarify`及对应用户证据。明确指令未办理、后台计划标记requires_sync、或者对象有歧义时，普通草稿不能直接通过。

出现sync_write时，当前草稿尚未展示，程序将其丢弃或冻结，升级为关键事务路径；提交后重建有关状态，再生成并双检。无法确定目标时只做自然澄清，不替用户默选记录。全Run最多升级一次。

升级与读取需求同时出现时，先处理遗忘/停止、关键控制及实际写入，再处理仍合法的只读请求；不能查回刚要求忘记的对象。路径升级不重置查询数、读取阶段数或截止。

用户明确命令的漏判检测不得只靠关键词，也不能依赖生成模型自报“我没有修改记忆”。语义检查仍可能出错，故设定关键场景零错误验收和路由召回率监控，不能宣称程序能确定识别所有自然语言。

**不能为了让草稿中的错误保存承诺成立而临时补写。** 若用户只是普通分享，草稿却擅自说“已经保存”，应按实际回执拒绝或文字修复；用户意图与草稿陈述分别判断。

### 3.4 单次解析与受限计划

新增`src/memory/intake.ts`和`src/memory/inbox.ts`。普通路径由后台执行一次小型结构化提取；关键路径才等待其完成。输入仅含必要用户原话、已展示的助手语境、实体/槽位候选和时间，继续使用已授权模型提供方。

计划表达主体、谓词、值、时间范围、肯否定、意图、风险与逐条证据。一次私人征询的回答需核对实际displayed提问、唯一事件及用户回应，不能从普通“好”推导整类授权；首次征询不新增解析调用。明确主动关心授权/撤回按交互控制关键路径执行，并在同事务更新对应proactiveUse。当前单值覆盖、撤回、关键称呼和明确交互约束都属于同步候选，不能因category叫preference就被丢到普通慢队列。简短回答可以利用上条已展示提问定位语义，助手建议本身不能作为用户事实。

一条输入的前台与后台共享父幂等键、计划指纹及single-flight租约。若后台正在解析而路径升级，前台提升该任务优先级并在剩余截止内等待同一次计算；已有合法计划直接复用，不同时再调用模型产生另一套申请。后台不得独自执行已判定须同步的显式保存、更正、关键槽位、明确交互控制或遗忘命令，只生成计划并返回requires_sync。若结果在发布后才揭示漏判，记为关键时效失败，不偷偷补一次执行来把当前回合算对。

准入先做预算预检。私人事件提交的primaryEvidence指原用户陈述，contextEvidence引用实际已展示征询和明确同意；程序将许可约束绑定本事件，事件事实和许可需同事务成功。自然征询不算提交，拒绝/跳过不建立长期事件；关系级设置另按明确指令办理。一次最多申请8个原子变更；超出项有明确后续范围，整体结果标为partial。quarantined计划不自动猜测升级；未许可受限内容/禁存值不持久化为候选或计划正文，仅保留必要来源ID与拒绝原因，不复制原文。其他合法临时计划正文7天清理；澄清依据必须来自新的有效输入。过长输入不得截半条去存。

来源切片只能证明原文存在，不独自证明解释正确。有限谓词、保守风险策略、撤销历史与毒化测试共同约束自动写入；后台模型解析错误也要计入记忆失败。

### 3.5 命令接口与真实回执

```ts
type MemoryCommand = {
  type: "add" | "replace" | "set_override" | "retract" | "forget";
  subjectId: string;
  predicate: string;
  value?: unknown;
  targetId?: string;
  expectedRevision?: number;
  scope: {
    kind: "relationship" | "segment" | "until";
    id?: string;
    until?: number;
  };
  primaryEvidence: EvidenceRef[];
  contextEvidence?: EvidenceRef[];
};
type MemoryReceipt = {
  kind: "memory_command_result";
  mutationId: string;
  inputId: string;
  inputRevision: number;
  status: "committed" | "noop" | "partial" | "quarantined" | "failed";
  durability: "durable" | "segment" | "until";

  committedAt?: number;

  memoryVersion: number;

```

入队票据、原话落盘、提取完成、向量ready与本接口的成功提交是不同状态。owner、relationship、来源资格、策略版本、mutationId和实际结果由程序填入；模型或用户粘贴的JSON没有执行权限。新表有作用域复合索引，指针在事务中检查所属关系。

committed加durable才支持“这条已长期保存”；segment/until只支持对应短期范围。noop可以支持现有已存状态，不证明本轮新增。partial只能描述已成功的子集。向量未完成不影响事实保存成功，也不支持每次必然召回。

### 3.6 原子提交与下一轮可读

1. 校验字段白名单、对应origin的主要证据、UTF-16边界、风险、范围、排除规则与当前时间。用户事实须用户证据；assistant_said须实际displayed证据，不能互换权限。
2. 父键为 `intake:{inputId}:{inputRevision}:{policyVersion}`，保存计划指纹和各操作ID。相同键不同申请返回冲突，不新建第二条事实。
3. 短事务内复核来源、epoch、取消状态与CAS；写事实、槽位/事项/屏蔽、依赖、dirty索引状态及实际回执，统一推进内容版本。
4. 事务成功后立即更新结构化读取、当前值与未索引事实delta。下一轮不等待自然语言概览、MD或向量才看到新值。
5. 后台任务只读已提交版本，旧来源或旧序列的迟到结果不能覆盖新纠正。

同一槽位替换的旧值失效、新值生效、指针和回执必须原子完成。CAS最多重新读取一次；网络/模型等待不得跨SQLite事务。mutations最多8个的限制不允许把半槽位结果标成成功。

### 3.7 尚未提交时的连续性

普通自动记忆目标为输入接收后提交P95不超过5秒，正常负载下每条待处理输入30秒内进入明确结果或failed；这些是待验证的工程目标，不能以后台仍在排队无限延期。

下一轮先读取已提交delta；若前序输入还未处理，可在本次本地读取阶段内进行最多80ms的有界等待，并使用有限的pending-source覆盖。覆盖最多取8个来源，只占工程第5节近期分区配额，带有user-stated/recent-source与pending标识，不叫长期已确认事实。

用户问“已经存好了吗”必须检查真实回执，不能用来源覆盖回答“已存”。当前知道某内容、排队处理过、已经长期提交分别统计。队列失败时，可以在本轮依据中使用仍允许读取的原话，但不得假装持久化完成。

证明确实靠长期记忆的消融必须同时禁用近期原文、摘要、临时来源覆盖和带答案的交流背景；等待实际commit之后再问。只从pending原话答对，不算长期召回成功。

### 3.8 取消 失败与重启

正常回复完成不取消普通记忆后台任务。取消发生在某项写入提交前时，撤销该输入尚未提交的写入，标记inbox cancelled，不让维护任务再从相同来源自动重放；已提交项不因停止回复隐式回滚。明确撤回、关闭形成、遗忘和来源删除使有关未提交任务失去资格。

回复生成或评审失败不等于已经提交的记忆消失；用户未撤回输入时，合法后台任务可在其原始截止内完成，状态分别展示。重启先读幂等记录、计划租约、回执和删除台账；不重复写入，也不自动继续中断的聊天。

### 3.9 前台与后台调用预算

| 路径               | 正常前台模型调用 | 额外工作与边界                                                                |
| ------------------ | ---------------: | ----------------------------------------------------------------------------- |
| 普通无工具聊天     |                3 | 生成1，facts与operations并行各1；普通提取后台最多1次成功解析                  |
| 普通加一次检索续接 |                4 | 主生成发出有界检索请求，读取后续接1次，无独立问题规划模型                     |
| 已识别关键命令     |             4至5 | 等待/复用准入最多1次，生成1至2次，检查2次                                     |
| 快路漏判后升级     |         最多7至8 | 已花3至4次，准入最多1次，再生成与检查；未用过的工具续接至多1次，整体仍不超8次 |
| 完整文字修复       |            另需3 | 无工具、无写入重放，启动前必须预留3次                                         |
| 检查故障恢复       |     全Run最多1次 | 同一规则重试故障检查，仍受总额约束                                            |

前台硬上限仍为8次、60秒；升级、恢复和修复共享额度，不能把它们逐项相加后越过上限。主生成所用的检索问题随允许的工具申请产生，不额外先串行问一次模型。预算不足时不开始不可完成分支，也不为了继续输出而跳过检查。

每条输入的普通后台解析最多一次成功执行，暂时故障最多重试一次，受30秒队列总截止和原始来源资格约束。关键路径复用同一解析，不能前后台各算一次“正常成功”。同一输入前台最多8次，另有未升级的后台解析最多2次尝试，来源级总尝试上限10次。后台解析被提升为当前Run等待时，已开始的相同来源尝试纳入前台8次账本，不重复计费；超额前停止启动新请求。异步调用、被取消但用量未知的调用、路径升级和维护均有originInputId/RunId并计全局日预算；移出前台不等于免费。

主动交流按工程第3.12节作为既有低优先级后台任务计费，不能另开模型池。后台概览/整理由维护作业单独计费，25秒单调用截止；它们不发送聊天或通知，不获得日程授权。索引与CPU后台工作优先级低于前台读取。普通快路保留两个模型发布检查，因此仍有模型等待；在没有单独验证前不承诺Tolan式即时语音。

### 3.10 模型并发与前台优先级

采用一个有界模型请求调度器，按提供方账户/凭据引用划分资源池，不记录原始Key。初始池上限3个在途请求，其中最多1个普通后台提取/维护；前台双检按一组预留2个槽位，避免各占一个再互相等待。每个bot仍只有一个前台Run，跨bot共享调度资源不共享任何资料或回执。

初始3并发必须通过当前提供方的限流与延迟实测。前台到来时不再启动会占用预留的后台工作；已经开始的模型请求不能被假设能即时中断或释放远端资源。资源不足时可观测地排队或让双检串行执行，检查标准不变，但不能仍按“已并行”报延迟；普通提交5秒目标或首答目标因此不达标时，该条件不得通过发布门槛。

关键事务与前台检查优先于普通提取，普通提取优先于主动交流，主动交流优先于概览/每日维护。后台工作保留原输入截止，不能在每次重新排队时续期。记录预留、排队、开始、结束和限流错误；取消后的未知用量照常入账。重试不新开无限并发池。

基准延迟目标以每账户一个活跃前台Run加一个普通后台任务为基础负载；多bot并发和服务端限流另设压力场景，同样报告受理至结果的完整延迟与失败，不隐去排队。无法获得足够并发时，应据实优化请求结构并重新验证，不能静默停用自动记忆或跳过任一检查来兑现时延。

### 3.11 展示后的bot连续性登记

口头承诺涉及未来可交付内容时，复用operations检查输出可在展示后登记的自述/约定候选及草稿区间，facts仍校验人格和依据。实际displayed后，程序只取可见完整区间，以`display:{messageId}:{displayRevision}:{policyVersion}`键进入现有收件箱，验证来源和准入后短事务写入；不再模型提取一次，不增加输入来源10次调用上限，也不为每个文本片段重登记。同一显示消息的增量只追加未处理完整区间，重复/回退回执不得双写。

一般自动形成关闭时不被动新增bot/共同经历，明确用户保存仍按原模式处理。用户主张共同仪式的解析可引用已展示助手语境，但assistant_said与用户事实必须拆开。后台写入继续受取消、作用域、源修订、删除台账和原有任务限制；以可用displayed回执接收时间起算5秒目标/30秒截止，和用户输入受理到事实commit分栏，不把12秒后才说出的承诺要求在输入后5秒落盘。记录失败进入连续性故障，不自动重发承诺；近期已展示消息仍可用于当前接续。显式保证“已保存这个约定”仍需发布前真实提交，否则修复该保证；展示后登记仅证明说过，不替虚假保存回执补票。

本节只登记已展示内容，语义见[产品第8节](companion-memory-v3-product-rules.md#8-bot与共同经历连续性)。它不新增模型调用、人格服务或新的用户事实来源。

### 3.12 主动交流执行合同

用户规则由[产品第11节](companion-memory-v3-product-rules.md#11-主动发起交流)维护。执行只扩展既有tick、concernRule、processConcern、deliveryEvent与前端显示：

1. **形成候选。** 普通新事实/事项更新时及现有tick检查dueAt时，最多选一个有触发和许可依据的候选。首版来源仅为明确授权具体事项的reviewAfter/日期检查或用户明确Series；72小时空闲触发暂缓；没有近期新消息不是情绪证据。不扫描原聊天、不每tick询问模型“要不要联系”。
2. **登记一次。** 同一事务以事项ID+触发类型+原review窗口，或空闲起点enqueueSeq，构造稳定occurrenceKey，登记已有FollowUp。源修订、政策升级、时区变化、重启和换文案不产生第二个相同机会；更新资格/许可只刷新同一候选或取消，不重置成功尝试。Series沿用系列ID+实际发生槽位。
3. **程序预检。** 沿用remoteDisclosureAcknowledged及modelReview门槛；在模型调用前检查许可范围、源修订/屏蔽、有效窗口、普通/私人用途、总闸门、静音/专注/当地静默、前台Run/真实输入信号、当前在线通道、未回应暂停、日额度/24小时/同事项冷却。没有可用通道就不调用模型，为原窗口内现有tick留待判定；到期关闭，恢复在线不为旧候选重开窗口。
4. **有限生成。** 复用既有关心值得性判断、生成与评审；正常最多4次后台模型调用（判断1、生成1、facts/operations各1），60秒原始总截止，单调用25秒；来源级及日预算照常计费。没有新的规划模型，两项检查使用同一草稿/read-set，作为后台请求顺序执行以服从账户最多3在途/后台1的资源池；不照搬前台双检并行来占满后台额度。每次调用先核对剩余60秒截止与费用，不启动无法完成的分支。前台到来优先中止/延期，未知远端用量入账。
5. **最小证据。** 从已授权事项及合格当前记忆有界组装，沿用2阶段/总500ms读取、24000请求输入预算及现有分区；不直接把f.sources整段原文塞给关心模型。私人源只提供许可区间，事实/操作检查同时防止未知结果、因果、虚假办理和扩大许可。该后台生成不执行一般记忆写入或创建新的Series。
6. **保留原窗口。** 一次生成/双检失败或值得性skip不发布，当前occurrence结束；语义判断的skip或defer都记为本次skipped，不推迟一小时再问模型。免打扰、离线等程序条件仅在模型调用前于原窗口内延后检查；同一窗口最多一次语义判断/生成，当下不值得就放弃此次机会。过长结果不在检查后slice成半句，超出最终允许文本长度就不入Outbox。没有用户等待本次答复，失败不发送固定故障模板。
7. **Outbox与认领。** 检查通过后在现有Outbox事务中对FollowUp/许可/read-set/epoch复核，同一occurrence最多一个Delivery。actual attempt再短事务复核所有发送条件及客户端，原子认领、记录用户序列和消耗配额；总闸门关闭/取消/遗忘先提交则拒绝认领。已经开始外发只能如实报告inFlight，不保证收回。
8. **显示与接续。** 可见且当前选中该bot的页面走in_app；后台在线页面只有既有granted通知权限且触达授权明确包含该通道才走browser_notification。心跳复用现有45秒新鲜度，未提供可见性不猜可用in_app。一次认领选择一个打断面，保留现有5秒permit；客户端超时/撤销后不得构造消息；切bot或关闭页面作废该页面旧permit，不把消息插入其他关系。系统预览固定泛化文字，具体内容只在当前聊天按资格展示。回执/重连仅核对同一ID，不重试外发；用户新消息再走正常Run更新事项。

现有浏览器granted检查不能原样套到in_app：用户允许应用内主动聊天但拒绝系统通知时，只允许当前可见聊天内显示，不弹通知。扩展既有channel/attempt字段即可，不增加平行发送器。应用不运行、网页完全关闭或无在线通道不承诺唤醒；不注册新自动任务、系统cron或外部通知服务。

免打扰用quietStart包含/quietEnd不包含、用户时区和既有相等值语义。陪伴触达固定allowInterrupt=false，即便模型或旧普通FollowUp传true也不能绕过。旧commitment仅保留原先该明确提醒的打断许可，不继承到陪伴；muted与总关闭仍不可绕过。已明确创建的日/周仪式按每个Series槽位授权，不受自主滚动24小时/同事项7天限制，仍占陪伴日额度；当天有效Series先占候选优先权，普通触达/聊天内自发询问不能抢用其预留。延期不更新latestAt；自主一次性缺省窗口24小时，Series沿用windowMinutes默认60分钟/允许5至240分钟，不套24小时。关机/睡眠后不补发过期Series。

自主一次性触达attempt后，用attempt时的用户enqueueSeq判断未回应暂停：仅真实更新的用户消息解除该暂停，不靠click/反馈/心跳，解除也不重置频率或明确退出。已授权周期仪式和明确提醒走原Series语义，可不需回复而持续，但不得产生额外自主跟催。disturbed设置有来源的同类暂停；not_seen/error/unknown不重发，不能因unknown假设用户没收到而退款额度。

前台Run受理时，未认领的同关系陪伴Delivery让位并取消本次旧主动候选；不能插到用户问题前。若已认领则停止可取消部分，记录inFlight，下一次前台回复不指责未读。聊天内主动询问和Delivery用同一事项ID/来源去重，通知展示未知时只说真实状态，不将其解释成用户忽略。

## 4 发布屏障与故障恢复

### 4.1 同一草稿的并行检查

facts与operations并行处理同一份草稿和冻结的读取/回执快照，均完成才发布。程序先为两次调用一起预留预算；一项失败也要回收另一项的信号、使用量和结果，不能留下未计费请求。

- facts检查本轮证据、属性/主体/时间、当前明确约束及交流背景中的硬要求；必要时返回有用户依据的requestedRead，不把无依据断言改成“知识不足就算对”。
- operations检查保存/修改/删除/未来承诺，另检查用户是否有尚未办理的关键意图；requiredAction必须引用用户输入，不能以草稿自行作出的承诺为写入授权。
- 两项的flow decision与语义违规分开保存。要求查询或升级路径不是自动通过，也不允许对方越权返回不属于自身的违规类型。

默认快路仍执行两项检查，不靠放宽评分获得较低延迟。它是当前可验证基线，不是每轮双评审永远最优的结论；减少检查或分段发布仅按工程第4.6节实验，未经独立验收不进入试聊默认路径。

### 4.2 保存陈述的依据

`memoryOperations`只来自真实回执：允许动作、已提交子项、失败/partial状态、durability和有效时间。队列、输入落盘、提取已结束与index ready均不能充当保存成功。

回执ID解析为本次实际变更的主体、谓词、修订、有效期和受限摘要，作为committedFacts交付；已有确认状态作为existingFacts交付，两者独立于普通召回裁剪。不能用不透明ID支持任意保存内容，也不能把一次noop说成本轮新增。

普通分享默认不播报办理。显式请求只有实际commit后才可自然回应“记住了”；失败、短期保存、partial分别按实际范围表达。保存成功仍不保证每次跨窗口召回。

后台在检查期间完成了一条普通资料，不自动使已冻结的“未提交”状态变成成功判定。草稿若有相关保存陈述，只能在有剩余预算时刷新对应回执并重新检查，否则修复该陈述；不能把发生过一次提交当作检查已经通过。

### 4.3 发布前复核与路径升级

发布屏障检查源资格、取消、epoch、当前槽位、read-set修订、validUntil、相关suppression及requires_sync标记。需要升级时最多一次，保留原输入顺序与single-flight，不发布旧草稿。

普通加法式、不涉及read-set/核心/当前查询的提交不触发整轮重答。新版本若使已用记录失效、改变关键字段或产生同谓词冲突，必须刷新有关依据；不能把“后台异步”变成允许旧称呼或已遗忘内容继续发布的例外。

收到要求忘记或停止的输入时优先执行失效与取消边界，不等普通索引或概览任务。任何实质性用户指令都不能被“快路优先”跳过。

### 4.4 有界修复

只读搜索或来源展开后允许一次保留完整结果的文字修复，`tools=[]`；不重跑检索、准入或副作用工具。关键事务已提交的回执照常保留，不能用文字重试再次写同一事实。存在未处理副作用或不完整工具组时不进入自动修复。

已有整句移除只在facts已通过、违规仅为操作/流程句、位置唯一、结果非空且仍回答用户问题时使用；结果再次双检。不能删除正确答案主体、半句否定或歧义引句凑通过。

### 4.5 检查故障与可见输出

非法JSON、网络错误、截断和非法引句属于检查故障，与语义拒绝分开。全Run最多一次同规则恢复且必须有预算；不得补括号猜结论、将空结果视为通过或换宽松评分。原草稿仍不可信时不发布它。

用小型确定性故障回应替代只有失败图标的沉默，不再调用模型、不读取用户档案、不插入昵称或事件细节；只表达本轮故障，不泛化安慰或猜测用户心情。从已发布人格选择1至2条预审固定故障文案，找不到时用中性文案，例如“刚才这条回复没能完成。”文案与人格版本绑定，只改变语气；缺失/非法文案不能令故障处理再调用模型。按Run实际状态选择文案。没有识别到原输入丢失，不要求用户重新说一遍，也不承诺后台会自动重试。关键命令的未决执行先停止或有明确终态，不能在回应失败后又悄悄执行关键命令；合法普通后台形成仍按工程第3.8节保留原截止，不把生成失败当自动撤回输入。

若该Run存在显式记忆命令，故障回应必须与真实事务结果一致：已提交、未提交、部分提交、状态尚不可确认分别说明，不能笼统说保存失败。只用程序生成的允许动作/数量/短期范围，不回显未审阅的任意正文；状态不明时不自动重放，先按幂等记录核对。已提交事实仍在，回复检查失败不回滚事实。

故障回应作为本轮唯一受限可见结果，记录`outcome=degraded`与来源Run；重复发送去重，取消/过期Run/切关系禁止迟到发布。它经过程序的作用域、取消、原始预算、回执与固定文案检查，不把未经检查的模型句子拼进去。若关键槽位装载或存储基础设施已失效，使用不含任何个性化内容的故障文案；通道本身断开只能界面报告，不承诺每种故障都可送达。

该消息可在用户允许朗读时作为独立受限故障消息播放，照常支持取消；不会进入bot自述/用户事实、摘要或共同仪式。它不算原问题成功或首个有效答案，单列故障回应送达时间与率；不能把沉默改成模板后声称u02/u07已修好。

默认路径的模型文本段和TTS仍等完整发布屏障。界面“正在回复”不写成角色消息、不发给TTS；预录语气词、动画和故障回应不能计首个有效答案。u02、u07、q28原输入与评分保留，完整回归仍要求交付正确实质回答。

### 4.6 风险分级发布实验

本项是独立、默认关闭的实验，不是CM3早期试聊或完整交付的必需前置。只在合成数据/新隔离副本运行，不接管现有bot，不将“先发出去再更正”作为默认策略。

对照保持相同输入、模型、记忆快照与评分：A为完整双检基线；B试验确定性检查加缩小语义检查范围；C只有B先通过才试验完整语义段的分段检查/发布。不设独立风险规划模型，不引入通用发布策略框架；用现有harness内一个实验分支即可。

风险识别同时看用户意图、实际注入资料、工具/回执与待发布内容，不能只看有没有“记住了”字样或让模型自报安全。保存、更正、遗忘、关键称呼/边界、历史断言、敏感事件及关键意图有歧义时保留完整屏障。没有历史断言也不自动免除昵称、隐私和普通事实真实性约束。

程序能做的作用域、取消、失效、回执和已知禁用称呼匹配先做；字符串匹配不是完整语义判定。若无法定义足够可靠的轻量路径，就记录未达到条件并保留A，不为节省调用宣称天然安全。C每个完整语义段必须先满足实验定义的检查，余段未过不外发；跨段指代/否定不清退回整段检查。已发语音不可撤回，不能靠后一句更正抵消泄漏或虚假回执。

实验样本在运行前冻结，包含一般闲聊、隐含称呼/历史依赖、迟到更正/遗忘、混合敏感内容、反讽否定与半句误导。与A逐条配对报告：完整成功、误放行、误拦截、取消/晚到、首个有效文本及音频、总成本。涉及泄漏、禁用称呼或虚假回执的错误阻断实验；其他分项也不能以延迟改善抵消退化。候选至少按工程第11.4节负载每路径固定120次尝试，并人工复核冻结对抗样本；小样本零事故不证明总体安全。

是否采用B/C，需形成单独实验结论、明确适用回合与未覆盖风险，并更新默认路径合同与验收后再安排隔离发布。文档没有预先承诺少一次评审或流式一定更快。

## 5 上下文预算

### 5.1 独立分区

继续采用 24000 token 的 requestInputBudget，包含工具 Schema、包装及本次所有输入消息。输出和推理 token 另受模型能力与请求上限约束；调用前检查 input 加 output 加 reasoning 不超过该模型可用窗口。不得把 24000 当作包含输出的模型总窗口。

| 系统 人格 执行与记忆规则 |             7000 | 不靠裁剪安全规则挪预算；规则本身必须控长   |
| 关键称呼与明确交互边界   |             1600 | 每轮固定包含当前有效值，不参与普通事实淘汰 |
| 核心软性概览             |              500 | 可去掉低优先级背景，保留来源引用           |
| 近期情况与持续事项       |              800 | 当前话题优先；不将未展示新输入带入旧 Run   |
| 分段与近期摘要           |              800 | 按范围与相关性选择，避免同时重复日摘要     |
| 长期召回事实与事件       |             1500 | 已包含在核心/近期的记录不重复注入          |
| 近期原文                 |             3500 | 以完整交流组裁剪，助手只读 displayed 前缀  |
| 当前输入                 |             2000 | 软配额，可借其他分区；不静默截断用户输入   |
| 工具 Schema              |             1000 | 只提供当前允许的工具，不截坏 JSON Schema   |
| 工具结果交流组           |             2000 | 完整配对，当前交流组不半截删除             |

| 修复与额外状态预留       |             2300 | 日常组装不预先吃满；不足时继续裁剪可选分区 |

软配额允许借用，最终以整个请求序列化后的估计为准。按用户遗忘指令屏蔽目标值属于明确的隐私投影，不属于预算截断；保留命令框架与来源映射，并记录屏蔽，不能无痕改写原消息。估算误差记录到指标；供应商提供真实 token 时记录估计与实际偏差，不能宣称中文估算精确。

近期分区800 token内部初始分配为持续事项350、交流背景250、pending来源覆盖200；开场候选、观察与当前相关bot约定从相应子配额共享，不再新增分区。三者可互借，不能再各加一个800。原文与pending覆盖按来源ID去重。确实回答当前问题所需的待处理原话可借用归档/旧历史配额，但仍标为recent-source，不伪称长期事实。

### 5.2 确定的收缩顺序

当完整请求超过总预算时，按以下顺序执行；每一步删除原因、记录 ID 和最终分区大小写入 Trace。

1. 去重：相同事实、概览与原文的重复注入先去掉。
2. 旧工具组：2000 → 1000 → 0，当前所需完整工具组保留。
3. 较早原文：3500 → 2000 → 1000 → 0，按完整 Run 交流组淘汰。
4. 可选摘要：800 → 400 → 0，不误报已经覆盖全部原文。
5. 归档召回：1500 → 800 → 0，关键字段已在核心，相关建议证据丢失后必须重建读取范围。
6. 非当前事项：近期情况 800 → 400 → 0；当前明确未解决事项先保留，其余归档仍可检索。
7. 软性概览：500 → 250 → 0。
8. 若关键字段、当前输入、当前完整工具组、Schema 和必要规则仍放不下，返回明确预算错误，不丢禁用称呼、不截用户原文、不伪称全量。

关键字段可借用被释放配额，因此 1600 不是“第 1601 个 token 开始忽略用户边界”的存储截断线。字段持续膨胀时做有来源的等价去重；不能压缩成语义更宽或更窄的规则。极端情况下无法装入全部关键约束，停止生成并记录 `critical_context_over_budget`，不以沉默忽略换取正常回复。

### 5.3 每轮重建与依赖检查

每轮组合已发布人格、当前槽位、软概览、近期/交流背景、相关bot/共同经历、相关归档及真实应用信号，不沿用上一轮整块动态提示。静态前缀可复用；缓存键包括作用域、策略、来源修订、epoch及最早失效时间，不复用已过期心情或旧昵称。

快照包含coreRevision、memoryVersion、contextVersion、indexVersion、enqueueSeq、validUntil，以及实际使用的record/source/slot/context IDs及修订，形成read-set。若新输入明显换话题，重新选择相关事项与检索问题，不把上一主题回忆机械追加进来。

memoryVersion/contextVersion变化用于发现可能失效，不能单凭全局版本变化要求整轮重答。分别处理：

- 不相关普通事实新增、无关概览更新、向量ready或MD完成：本轮read-set仍有效则继续。
- 当前槽位、已用事实修订、同谓词当前值、来源屏蔽/删除、关键背景或validUntil变化：刷新相关快照；必要时最多一次重建/重生成，并受8次上限约束。
- 交流卡片过期：去掉“当前状态”资格，不能仅把后台时间戳改新。系统取消和epoch失效优先阻断发布。

read-set还保存本轮查询的主体/谓词/时间范围和覆盖条件。新事实即使不在原记录ID集合中，只要落入当前查询范围、改变完整列举或当前值，就视为相关变更；无法证明无关时保守刷新。readScope包含本次读取时刻，不能把某快照的完整集合宣称为实时全历史。

程序保留实际提交回执，不重新执行写事务。它可以刷新证据后重检，但不能把旧检查结果套到新草稿或新关键依据上。主动触达的许可/通道/额度在Outbox和attempt边界另复核，前台检查通过不自动授予后台发送权。

## 6 主动检索与间接召回

### 6.1 先确定需要哪种信息

| 目标                       | 首选路径                                      | 证据范围                                          |
| -------------------------- | --------------------------------------------- | ------------------------------------------------- |
| 当前称呼/禁用/明确交互边界 | 当前有效槽位固定注入                          | 不靠E5命中，不用旧值替代新值                      |
| 刚说过但后台未完成的资料   | committed delta，必要时有限pending覆盖        | 保留pending/recent-source标识，不算长期已存       |
| 当前事项与交流背景         | 主体/事件/时间过滤                            | 卡片存在不证明当前情绪未变                        |
| 一般稳定事实               | 小规模全量，否则关键词加E5                    | 资格一致、未索引事实有delta                       |
| 早期决定/经历              | 摘要或事件FTS，人物/时间过滤，逐步接事件E5    | 受限来源展开，不把计划推成结果                    |
| 旧昵称/旧偏好              | asOf/历史修订查询                             | 不写回当前值                                      |
| 编号/型号/精确名字         | 结构化与字面匹配优先                          | 不由语义近似补数字或身份                          |
| 受限私人事件               | 合法许可、当前意图下主体/时间/FTS及受限本地E5 | 不入核心/MD/all；候选不是因果，不自动授予主动点名 |
| bot自述与共同经历          | 按audience和主体过滤近期/事项或FTS            | 同一关系但不同证据权威，不污染用户档案            |

### 6.2 有界主动检索计划

程序先利用当前消息、当前实体和持续事项选择基础查询。问候/普通闲聊只读核心及必要近期状态，交流段开始时可含产品第5节最多一个合格接续线索；不强制每轮扫描归档。指代未解、用户回问历史、或当前目标缺少相关背景时才扩展。

合成问题优先由已存在的主生成调用以工具申请表达，不增加每轮独立问题规划模型。主模型看到的工具描述要求：先提出能弥补本次信息缺口的问题，查后回答；不能把问题本身当作事实。

```ts
type RecallPlan = {
  trigger: "history_question" | "unresolved_reference" | "missing_context";
  questions: {
    text: string;
    target: "facts" | "conversation" | "episodes";
    entityIds: string[];
    reasonEvidenceIds: string[];
    from?: number;
    to?: number;
  }[];
  sourceIds?: string[];
};
```

问题来自当前用户意图或有效近期线索，例如“今天总算结束了”可查询最近尚未结束的事项，不能据此认定某次面试已完成。未解析出对象时先搜近期候选，多个合理对象仍需自然澄清；不得补造婚姻关系、人物或敏感背景当作过滤条件。

服务端绑定owner/relationship、现实范围、来源权限和当前截止；模型不能指定其他bot。questions最多2个，每条最多256个UTF-16单位，sourceIds最多2个且每条默认展开不超过512 token；连基础当前消息查询每Run最多3条查询。缓存命中也占查询数，避免通过缓存制造无限搜索；问题和缓存都没有写入权限。

facts检查可在当前问题确需缺失依据时请求一次有界读取；若主生成已经使用额外工具往返，不能再次无限扩展。预算不足时如实表达本轮依据不足，不猜值或声明全库没有记录。

### 6.3 读取阶段与延迟上限

每Run最多两个本地读取阶段：生成前基础读取，以及必要时一次工具读取/来源展开。每阶段墙钟截止250ms，所有阶段合计预算500ms；每个阶段内多个查询共享截止，包含排队、最多80ms pending等待、编码、扫描、过滤、去重和受限来源展开，不给每个问题重新250ms。

基础读取已耗尽时，工具阶段仍只能使用剩余全Run本地预算。版本重建也共享原预算，不通过新建controller重置计时。关键命令的模型解析/提交等待另外计入写入时效与Run60秒，不能算成“本地读取很快”。

同一工具往返可合并questions和已知sourceIds，或由服务端在结果中带出最小必要证据；不为每条问题再生成一轮。完整结果仍服从1500 token归档配额，二次裁剪必须更新readScope。更复杂的多跳任务不能假装全部查完。

### 6.4 结果融合与缓存

先按作用域、audience、风险准入/本次用途、主体、时间、修订、来源和屏蔽过滤，再合并关键词/E5。受限私人事件不进入一般all路径。仅许可仍有效的最小事件可进入受限本地E5用途；shared_history的私人来源同样受限，不能凭改audience绕过。不同问题的结果按记录ID及修订去重；同一旧事实在多个问题命中不增加真值权重。当前结构化值高于归档相似度，完整编号命中优先于语义近似。

记录每条查询的触发、依据、候选、入选与排除原因，以及最终最小充分证据。全部为空、部分命中和不可用分别表达；合成问题不是“用户从前说过”的证明。

查询计划缓存初始60秒，绑定owner/relationship、输入/有效语境指纹、策略、epoch和最早到期时间。换话题、槽位变更、相关背景过期或遗忘即失效。命中缓存省计算但不省资格复核，不把前一主题的情绪和人物带到下一主题。

v3一般事实模式按未重复提供的合格投影进入1500、退出1250 token；v2保持2000/1700。未读到完整集合或总预算裁剪后必须标partial/budget_limited。

### 6.5 索引与后台维护

继续使用本地`intfloat/multilingual-e5-small`、384维及原固定revision，普通事实先接入；受限事件仅最小文本在通过许可/用途/遗忘验收后复用同一编码器及索引能力，不新增数据库或账户开关。不更换正式开关，也不因Tolan案例直接接入云Embedding或新向量服务。

预热编码器与矩阵；未就绪时关键词降级，不能等待整个冷启动。矩阵常驻worker，传查询向量与资格掩码，不每次复制。后台编码按预计50ms时间片调度、长片段独立处理，每批之间检查前台队列；不能声称单段CPU推理可以随时中断。

向量与缓存仍是用户资料。未索引事实先由结构化查询和delta可读；索引完成不能延迟真正保存回执或使全局内容重答。

### 6.6 增量整理与每日归档维护

分三种时间尺度处理，均有来源与版本：

1. 关键事务即时更新槽位、事实和屏蔽；不等后台概括。
2. 核心软概览/近况按60秒合并、最早dirty后最多5分钟调度；过期时用原子资料后备。
3. 每日一次低优先级归档整理，初始计划在用户当地03:00；设备睡眠或应用关闭时在下一次启动空闲窗口补跑一次，不补跑多天的重复任务，不通知用户。

每日作业合并重复条目、降低无后续价值内容的召回优先级、复核时间与矛盾。它不能删除原聊天来实现“压缩”，也不能按特定主题关键词机械删记录；用户明确要求保存的短期跟踪有其用途。冲突处理沿用明确来源、时间与谓词规则，无法证明的保留分歧，不由模型任选一个“更合理”的版本。

夜间维护不覆盖关键槽位、不改变用户亲自确认值、不修改人格。提交前复核wantedVersion、源修订和suppression。发生前台负载、预算不足或来源变化时让出/重排；每批仍受25秒调用截止和日预算约束，不能持有SQLite事务做长模型请求。

### 6.7 受限私人事件的间接召回

读取权威许可与用途先于内容交付。private事件不混入普通all、核心、核心MD或开场通用候选。沿用现有索引/worker，事件risk/origin/epoch/许可来源进入资格元数据与掩码；不要求把整张向量矩阵另复制成敏感库。不再有“一律禁止受限事件E5”的合同，但实现未通过本节验收前不开放该用途。

主生成基于当前缺失背景提出既有RecallPlan，reasonEvidenceIds绑定本轮用户语境；程序校验作用域、实际许可与用途。不要求用户逐字重复实体名，未解析实体可在当前关系的合格私人事件内做有限语义候选检索。问候/不相关话题不派发这类查询；含糊压力表达允许因相关缺口检索，但结果仅为可能背景。不得为了提高候选召回在每个请求注入所有受限事件。

结果投影带`possible_context`及来源/发生时间，不写因果断言。主生成与既有facts检查区分唯一回指、多个可能事件和泛化表达。相似度只排序，不证明“因为X所以睡不好”，也不证明治疗结果、财务变化或当前情绪。未获主动关心许可且本轮未定位对象时，不能点名披露私人旧事；可中性澄清。对具体对象的明确回问仍可回答，不把所有响应都算主动关心。

复用每Run3查询、2读取阶段/总500ms、归档1500 token与每次最多2来源展开；受限检索不是额外免费通道。E5超时退FTS/结构化和delta，记录不可用/空/partial，不断言原库没有。已授权未索引的事件可在同一预算内走主体/时间/FTS与delta，不能等待索引才返回真实保存回执，也不承诺此时所有改述都能命中。

只编码接纳后的最小文本，不编码许可前原话、候选征询正文、禁存细节或整段病历。统一索引允许物理共存，查询必须在扫描和输出时使用资格掩码；某后端无法在输出前可靠排除就不开放private用途。来源展开也只返回许可区间，不能借证据引用暴露整条混合消息。

授权/用途撤回的事务先推进相关版本、使资格/缓存/read-set/未展示输出失效，再异步删除不再允许的向量。撤回主动提起不自动禁止用户回问；关闭自动形成不自动撤销已有读取，两种范围分别处理。忘记则执行完整闭包，旧备份、旧矩阵、迟到编码、摘要和bot共同经历都不能复活目标。许可不明的旧向量先屏蔽，不当作有权限。

受限事件的间接召回先在隔离副本做FTS-only与本地E5混合配对：同一已提交来源、上下文消融、模型和预算，覆盖明确/唯一间接/泛化多因/无答案/第三人/撤回/删除/索引未就绪。分别报告候选召回、实际交付、合理运用、错误因果和越界披露；最高相似事件不是评测真值。此实验验证记忆用途，区别于默认关闭的风险分级发布实验；两者都不改正式向量开关。

## 7 版本一致性与遗忘

### 7.1 版本递增清单

| 写入                                      | memoryVersion            | contextVersion                          | indexVersion         |
| ----------------------------------------- | ------------------------ | --------------------------------------- | -------------------- |
| 新提交事实 替换 撤回 槽位/事件许可变更    | 增加                     | 槽位或上下文投影受影响时增加            | 索引资格变化时增加   |
| 近况 持续事项 交流背景 会话摘要生效或失效 | 仅同时改变事实资格时增加 | 增加                                    | 索引条目变化时增加   |
| 来源遗忘 屏蔽区间 删除台账                | 增加                     | 增加                                    | 增加                 |
| 收件箱进度 quarantined计划 内部候选       | 不增加                   | 不增加，pending覆盖绑定自己的来源与状态 | 不增加               |
| 向量 dirty→ready 重建批进度               | 不增加                   | 不增加                                  | 增加                 |
| MD 导出成功 观察指标 运维日志             | 不增加                   | 不增加                                  | 不增加               |
| 临时槽位自然到期                          | 按读取时点计算资格       | validUntil 检查，不依赖后台及时写版本   | 资格掩码在使用时复核 |

同一事务内同一种版本至多递增一次。交流背景与事件证据自然到期另由validUntil/expiresAt判断；许可撤回和主动用途变更是有来源的内容资格变化，依赖该许可的read-set必须复核。收件箱从queued变running不改变事实真值。索引变化或无关后台新增不能使内容依据未变的Run反复重答；按工程第5.3节检查read-set。软概览read-set绑定其支撑原子资料，概览仅换包装版本不单独使仍有效的事实过期。

### 7.2 遗忘语义

用户说“忘掉这条偏好”，默认移除它的记忆与派生内容，并阻止原聊天在模型读取、摘要重建或再提取时把它带回来；原聊天在界面仍可保留。用户明确要求“原话也删除”，进入现有原文遗忘命令，移除原始内容及派生记录。回应只能描述实际完成的范围，不能把移除记忆说成抹掉所有聊天与备份。

`memory_suppressions` 记录来源修订与 UTF-16 区间、规范化对象/谓词指纹、适用范围及触发输入顺序。模型历史投影、pending来源覆盖、全文搜索、摘要、来源展开、再提取均检查屏蔽区间，不只过滤memories表；遗忘命令里再次出现的目标值也纳入后续模型读取屏蔽，避免从命令原话重新学回。

新 v3 事实必须具有原子证据范围。遗忘同一原话中的一个事实不能顺手删除另一条独立称呼或边界。旧记录没有可靠区间时保守屏蔽整条来源的模型读取，界面聊天可保留；通过其他独立有效来源重建不受影响的信息，并记录降级原因，不能伪造精确切片。

用户明确忘掉某类信息后，相同来源的重放和后台重提取不能恢复它。基于新的输入重新学习，要求用户明确重新提供/允许保存且符合风险策略；不能仅因字符串相似度低而绕过遗忘。

### 7.3 失效闭包

遗忘命令在返回成功前完成逻辑失效：事实和槽位不可读、来源区间被屏蔽、缓存失效、epoch/版本推进、未展示文本停止发布。物理删除大索引可分批，但每次读取必须先做资格过滤。

固定处理顺序为：

1. 写删除或屏蔽台账，标记受影响源与事实。
2. 失效槽位、概览、会话摘要、事件、持续事项、交流背景与收件箱，停止未提交提取，并保存完整依赖集合；同源bot/共同经历、开场候选和本轮观察一并失效。
3. 失效向量、索引队列、内存矩阵资格、合成检索问题及计划/结果缓存。
4. 清理回执中重复正文、Trace、导出、MD 及临时文件的相应内容；取消依赖目标的FollowUp/Series未发送实例、Delivery和未播放内容。
5. 所有迟到worker、摘要、交流背景及模型结果按来源修订、epoch和观察截止拒绝提交；取消含目标内容的未播放音频与未展示尾段，已被用户听到/看到的内容不声称能追溯消除。

依赖使用现有表并保持直接原始来源引用。首版不实现任意深度递归记忆图；派生视图展开依赖时同步存平坦来源集合，防止概览引用概览造成无界循环。异常依赖保守使整个派生视图失效，不能保留疑似过期片段。

忘记一个记录不意味着物理磁盘不可恢复擦除。恢复备份时先应用最新台账与屏蔽规则，再允许模型读、再启动后台任务。

## 8 导出与接口

### 8.1 核心记忆 MD

拟生成路径为每个 bot 私有目录下 `memory/core-memory.md`，目录 0700、文件 0600，继续排除 Git 与静态 Web 资源。文件包含作用域、策略版本、快照版本、生成时间、有效至、当前称呼、简短背景与相处偏好；本版不导出受限私人事件、秘密或全部原始消息，不能因为获得主动关心许可就进入核心MD。

MD 来自数据库已提交快照。写到同目录临时文件后原子替换，禁止跟随用户构造的符号链接。异步导出前后核对版本；旧任务不能覆盖较新的文件。失败只影响查看或导出，模型直接读数据库投影，不读取可能陈旧的磁盘 MD。

用户不能手工改 MD 就绕过资料准入。管理界面的修改进入同一领域命令；未来若支持 MD 导入，要单独做差异预览、来源标识和规则检查，首版不实现任意文件自动反向同步。

删除与恢复必须覆盖 MD 和临时文件。发现已遗忘数据残留且无法清理导出时，不提供该导出下载，并记录修复任务，不能宣称遗忘闭包完成。

### 8.2 拟新增接口

所有新接口复用当前鉴权、bot 选择和作用域绑定，不接受客户端任意 owner。新增前检查现有动态 `:id` 路由，避免静态 profile 路径被当作记录 ID。

| 接口                                 | 合同                                                            |
| ------------------------------------ | --------------------------------------------------------------- |
| `GET /v1/memory/profile`             | 返回当前可读档案、修订、来源和有效时间，隐藏内部秘密            |
| `PATCH /v1/memory/profile`           | typed changes、expectedRevision、idempotencyKey；走同一准入事务 |
| `GET /v1/memory/threads`             | 按状态/时间分页读取当前 bot 的持续事项                          |
| `GET /v1/memory/mutations/:id`       | 仅当前 bot 的实际结果，不信任用户粘贴 JSON                      |
| `POST /v1/memory/mutations/:id/undo` | CAS 与幂等撤销，拒绝覆盖后来的明确更新                          |
| `GET /v1/memory/profile/export`      | 按当前快照生成或取匹配版本 MD；不提供过期导出                   |

沿用 `/v1/memory/search`、`/v1/memory/corrections`、`/v1/memory/forget` 与来源展开，扩展目标和资格函数。旧客户端仍可按旧语义操作旧记录；不能用老 confirm 接口绕过新敏感策略。

聊天说明、可选管理与固定人格故障文案的用户规则见[产品第10节](companion-memory-v3-product-rules.md#10-用户掌控与故障表达)。不将内部许可ID、schema或Embedding展示给普通用户。主动消息复用现有follow-ups/series/deliveries、channel与回执接口，仅增加必要用途/显示字段；手机推送、外部消息渠道及新凭据接口不在本版。

### 11.2 真实模型与自然对话

核心集合保留24个多轮使用过程，每个过程3个探测点，共72个回答位置。覆盖核心称呼、主体归属、自动保存及后台时序、临时/长期变化、持续事项与主动检索、历史事件、间接约束及时效背景、遗忘八类，每类3个过程。至少一个过程经过200条交流后回问早期决定，规模实验另种25000条干扰记录。

其中16个过程/48个位置作为开发回归；8个过程/24个位置在最终实现冻结后首次运行，保持题目、预期、模型配置和资源预算不变。由同一作者设计时只能叫预冻结未运行集，不能称为独立盲评。新题运行后若继续修复，则它转为回归，下一次泛化声明必须使用另一个事先冻结集合。

新增12个温度层过程，每个4个位置，共48个；覆盖跨天接续、敏感事件、观察/否认、bot/共同仪式、拒绝与冷却、故障/来源解释六类，各2个过程。8个过程/32位置为开发，4个过程/16位置冻结后首次运行。新增6个触达过程，每个4位置共24位置：4过程/16开发，2过程/8冻结后首次运行。总计42个过程/144位置，开发96、未运行48；核心72、温度48、触达24分别报告，不混一个总分掩盖退化。这144个位置仍是完整能力的规划，不声称已编写或冻结；本轮只冻结并运行切片准入12题，分开报告。

每个温度位置事先标`should_use | may_use | should_not_use`，标注可用事实、时间、允许表达/询问、禁止推断，以及合理的多种回应。should_use可以通过正确调整建议或语气实现，不要求逐字提往事；may_use不因没有提及而扣分；should_not_use要求不揭露/不绕回，不把泛化问候误算主动接续。标注随上下文不同而变，不能把某主题固定成应问。48位置至少含12个should_use和12个should_not_use，不足则在运行前重做分布，不用重复跑题填分母。

增加来源允许范围明确的自然使用片段；脱敏与改写必须重新标注预期，不能把个人聊天直接上传新第三方评审服务。公开 LongMemEval 使用固定版本、固定子集和原评分口径；中文自编过程另报，不混成一个行业准确率。

自动形成的测试必须由真实用户输入触发inbox、提取和commit，不能用手工addMemory/confirmed种入替代后宣称自动形成有效。纯召回和规模干扰可程序种入合法记录，但单独标明；故障虚拟时钟不作真实性能成绩。

授权与分类在冻结前定稿，最少将下列正反配对纳入现有T65至T72及48个温度位置，不新增一套题号或放宽原评分：

| 对照                              | 成功与失败边界                                                     |
| --------------------------------- | ------------------------------------------------------------------ |
| 当前事件同意/全局设置             | 可以只保存该事；不因一句可以改related_events；换题后的好不当同意   |
| 拒绝/未答/未展示征询              | 不写事件或重复问；用户未来显式命令仍可办理；off不旁路              |
| 分手/失业/争执及各自细节          | 最小本人事件普通，诊疗/金额/第三人私密部分受限；混合消息不全收全丢 |
| 间接唯一回指/泛化压力/多因/无答案 | 可自然找回未点名旧事；相似不建立因果，不泄露无关私事               |
| 具体主动关心许可/撤回             | 仅该事项可供候选，频率仍在；撤回后不靠新同义问句继续               |
| 状态过期/事件仍在/事件超期        | 读历史不当现状；超期不计观察；原聊天还在不能冒充证据仍合格         |
| 同一经历隔天重述/不同日独立经历   | 前者不凑两日支持或续期，后者才可考虑不确定询问                     |
| 29:59/30:00/30:00以上与busy       | 只严格超过且无其他在途Run才换段；跨午夜/刷新不切；恢复不重问       |

主动触达24位置预标should_send / may_send / should_not_send及触发时刻、许可、通道/前台状态、窗口和既有额度，至少各8个should_send与should_not_send；标签不进入生产模型。仅因检索命中、生成了文本或系统构造了通知不算成功。配套确定性虚拟日历覆盖至少30天、多bot/客户端、静默、未回应、真实用户返回、Series与DST；虚拟时钟不作真实性能成绩。每个触达位置保留未发原因、后台模型总用量、occurrence/Delivery/attempt及客户端报告，曝光未知单列。

每个位置保存输入、路由与升级依据、交付快照、实际模型请求、合成检索问题、队列/提交状态、事务回执、有效背景卡片、完整发布答案、数据库前后状态、阶段耗时、费用和错误。评分预期不发给生成、提取或运行评审模型。

### 11.3 对照与分项指标

基线为当前v2；实验为v3.4，使用同一回复模型、同一E5版本和相同数据范围。3.0/3.1尚未实施，只能比较设计调用预算，不能冒充实测基线。额外做关键词关闭向量、核心不注入、近期投影清空等隔离消融，不能改用户原聊天来制造效果。

小数据可使用完整读取作为参照。超过模型窗口的全量条件标记不可运行，不能截断后仍叫全量，也不能因此从总数中隐藏困难题。

分开报告：

- 准入准确率与误写率：是否应该存、内容/主体/范围/时效是否正确。
- 槽位更新与真实持久化：读当前值、重启、CAS与回执是否一致。
- CandidateRecall 与最终交付证据召回：正确证据进候选，不代表最终上下文仍含足够证据。
- 阅读与运用正确率：已读到后是否答对、是否遵守建议中的限制。
- 记忆与关系连续性：按下列陪伴合同单列，不只记“没出错”。
- 完整任务成功率：未发布、超时、预算错误、评审错误均算失败。
- 评审本身：漏拦与误拦分开，不能靠放宽引句或模糊真值提高分数。
- 资源：路由、准入、读取、pending等待、排队、生成、检查、后台/每日维护、首有效文本、首答案音频、完成与总token分别测量。
- 及时生效：从input accepted到commit、commit到下一轮可读、自动形成失败与后台排队分别统计；只靠pending原话答对不计长期存储成功。
- 快路覆盖率与误升级：真正普通回合是否被无必要地串行化，漏判关键指令是否在发布前处理。

人工复核必须逐条阅读发布正文及关键证据。模型评审只是诊断工具；评分问题可新增严格版本，但原版本与结果必须保留，不能原地改标签抹掉失败。零泄漏只描述本次观察，不承诺未来零错误。

陪伴指标的语义分母由[产品规则第9节](companion-memory-v3-product-rules.md#9-陪伴评价口径)唯一维护；本节维护规模、执行和数值门槛。人工先不看A/B标签；同作者需披露，资源允许时双人复核并保留分歧，不比较参考句措辞。

### 11.4 发布门槛

以下均为初始待验证门槛，不来自厂商承诺或已经取得的实验结果。区分早期可试聊与完整稳定交付。

早期门槛唯一维护在[CM3 2 最小试聊清单](companion-memory-v3-cm3-2-checklist.md)。CM3 2后先评该清单；不要求未实施的温度48或完整模型负载先通过，也不称完整v3.4发布。

**记忆稳定交付门槛（主动触达不作为前置）：**

1. 确定性合同全过；跨用户/bot串读、秘密入库、遗忘复活、半事务和未授权副作用为零容忍阻断。
2. 预定义关键称呼、禁用、主体、临时覆盖和更正场景全部正确。自动保存必须在不点确认卡片的条件下生效；明确命令在发布前完成或如实失败，普通后台满足提交时效，不能只用pending覆盖通过。
3. 核心72个位置完整成功率至少98%；其最终未运行24个位置独立统计，关键场景全过。温度48位置/未运行16、触达24位置/未运行8另报。不得让144位置总平均掩盖核心错误。
4. 正确回答引用的最小充分证据完整；无法回答的问题不猜值，不作全库否定。虚假写入/删除回执、永久保证与错误核心写入在验收中不得出现。
5. u02、u07、q28及跨主题变体固定复现集连续三次完整运行均通过；不能从三次中逐题挑最好结果。已有80题严格评审集保持严格诊断，v3只有提供真实回执的条件才允许新增成功陈述。
6. 本机热态每读取阶段P95不超过250ms，阶段最多2次、总本地读取预算500ms；pending等待和多问题排队算在内。热态无人工故障的向量降级率目标低于5%，冷态/回填单独测，不能用一次短查询代表完整检索延迟。
7. 短回复负载分普通快路、关键写入、主动检索三组，每组固定120个尝试且模型/输出长度条件固定，不靠不断补跑到某个成功样本数来选择结果；每组完整成功率也须至少98%。普通快路首有效文本P50目标6秒、P95目标12秒；关键写入与检索路径目标P50 8秒、P95 15秒，Run硬截止60秒。真正普通样本至少90%不触发无必要前置准入/升级。普通自动提交P95目标5秒、30秒内必须有结果；合法关键命令从解析完成到DB commit目标P95 50ms，不能把模型解析等待藏掉。首答案音频在文本获准后额外耗时P95目标2秒；ASR/VAD、TTS和用户侧网络另分解。以上均待实测，不声称实时语音已达标。P50/P95须标明成功样本数，所有未发布/超时仍进入完整任务失败分母并单报，不能只展示成功延迟；不足100个成功样本时，该P95不作为发布证据；即使样本足够，也只代表本次固定负载，不能宣称真实用户总体已稳定。
8. 浏览器演示包含自动学习、无近期历史的召回、昵称更新/临时覆盖、自然纠正、pending与commit区别、主动检索、背景到期、遗忘与一次故障恢复；管理页不是成功必要步骤。
9. 温度48位置中，should_use恰当运用率初始目标至少80%，should_not_use违规率不超过5%，bot连续性适用位置至少95%；敏感越界、违反明确不再提及、虚构共同经历均阻断，不受均分抵消。人工“被记得”和“被理解”分别至少80%的适用实质回答达4/5；故障/超时位置保留在端到端失败，不拿来凑温暖分。报告各项实际n/N，分母不足不外推；最终未运行16位置逐项审阅、关键场景全过，其小样本不声称稳定总体比例。与v2同条件配对审阅，说明收益与退化，达阈值也不能隐去具体反例。

## 12 迁移与隔离发布

### 12.1 数据库兼容

schema3 只通过显式迁移命令创建。普通启动不能顺手升级正式库。新二进制分别识别1、2、3；基础能力检查改为明确的版本集合，不能让现有 `hasMemoryV2 === 2` 在新库上误判成“没有基础表”。

迁移过程先输出 dry-run：输入路径、数据库schema、当前作用域、表计数、待转换记录数、冲突、缺失来源和预计索引变化。用 SQLite backup 获取一致备份，校验完整性、scope与非符号链接路径后才在获授权的副本执行短事务。旧二进制对schema3继续拒绝，不调低user_version。

主动交流迁移不把旧proactiveEnabled=true或任意confirmed FollowUp当新范围许可；既有明确提醒只保留原来源能证明的对象/时间/通道范围，缺证据项暂停而不补造授权。新身份副本默认关闭发送、Series不续排；既有4321未来更新须按原身份核验已授权任务，不能以保留聊天为由自动扩大主动能力。

旧 active/confirmed 记录保留原ID、来源、修订、时间和确认属性；增加兼容准入来源时不把人工确认解释成外部核实。普通 pending、过期候选、争议记录不自动全量升级。它们可保留历史；重新准入必须回到有效用户证据并通过v3规则，无法证明的继续隔离。

旧确认不等于对核心常驻、向量化或主动提起敏感内容的新许可。迁移报告单列敏感/风险不明记录：保留权威记录与来源，不默认标ordinary；风险未明的暂不进入新核心/all/E5用途，明确记录限制原因并可在管理页解释。按产品第4节完成分类与读取资格后再开放相关读取；已有不满足新用途资格的私人派生概览/MD及向量先逻辑失效并排队清理；对通过明确许可/用途校验的最小事件可重新生成受限本地向量，不能将旧确认一律当编码或主动使用授权。此处限制的是新用途，不冒称原已确认记忆被删除，也不把未知资料偷偷提升为用户本人事实。

旧摘要能保留原文和覆盖范围，不能直接拆成无原始证据的新确定事实。旧主体unspecified不被偷偷归到用户本人；核心称呼提升只接纳主体明确且无冲突的记录。建立旧记录到新槽位的映射报告，不重写原聊天内容。

### 12.2 提前试聊与既有测试bot更新

**早期新隔离入口：** CM3 2通过最小试聊清单门槛，且后续实施请求覆盖隔离试聊时，即可创建新目录/新数据库/新bot身份和空闲端口。需用真实资料时只从只读一致性备份复制，执行删除台账和来源资格核对；不直接扫描正在写的SQLite文件做不一致复制，不修改原bot身份或原库。默认可先用合成资料演示，真实复制需遵守现有资料范围，不发送到新第三方。

复制需生成旧bot/关系到新身份的显式映射，相关消息、事实、来源和删除台账整体重绑定，跨作用域校验一致；新副本不通过放宽owner/relationship过滤读取源库。只给新副本执行已验证迁移。浏览器明确展示隔离入口、可用能力和限制；验证“自然输入→实际提交→关闭全部近期答案旁路→改述召回”、昵称/更正/遗忘和一次故障，不更改源聊天来造消融。复制后的新聊天属于该副本，不承诺自动合并回4321；试聊前说明入口区别，保留数据导出/备份。

反馈用非强制的简单标记或试聊笔记：“被记得”“像客服”“被打扰/被监视”“说错了”；不每轮打分，不诱导用户多聊或更亲密。随片段记来源、时间与实际上下文，私有存放并接受遗忘；不默认上传外部情绪评审服务。冷/热读取、故障回应和实质首答分别测量。

**完整验收后更新既有4321：** CM3 7通过工程第11.4节完整门槛，且实施请求明确包含更新当前测试bot时，才执行：

1. 记录4321实际botId、库/策略/向量开关和代码版本；保护正式4317及其他正式库/配置/进程。
2. 为4321创建一致性备份、聊天/确认事实/来源ID清单、最新删除台账及manifest，在新路径演练迁移与恢复。
3. 停止4321写入，创建最终备份，按已验证步骤迁移该独立库；尊重旧explicit_only与敏感设置，不从早期副本盲目覆盖。
4. 先应用屏蔽台账，校验schema及权威数据，再启动读取/任务；预热只保持原E5设置，不改正式向量。未就绪仍可读核心与delta。
5. 浏览器核对原聊天与已确认记忆完整、来源可解释、新形成无卡片、遗忘有效；比较正式环境保护快照。
6. 输出版本、备份、实际能力/开关、失败项和回退方法，继续自然观察。早期副本若有用户新增聊天，单独保全，不声称已无损合并。

当前任务只交付文档，不执行上述任一部署、复制、迁移、浏览器操作或开关变更。

### 12.3 回退

常规回退使用支持schema3的新二进制，将形成模式切为explicit_only或off，保留v3读取兼容、已有槽位、已提交资料和遗忘台账。关闭后台自动维护不能让已生效的用户称呼或纠正重新消失。不能通过关闭基础schema读取能力来实现回退；不兼容的schema/策略组合启动时明确拒绝，不能自动创建空库顶替原库。

若必须回旧二进制，先停止写入并保全当前v3库、删除/屏蔽台账和新增聊天。将迁移前备份恢复到独立恢复路径，先应用最新台账，再验证旧版本。该路径不自动把升级后新增聊天转换进旧库，不能承诺无损降级；需要另行设计转换或继续使用v3兼容读取。禁止直接用旧二进制打开新库或覆盖当前唯一副本。

正式发布另行安排，不属于当前设计交付或隔离试聊实施默认权限。

普通首答6/12秒只作阶段门槛，不能代表理想文字/语音体验；应优先减少无关上下文与串行等待，按真实试聊评估是否可接受，风险发布优化另行实验。3.0的“每轮前置准入、正常4次、笼统普通回复12/25秒”已被分路径合同取代，不再作为当前方案门槛。v2的2000/1700分流、220ms内部余量和大冷快照25ms等待是旧实现参数；实施适配须保留版本区分与原规模回归，不能混为已实现的新合同。

## 14 可观察性与诊断

每个Run记录模型账户池预留/排队/限流、快路/关键/检索路由及升级、inbox与事务状态、各内容版本与read-set、背景及到期、查询计划/命中/裁剪、首有效文本与音频、所有阶段等待及实际用量。指标按前台和后台分栏，但共享全局日预算与来源归属。

普通自动资料进入inbox不算提交成功；相关数据源即使仍可读，后台误写或超期未形成也进入端到端失败。指标不依赖用户是否点击确认卡片。改为统计：可接纳事实数、实际提交数、错写/撤销数、当前槽位正确率、核心遗漏率、检索漏召回率、已读后答错率、评审误拦/失败率、对话打扰频率与实际资源消耗。主动触达另记合法机会、许可来源、候选/跳过原因、前台让位、免打扰/频率阻断、attempt/unknown/实际用户回复、重复/越界和disturbed；不记录“用户冷淡”等推断，不把私人正文放标签。温度层另记录征询displayed/明确同意范围/拒绝、私人候选/交付/误关联/披露、reported事件形成/到期/缺证，以及候选供给/实际使用/忽略、重复追问、错误跨天情绪、bot矛盾、越界记忆和人工正向片段；ID与计数优先，不把敏感原文放指标标签。故障回应与实质回答分别统计。原候选确认漏斗保留历史，不继续作为新产品成功前提。

正式诊断默认记录ID、状态、计数和必要指纹；完整模型正文只在明确启用的本地私有诊断中保存，并接受遗忘清理。合成问题和pending缓存按同一私有数据规则处理，不作为公开观测标签。测试产物放到被Git忽略的 `test-results/companion-memory-v3/`，原始请求不能放公开文档或共享链接。

最终验收报告至少含：源码/fixture/配置hash、完整样本分母、所有失败与未执行项、开发集与未运行集分栏、评分版本、真实模型身份、费用上限及实际用量。多个临时数据库不能各自重置用量来绕过整个评估批次预算。

模型实测先用小批估计总调用量和成本，再按用户已有额度及任务约束登记全批预算。资源不足则暂停该批并记录未执行，不将未执行当通过，也不把更便宜的模型结果混入同一条件。

## 15 风险与暂缓项

| 风险                               | 控制与停止条件                                                        |
| ---------------------------------- | --------------------------------------------------------------------- |
| 自动提取理解错了用户意图           | 保守准入、主体/区间证据、有限核心谓词、撤销与更正；关键错写阻止发布   |
| 核心档案越积越大                   | 有界概览、去重、归档、关键与软性信息分开；不静默裁掉边界              |
| 角色关系概览固化成心理画像         | 保留用户表达与事件；临时观察不晋升人格/依赖度/健康结论                |
| 无必要前置调用或升级增大等待和费用 | 普通形成异步、检查并行、分路径SLO；后台仍计全费，不以少检查掩盖       |
| 旧格式与新资格不一致               | 统一资格合同，覆盖SQL/缓存/检索/摘要/索引/原文；逐路径测试            |
| 忘记后从原文或MD复活               | 读取区间屏蔽、平坦来源依赖、恢复前台账过滤、迟到结果拒绝              |
| 评测过拟合                         | 固定语义要求和未运行集、外部基准、原失败保留；不放实体/题号进生产规则 |
| 迁移影响正在试聊的数据             | 临时库优先、唯一副本禁止覆盖、阶段保护快照与回退演练                  |

暂缓：跨bot自动共享用户画像、自动人格改写、亲密度数值系统、情绪动力学状态机、通用知识图谱、全聊天逐句向量化、用户手改MD自动回灌、多Agent维护编排、云记忆供应商替换。需要这些能力时另立需求与验证，不在本次核心改造顺手加入。
