## 2.5 万条读取与调用者截止（2026-10-24 后续修复）

目标：每个 Run 的等待可取消，派生快照由当前 bot 的读取服务持有；用户取消一次查询不销毁仍可复用的有效索引，遗忘／关闭则必须使全部派生工作失效。继续核对相同固定快照的 `src/_base/utils/abort.ts` 与 `test/_base/utils/abort.test.ts`，提炼“调用者等待和资源所有者生命周期分开，已取消和等待中取消均保留原因”的不变量。**Adapt**：本项目使用自身 DomainError、AbortSignal、带版本的快照任务和短等待，不复制 DI 或重放框架；大快照分批读取／校验，调用者只等短窗口，后台完成后再提供语义结果。索引代数与事实版本仍分别核对。

验证落点：`memory-scale.test.ts` 的真实 25000 行驻留矩阵、取消与失效来源；`memory-scan.test.ts` 的整块／旧分行协议与穷举余弦对照；性能脚本强制检查全部冷读及后续样本，不隐藏初始化降级。具体实测见[召回与大库延迟修复](../implementation/memory-recall-latency-fix.md)。
