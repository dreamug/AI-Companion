# 记忆 benchmark 合同 v1

日期：2026-10-24。状态：内部工程回归合同；不是已经验证的产品上线 benchmark。

当前题目、静态参照和评分实现由同一工程代理编写，模型评审也使用同一提供方。没有独立人工金标，没有从真实用户流量抽样，没有可以证明泛化率的独立留出集。静态参照不应被称为“人工已验证”。

## 目的与权威

用于发现与复现资格过滤、来源交付、回答判断、引用、合成输出和评审执行问题。所有试验使用隔离合成资料；不能将代理自己写题、自己判分的结果当作客观 chatbot 记忆准确率。

版本清单位于 `tests/fixtures/memory-benchmark-manifest-v1.json`，含题集／校准集 hash、角色与严格门槛。更改旧题须另出版本并保留旧输入、旧标签和旧结果。检查输入与数据hash不会随结果自动修正。

## 当前组件

| 组件 | 规模 | 作用与边界 |
| --- | ---: | --- |
| 来源读取回归 | 262题：188已知、74未知 | 含8套已知工程题；不是262次独立用户事件 |
| 历史真实模型答卷 | 50题：24+12+3+3+8 | 直接写入确认记忆，独立对话；没有测试自然提取确认全过程 |
| 跨领域保留检查 | 12题 | 改动前冻结，但同一作者，不能称独立金标 |
| 评审校准 | 12题，6正6反 | v1.1修订数量歧义，v1.2修订一条主体可回答性元数据；旧版与旧失败保留 |
| 普通聊天捕获 | 12次 | 不要求JSON或引用ID，无自动语义通过分；保留全文附带断言 |
| 生命周期／UI回归 | 单元、领域、API、浏览器 | 检查工程状态与边界；不等于自然语言准确率 |

50题有45个不同问题字符串，包含同题换证据的正反对照，也包含同一事实的改写。按故事／事实世界分组解释结果，不视为独立同分布样本。原holdout已被开发使用，归为回归；不能再重复命名成新留出集。

## 必须分开的指标

1. **完整来源交付率**：已知题全部必需来源确实出现在最终模型请求中的题数／已知题数。至少一条命中不能当完整交付。
2. **有序检索Recall@5**：每道有排序检索的已知题，前5条覆盖其必需来源的比例，再跨题求平均。全量读取没有排名，不放进这个分母。
3. **回答语义**：主体、属性、时间、现实范围、肯否、未知与所有附带断言。查不到不等于不存在；属性相关不等于等价或排斥。
4. **引用质量**：每项事实及必要身份连接有实际引用路径，每条引用都有用；一条资料可支持多项事实，但不能因用过一次就跳过另一项的完整性。
5. **合成协议**：恰有answer、abstain、memoryIds三键；不忽略额外字段，不改原未知标记，不补原引用。此合同不是普通聊天UI的输出要求。
6. **评审质量**：正例误拒、反例误接、结构与调用失败单列。证明不完整是待复核，不足以说明原回答错了；评审给出pass也不是独立真值。
7. **延迟／成本**：检索、生成、评审分别记录。模型思考预留计入预算；按读取模式和降级原因保留全部样本。

未知题不进入已知来源召回的分母，不代表应返回空列表，也不代表已正确拒答。无关候选可以被交付，回答阶段必须判断它们不能证明目标。

旧recallAt5曾使用全部交付并只看任一来源命中；名称不准确。新版本分为sourceHitRate、completeRecall、rankedRecallAt5。旧报告保留，不用新分母给旧成绩改名。

## 严格门槛与重放

原严格门槛保持全部要求通过；fail和review均阻断。不同维度不互相抵扣，没有为了43/50而新设85%或90%及格线。原50题重放只读取冻结raw和实际交付记录，不重新生成，也不修正原字段。保存的证明须绑定同一答卷hash，并重新验证，不相信旧的pass标记。

评审看不到标准答案、预期ID或静态诊断标签。来源核对只使用实际交付的事实；原始全库与交付视图分别保存。结构错误最多修复一次；只有推理容量耗尽且完全没有可见判断时，可在相同两次总上限内切换一次非推理请求。完成的语义判定、不完整可见JSON和用户答卷不因预期分数而重试。

## 配置对照

快速与可选grounded-low-v1路径使用相同题目、事实、模型和系统提示。后者由默认关闭的 `HARNESS_MEMORY_ANSWER_REASONING` 控制；仅在显式开启且本轮使用合格记忆时开启请求级推理，额外4096 token先计预算。隔离脚本可用 `--grounded-reasoning`，不写正式配置。

一次顺序采样只是工程对照，不是随机交替实验；不据此声称统计显著提升或固定延迟增量。新生成结果与原答卷重评结果分开，保留全部失败，不挑一批较好答案覆盖旧答案。

## 产品benchmark仍需补齐

先定义真实任务分布，再按用户／故事／时间线隔离开发和留出，同一事实换问法不能分散到两边。参照应由独立复核者确认可接受语义、必要证据路径和禁止推断；对歧义记录分歧。提取、聊天确认、更新遗忘、长聊回问、工具来源和普通聊天分别评估。评审须先校准误接、误拒和执行失败率，不能用未经校准的同模型评审直接做生产回答闸门。

本轮结果、25项逐题复核及未解决边界见[实施报告](../implementation/memory-benchmark-v1-audit.md)。正式库、向量开关及服务未因本轮试验改变。
